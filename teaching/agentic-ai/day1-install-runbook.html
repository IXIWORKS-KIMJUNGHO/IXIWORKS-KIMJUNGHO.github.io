Node.js가 없다면 LTS 버전을 설치합니다

Node.js를 설치하면 npm과 npx도 함께 준비됩니다. 이미 준비됐다면 설치는 건너뛰고 확인만 합니다.

  1. 4단계에서 Node.js, npm 또는 npx가 설치 필요로 나왔을 때만 진행합니다.

  4. 내려받은 설치 파일을 열고 화면의 기본 안내에 따라 설치를 마칩니다.

Node.js 설치가 끝났는지 확인해 줘. node --version, npm --version, npx --version을 차례로 실행하기 전에 무엇을 확인하는지 쉬운 말로 설명하고 내 승인을 기다려. 파일이나 설정은 만들거나 바꾸지 말고, 프로그램도 추가로 설치하지 마. 세 명령의 결과를 ‘준비됨 / 확인 실패’로 나눠 표로 보여 줘. 확인 실패라면 추측으로 고치지 말고 오류 원문과 다음 확인 한 단계만 알려 줘.
npx는 따로 설치하지 않습니다 Node.js 공식 Installer로 설치하면 npm이 함께 준비되고, npx는 npm 명령줄 도구에서 사용할 수 있습니다.
이미 모두 준비됨이라면 Node.js를 다시 설치하지 않습니다. 위 확인 문장으로 세 버전만 확인하고 통과 표시를 합니다.

06

Git 변경을 연습하고 첫 커밋을 GitHub에 올립니다

로컬 복구 지점을 만든 뒤 변경점 확인·되돌리기·비공개 첫 업로드까지 해봅니다.

  1. 4단계에서 Git이 준비됨으로 확인된 경우에만 진행합니다.
  2. Codex 입력창에 아래 문장을 붙여 넣습니다.
이 폴더를 수업 프로젝트용 Git 저장소로 준비해 줘. 먼저 현재 상태를 확인하고, 저장소가 아니라면 무엇을 할지 쉬운 말로 설명해. README.md와 웹 프로젝트용 .gitignore 초안을 제안하되, 내가 승인하기 전에는 파일을 만들거나 커밋하지 마. 내가 승인하면 저장소 초기화, 두 파일 생성, 첫 커밋까지 진행해. Git 사용자 이름이나 이메일이 없으면 전역 설정을 바꾸지 말고 이 저장소에만 설정할 값을 물어봐. 끝나면 저장소 여부, 마지막 커밋, 아직 커밋하지 않은 변경을 표로 보여 줘.
  1. Codex가 설명한 대상이 현재 my-small-service 폴더인지 확인합니다.
  2. README.md와 .gitignore에 들어갈 내용을 읽고 승인합니다.
  3. 마지막 표에서 저장소, 첫 커밋과 현재 변경 상태를 확인합니다.
  4. GitHub Desktop에서 File → Add Local Repository를 선택하고 my-small-service 폴더를 엽니다.

아래 문장으로 변경점 확인과 되돌리기를 한 번 연습합니다.

Git 연습을 할게. README.md 맨 아래에 ‘Git 연습용 한 줄’만 추가하고 커밋하지 마. 바뀐 파일과 추가한 한 줄을 설명한 뒤 멈춰. 내가 GitHub Desktop의 Changes 화면에서 확인하고 ‘돌려줘’라고 말하면, 방금 추가한 그 한 줄만 원래대로 되돌려. 다른 파일이나 이전 커밋은 건드리지 말고, 끝나면 아직 커밋하지 않은 변경이 없는지 보여 줘.
  1. GitHub Desktop의 Changes에서 README에 한 줄만 추가되었는지 확인합니다.
  2. Codex에 돌려줘라고 입력한 뒤 Changes 목록이 비었는지 확인합니다.
  3. GitHub Desktop에서 Publish repository를 선택합니다.
  4. Keep this code private를 선택한 상태로 게시하고 View on GitHub를 엽니다.
  5. 브라우저에서 README와 첫 커밋이 보이는지 확인합니다.
처음에는 비공개로 둡니다 공개가 필요한 시점과 공개할 파일을 확인하기 전에는 Keep this code private를 해제하지 않습니다.
저장소에 넣지 않습니다 .env, API 키, 비밀번호, 개인정보, 공개 권한이 없는 원본 이미지·영상과 큰 작업 파일은 프로젝트 밖의 개인 저장 공간에 둡니다.

Matt Pocock 스킬 전체를 복사해 설치합니다

스킬은 AI용 작업 안내서입니다. AI는 스킬에 따라 기획·구현·검토처럼 반복되는 일을 같은 순서로 진행합니다.

  1. 5단계에서 Node.js, npm과 npx가 준비됨으로 확인된 경우에만 진행합니다.
  2. 진행자와 함께 my-small-service 프로젝트 폴더 위치에서 터미널을 엽니다.
  3. 아래 명령 전체를 복사해 터미널에 붙여 넣고 Enter를 한 번 누릅니다.
npx skills@latest add mattpocock/skills --skill '*' --agent codex --copy --yes
  1. 파일 창에서 .agents/skills 폴더와 여러 스킬 폴더가 생겼는지 확인합니다.
  2. Codex에서 프로젝트를 다시 열고 새 대화를 시작합니다.
  3. $setup-matt-pocock-skills를 입력하고 수업에서 서비스 설계서와 작업을 프로젝트 문서로 관리한다고 답합니다. 모르는 선택지는 진행자에게 보여 줍니다.
  4. $ask-matt를 입력해 사용할 스킬을 안내하는지 확인합니다.
방금 스킬 설치와 설정으로 바뀐 파일을 설명해 줘. 비밀번호, 토큰, API 키 같은 비밀정보가 포함되지 않았는지 확인해. 내가 변경 내용을 확인하고 승인하면 이번에 바뀐 파일만 커밋해. 원격 저장소에는 아직 올리지 말고, 끝나면 마지막 커밋과 아직 커밋하지 않은 변경이 있는지 보여 줘.
  1. GitHub Desktop에서 커밋 내용을 다시 확인하고 Push origin을 선택합니다.
  2. View on GitHub에서 마지막 커밋이 같은지 확인합니다.
설치와 설정은 다릅니다 위 명령은 스킬 파일을 가져옵니다. $setup-matt-pocock-skills는 이 프로젝트에서 서비스 설계서와 작업 문서를 어떻게 관리할지 정합니다.
오류가 보이면 명령을 반복 실행하지 말고 오류 원문을 그대로 멘토에게 보여 주세요. 비밀번호나 토큰이 보이면 먼저 가립니다.
