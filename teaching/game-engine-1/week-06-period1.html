이동과 애니메이션은 서로 다른 변화입니다

Rigidbody2D는 Player의 세계 위치를 바꾸고, Sprite Animation은 같은 위치에서 보이는 그림을 바꿉니다. 둘을 분리해야 충돌과 표현을 각각 안전하게 조절할 수 있습니다.

게임 동작

세계에서 어디에 있는가

Rigidbody2D.linearVelocity와 Collider2D가 위치 변화와 충돌을 담당합니다.

화면 표현

그 위치에서 어떻게 보이는가

SpriteRenderer와 Animator가 현재 상태에 맞는 그림을 선택해 보여 줍니다.

핵심 구분 캐릭터가 이동하지 않아도 Idle 그림은 바뀔 수 있고, 이동해도 Animation Clip이 없으면 한 장의 그림으로 보입니다.

한 파일이 네 단계의 역할로 나뉩니다

이름이 비슷하지만 서로 대신할 수 없습니다. “원본 그림 → 나눌 규칙 → 한 장면 → 시간 순서”로 읽습니다.

교수자 확인 질문

“PNG 파일 자체가 Animation Clip인가?”라고 묻습니다. 원본 Texture와 시간 정보를 가진 Clip은 다른 에셋이며, 중간에 개별 Sprite로 나누는 과정이 필요합니다.

가져오는 순간에 크기와 선명도가 결정됩니다

먼저 전체 프로젝트의 기준을 정하고, 같은 종류의 캐릭터 시트에는 같은 기준을 적용합니다.

보이는 증상에서 가까운 설정을 찾습니다

모든 값을 한꺼번에 바꾸지 않습니다. 원본 → Import → Slice → Pivot → Clip 순서로 처음 어긋난 지점을 찾습니다.

픽셀 아트가 흐릿하게 보입니다

먼저: Filter Mode가 Point (no filter)인지 확인합니다. 다음: Compression과 Game View 축척을 확인합니다. PPU는 선명도보다 월드 크기 기준에 가깝습니다.

시트 전체가 한 장으로 선택됩니다

Texture Type이 Sprite (2D and UI), Sprite Mode가 Multiple인지 확인하고 Sprite Editor에서 Slice 후 Apply했는지 봅니다.

프레임이 바뀔 때 캐릭터가 떨립니다

Rigidbody2D보다 먼저 각 Sprite의 Rect 크기와 Pivot 위치를 비교합니다. 발 중심 같은 기준점이 모든 프레임에서 같은 위치에 있어야 합니다.

한 번 재생한 뒤 멈춥니다

Animation Clip 에셋을 선택하고 Inspector의 Loop Time이 켜져 있는지 확인합니다. Idle과 Move는 보통 반복합니다.

프레임 순서가 튀어 보입니다

Animation 창의 Sprite Keyframe 순서를 확인합니다. 파일명의 숫자가 텍스트 순서로 정렬될 수 있으므로 walk_00처럼 자릿수를 맞추면 관리하기 쉽습니다.

화면을 덮고 구조를 복원합니다

먼저 자신의 말로 답한 다음 펼쳐 확인합니다. 답의 핵심은 메뉴 이름보다 역할의 연결입니다.

Q1. Sprite Mode를 Multiple로 바꾸는 이유는?

한 Texture 안의 여러 자세를 개별 Sprite 하위 에셋으로 나누기 위해서입니다. Single이면 시트 전체를 하나의 Sprite로 취급합니다.

Q2. PPU가 서로 다르면 무엇이 달라집니까?

같은 픽셀 크기의 그림이 월드에서 서로 다른 크기로 보입니다. PPU는 월드 1 Unit에 대응하는 픽셀 수입니다.

Q3. Pivot이 프레임마다 다르면 왜 떨립니까?

Sprite 교체 때 각 그림의 원점이 Transform의 같은 위치에 놓이므로, 그림 속 발이나 몸통의 실제 위치가 프레임마다 이동하기 때문입니다.

Q4. 6프레임을 Samples 12로 재생하면 한 바퀴는 몇 초입니까?

6 ÷ 12 = 0.5이므로 0.5초입니다. Loop Time이 켜져 있으면 그 뒤 첫 프레임부터 반복합니다.
