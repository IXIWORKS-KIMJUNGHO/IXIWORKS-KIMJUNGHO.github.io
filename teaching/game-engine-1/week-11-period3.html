3교시의 도착점

AI가 만든 기능이 아니라 자신이 범위를 승인하고 실제로 검증해 설명할 수 있는 작은 변경을 제출합니다.

  • 01

    변경 전에 baseline, 체크포인트와 Console Error 0을 기록합니다.

  • 02

    Ask와 Plan을 거쳐 GameManager.cs와 TimeBonus.cs만 Agent에 허용합니다.

  • 03

    Unity Scene 연결은 직접 수행하고 예상 변경과 실제 diff를 비교합니다.

  • 04

    필수 테스트 8개, build, 변경 로그와 90초 코드 구술로 완료를 증명합니다.

CLASS MODE / PERIOD 03학생 개인 목표지향 실습

목표는 고정하고 구현 경로는 선택합니다. 클릭 순서 대신 중간 도착점을 확인합니다. 교수자는 목표, 변경 상한과 판정 기준만 분명히 하고 학생은 자신의 프로젝트 구조에 맞는 Ask, Plan, 수정 방식과 증거 순서를 결정합니다. 작업 속도와 Agent 호출 횟수는 평가하지 않습니다.

미션: Time Bonus 하나를 제한적으로 완성합니다

7주차 게임 루프와 10주차 에셋 통합 결과 또는 같은 행동을 가진 현재 프로젝트를 출발점으로 사용합니다.

FIXED OUTCOME

Player가 TimeBonus Trigger에 처음 닿으면 Playing에서만 남은 시간이 정확히 5초 늘고 최대 30초에서 멈춥니다. 성공한 보너스는 한 번만 처리되고, Ready, Won, Lost에서는 시간과 오브젝트를 바꾸지 않습니다. 기존 수집, 성공, 실패와 재시작은 모두 유지합니다.

00-60 min

승인과 검증에 절반을 쓰는 60분

Individual / goal-directed

  1. 00-06
    baseline과 체크포인트

    기존 전체 루프를 실행하고 Scene 저장, 프로젝트 복제 또는 버전 관리 지점을 만듭니다.

  2. 06-12
    Ask로 현재 구조 확인

    시간의 소유자, 상태 문, HUD 갱신과 기존 Trigger의 실제 이름을 읽기 전용으로 확인합니다.

  3. 12-19
    문제 정의와 Plan 승인

    목표, 두 파일, 금지 대상, 수동 Scene 작업, 위험과 테스트가 모두 있는지 봅니다.

  4. 19-28
    제한 실행 또는 수동 대체

    script-only Agent로 구현 코드 두 파일만 바꾸거나 접속 불가 시 같은 Plan을 따라 직접 작성합니다.

  5. 28-35
    diff와 Console

    파일 목록, 상태 문, 시간 상한, 반환값과 한 번 처리 순서를 읽고 컴파일 오류를 해결합니다.

  6. 35-43
    수동 Scene 연결

    TimeBonus GameObject, Trigger, Script와 GameManager 참조를 직접 연결하고 Scene 변경을 별도로 기록합니다.

  7. 43-55
    필수 테스트 8개

    경계값, 상태 거부, 한 번 처리, 기존 루프와 Restart를 확인하며 관찰과 수정 내용을 씁니다.

  8. 55-60
    build와 설명 증거

    증분 build를 실행하고 CSV, change log, diff와 60-90초 영상 또는 현장 구술을 정리합니다.

완료의 정의“시간이 한 번 늘었다”가 아니라 두 파일 범위를 지키고, 경계값과 기존 게임 루프를 포함한 8개 결과가 모두 PASS이며, 변경을 자신의 말로 설명할 수 있을 때 완료입니다.

같은 행동을 증명하고 표현은 스스로 정합니다

테스트할 데이터와 변경 범위는 고정합니다. TimeBonus의 시각 표현과 작업 순서는 학생이 선택합니다.

FIXED / TEST CONTRACT

모두 같은 행동

+5초, 최대 30초, Playing 전용, 오브젝트마다 한 번, 두 Script 변경, 수동 Scene 연결, 기존 루프 보존과 8개 테스트는 바꾸지 않습니다.

FLEXIBLE / AUTHORING

각자 선택할 표현

시계 Sprite, 색, 배치, Collider 크기, 기존 SFX 재사용 여부와 작업 순서는 자유입니다. 단, 테스트 결과와 설명 책임은 같아야 합니다.

동등한 구현

TryAddTime 대신 같은 책임을 가진 다른 이름이나 event 기반 구조도 허용할 수 있습니다. 그러나 시간의 소유자가 하나이고 상태, 상한, 한 번 처리와 회귀 결과를 같은 테스트로 증명해야 합니다.

    회귀 baseline 기록

    되돌리기 지점

    프로젝트 복제, 학교가 정한 백업 또는 버전 관리 체크포인트 중 하나를 만듭니다.

    확인 Agent Undo와 별개로 baseline을 복원할 수 있습니다.

개인정보와 권리

학번, 이름, 연락처, 평가 자료, API key와 비공개 타인의 코드를 prompt나 첨부에 넣지 않습니다. 필요한 project context는 해당 두 Script와 일반적인 Scene 구조로 제한합니다.

두 Script를 설명한 뒤 Scene을 직접 연결합니다

컴파일 성공만 보고 Scene으로 넘어가지 않습니다. 코드의 상태 문, 상한과 한 번 처리 순서를 먼저 표시합니다.

검토 순서통과 기준로그에 남길 것
파일 목록Agent 또는 직접 작성한 구현 코드는 두 C# 파일Plan, .meta, Scene과 구현 diff를 작성 주체별 비교
시간 메서드Playing, 양수, roundDuration 상한, HUD, bool 반환각 줄이 막는 실패
Trigger ScriptPlayer, null, 중복, 승인 결과, 비활성화 순서한 번 처리의 근거
기존 코드Update, AddScore, FinishRound, Restart 보존불필요한 수정 유무
ConsoleError 0, Missing Script 0오류와 직접 고친 줄
  1. 01

    TimeBonus GameObject 준비

    기존 Collectible을 복제해 이름과 Sprite를 바꾸고 점수 Script를 제거합니다. Collider2D의 Is Trigger를 유지하고 Player 또는 TimeBonus 중 적어도 하나에 활성 Rigidbody2D가 있는지 확인합니다.

    확인 시각과 Trigger, 2D 물리 조건이 있고 중복 게임 규칙 Script는 없습니다.

  2. 02

    새 Component와 참조

    TimeBonus를 추가하고 GameManager 참조를 끌어 놓습니다. Bonus Seconds는 5로 둡니다.

    확인 None 참조가 없고 값이 양수입니다.

  3. 03

    사람의 변경 기록

    Scene 저장은 Agent 변경과 분리해 Manual Unity changes에 GameObject, Component, Trigger와 참조를 적습니다.

    확인 실제 Scene diff가 생겨도 작성 주체와 이유가 분명합니다.

DIFF 저장 예시

새 파일은 일반 git diff에서 빠질 수 있습니다. 먼저 git add -N -- Assets/Scripts/TimeBonus.cs로 내용은 stage하지 않고 intent-to-add만 표시한 뒤 git diff -- Assets/Scripts/GameManager.cs Assets/Scripts/TimeBonus.cs > week11_학번_이름_diff.txt를 실행합니다. git diff --cached가 비어 있는지도 확인합니다.
