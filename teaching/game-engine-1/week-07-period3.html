3교시의 도착점

교수자의 장면을 그대로 복제하는 시간이 아닙니다. 같은 기능 계약을 자신의 기존 프로젝트에 통합하고 테스트로 완료 여부를 판단합니다.

  • 01

    Ready, Playing, Won, Lost가 분리된 하나의 게임 상태 흐름을 완성합니다.

  • 02

    점수와 시간 HUD, Start와 Result Panel을 현재 데이터와 상태에 맞게 표시합니다.

  • 03

    수집, 성공과 실패에 서로 구분되는 효과음을 연결합니다.

  • 04

    필수 테스트 8개를 모두 PASS하고 Editor 밖의 빌드에서 전체 루프를 재현합니다.

CLASS MODE / PERIOD 03학생 개인 목표지향 실습

교수자는 클릭 순서를 다시 시연하지 않습니다. 목표 확인, 질문 되묻기와 오류 범위 좁히기를 지원합니다. 학생은 작업 순서, UI 배치와 표현을 선택하고 구현, 테스트, 기록과 빌드를 직접 수행합니다.

미션 계약

목표는 고정하고 구현 경로는 선택합니다

아래 행동과 결과는 모두 충족해야 합니다. UI를 먼저 만들지, 상태 코드를 먼저 연결할지, 기존 수집물을 먼저 점검할지는 각자 결정합니다.

MISSION / WEEK07_PREFLIGHT

60분 안에 Start 버튼으로 시작해 30초 동안 수집물 3개를 모으면 성공하고, 시간이 먼저 0이 되면 실패하며, 어느 결과에서도 깨끗하게 재시작되는 2D 게임 Scene을 완성합니다. 마지막에는 실제 빌드에서 전체 흐름을 검증합니다.

REQUIRED 01 / STATE

한 번에 하나의 상태

Ready, Playing, Won, Lost 중 하나만 현재 상태입니다. 여러 bool이 동시에 결과를 나타내지 않습니다.

REQUIRED 02 / HUD

점수와 시간 표시

Ready에서 0 / 3과 30.0을 보이고 Playing에서 실제 데이터와 함께 갱신합니다.

REQUIRED 03 / EVENTS

정확히 한 번의 수집

각 수집물은 Player 접촉 한 번에 점수 1, 효과음 1회와 비활성화 1회를 일으킵니다.

REQUIRED 04 / RESULTS

서로 배타적인 성공과 실패

목표가 먼저면 Won, 시간이 먼저면 Lost입니다. 결과 뒤 타이머와 추가 점수는 멈춥니다.

REQUIRED 05 / RESTART

초기 상태 완전 복원

두 결과의 Restart 모두 점수, 시간, 수집물, Panel과 게임 시간 흐름을 처음으로 되돌립니다.

REQUIRED 06 / BUILD

Editor 밖에서 같은 동작

Week07_Preflight Scene을 Scene List에 포함하고 실제 빌드에서 성공, 실패와 재시작을 재현합니다.

완료의 정의 “한 번 성공 화면이 나왔다”가 아니라, 처음부터 성공 → 재시작 → 실패 → 재시작을 반복해도 8개 결과가 모두 PASS이면 완료입니다.

고정 조건과 선택

검증할 행동과 표현 선택을 구분합니다

목표지향 실습은 아무렇게나 만드는 시간이 아닙니다. 테스트에 필요한 값은 고정하고, 게임의 인상을 만드는 선택은 학생에게 남깁니다.

FIXED / TEST CONTRACT

모두 같아야 하는 행동

목표 3개, 제한 30초, 네 상태, 세 효과음, Start와 Restart, 필수 테스트 8개와 실제 빌드는 변경하지 않습니다.

FLEXIBLE / AUTHORING

각자 선택할 표현

HUD 위치, Panel 크기, 색, 글꼴, 문구, AudioClip과 수집물 배치는 자유입니다. 단, 정보가 읽히고 플레이를 가리지 않아야 합니다.

다른 구현도 허용

2교시의 Time.timeScale 방식 대신 Player와 타이머를 명시적으로 멈추는 구조를 써도 됩니다. 다만 상태가 한 번에 하나이며, 필수 테스트가 같은 관찰 결과를 보여야 합니다. 자신이 선택한 방식은 설명할 수 있어야 합니다.

최소 인터페이스

구조가 달라도 책임은 분명해야 합니다

아래는 2교시 기준 구현의 최소 인터페이스입니다. 이름을 바꾸거나 Script를 나눠도 되지만 각 책임의 소유자와 호출 방향이 명확해야 합니다.

STATEGameState

Ready, Playing, Won, Lost 중 현재 하나를 저장합니다.

STARTStartRound()

값을 초기화하고 Playing을 시작합니다.

EVENTAddScore(1)

Playing에서만 점수와 수집 피드백을 갱신합니다.

RESETRestartScene()

현재 Scene과 실행 데이터를 처음으로 되돌립니다.

책임가능한 위치관찰 가능한 기준
점수와 목표GameManager 또는 별도 Score 모델UI 문자열을 읽지 않고 정수 데이터로 성공 판정
타이머Playing 상태의 Update30.0에서 감소, 0 아래로 내려가지 않고 결과 뒤 정지
상태 전환한 관리자 ScriptWon과 Lost가 동시에 발생하지 않고 종료 함수가 한 번만 실행
UI 출력한 UpdateHud 함수 또는 명확한 View저장 데이터가 바뀐 직후 Text와 Panel이 같은 사실 표시
효과음GameManager의 AudioSource수집, 성공, 실패 사건마다 대응 Clip이 정확히 한 번 재생
재시작Scene 재로드 또는 동등한 전체 Reset두 결과에서 값, 수집물, UI와 게임 시간이 모두 초기 상태

디버깅 순서

증상이 보이면 원인에 가까운 층부터 봅니다

UI 색이나 글꼴부터 바꾸지 않습니다. 현재 상태, 실제 데이터, 사건 호출, Inspector 참조, 마지막 출력 순서로 처음 어긋난 지점을 찾습니다.

STATE→DATA→EVENT→REFERENCE→OUTPUT
Start를 눌러도 시간이 줄지 않습니다

State: CurrentState가 Playing인지 봅니다. Time: Time.timeScale이 1인지 확인합니다. Button: On Click이 Scene의 GameManager와 StartRound를 가리키는지 확인합니다.

점수 글자가 바뀌지 않거나 Null 오류가 납니다

Data: Debug Inspector나 로그로 score가 변하는지 봅니다. 변한다면 Reference: scoreText 필드에 TMP_Text가 연결되었는지, Output: UpdateHud가 호출되는지 확인합니다.

한 수집물에서 점수가 두 번 오릅니다

Collectible의 collected guard와 SetActive 순서를 확인합니다. Player에 Collider가 여러 개라면 같은 Trigger가 여러 접촉 사건을 받을 수 있으므로 한 번 처리한 사실을 먼저 기록합니다.

시간이 음수로 내려가거나 결과 뒤에도 변합니다

Mathf.Max(0f, ...)로 0에 고정하고, Update 시작에서 Playing이 아니면 return하는지 확인합니다. FinishRound를 매 프레임 반복 호출하지 않아야 합니다.

효과음이 들리지 않습니다

AudioSource, Clip 참조, Mute, Volume, Audio Listener 순서로 확인합니다. Scene 안의 Audio Listener는 보통 Main Camera에 하나만 있어야 합니다.

Restart가 Editor 또는 빌드에서 실패합니다

using UnityEngine.SceneManagement;, public 함수와 Button On Click을 확인합니다. 빌드에서는 Scene List 포함 여부와 체크 상태를 추가로 확인하고, 로드 전에 Time Scale을 1로 복원합니다.
