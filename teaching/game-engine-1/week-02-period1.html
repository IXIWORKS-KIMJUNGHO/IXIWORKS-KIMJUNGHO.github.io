이번 교시는 학생이 기능을 따라 만드는 시간이 아닙니다. 교사의 화면을 함께 읽고, 같은 대상을 여러 창에서 관찰하면서 Unity의 기본 문법을 세웁니다.

  2. 08-22Editor의 여섯 창

    창의 위치가 아니라 각 창이 답하는 질문을 기준으로 설명합니다.

  3. 22-36Unity의 네 층

    Project, Scene, GameObject, Component의 포함 관계를 한 장면으로 풉니다.

  4. 36-48선택과 Inspector

  6. 56-60회수 질문

여섯 창은 서로 다른 질문에 답합니다

Unity의 Layout은 기기와 설정에 따라 달라질 수 있습니다. 왼쪽, 오른쪽 같은 위치보다 창의 이름과 역할을 기억해야 다른 화면에서도 길을 잃지 않습니다.

교수자 도입 문장

Unity Editor는 게임을 보여 주는 한 화면이 아니라, 같은 프로젝트를 여러 관점에서 살펴보는 작업대입니다.

Scene

어디에 놓을까?

GameObject를 선택하고 위치, 회전, 크기와 구성을 편집하는 제작 화면입니다.

만드는 사람의 시점
Game

플레이어에게 어떻게 보일까?

Main Camera가 촬영하는 최종 화면을 확인합니다. Scene 뷰와 보이는 범위가 다를 수 있습니다.

카메라의 시점
Hierarchy

현재 Scene에 무엇이 있을까?

열려 있는 Scene의 GameObject 목록과 부모, 자식 관계를 보여 줍니다.

현재 장면의 구조
Inspector

선택한 대상은 어떤 상태일까?

선택한 GameObject의 Component와 값, 또는 선택한 Asset의 설정을 보여 줍니다.

선택에 따라 내용이 달라짐
Project

어떤 재료가 저장되어 있을까?

Assets 폴더의 Scene, Prefab, 이미지, 소리와 Script 같은 파일을 관리합니다.

프로젝트의 저장된 재료
Console

무슨 일이 기록되었을까?

오류, 경고와 실행 메시지를 모아 보여 줍니다. 문제가 생기면 가장 먼저 확인합니다.

상태와 문제의 기록
판서 핵심 Scene은 만든다. Game은 확인한다. Hierarchy는 고른다. Inspector는 바꾼다. Project는 보관한다. Console은 알린다.

창 이름을 설명할 때마다 이 동사로 돌아오면 초보자가 역할을 빠르게 구분할 수 있습니다.

Scene 뷰에서 보인다고 Game 뷰에도 보이는 것은 아닙니다

Scene 뷰는 제작 공간 전체를 자유롭게 보는 화면입니다. Game 뷰는 Main Camera의 촬영 범위만 보여 줍니다. 오브젝트가 사라졌다고 느끼면 먼저 두 화면을 구분합니다.

Unity는 큰 단위에서 작은 단위로 읽습니다

네 용어는 나란히 놓인 기능 목록이 아닙니다. 큰 그릇 안에 작은 단위가 포함되고, 가장 작은 기능 조각이 GameObject의 행동과 모습을 결정합니다.

Project게임 전체 작업

여러 Scene, Asset, 설정과 패키지를 함께 담는 가장 큰 단위입니다.

Scene한 장면 또는 상태

레벨, 메뉴, 테스트 공간처럼 GameObject가 배치되는 저장 단위입니다.

GameObject장면 속 대상

플레이어, 카메라, 배경처럼 이름과 계층을 가진 기본 그릇입니다.

Component대상이 가진 기능

위치, 화면 표시, 카메라 촬영처럼 실제 역할을 나누어 담당합니다.

Project > Scene > GameObject > Component

설명 비유

Project가 공연 전체라면 Scene은 한 막, GameObject는 무대 위 배우와 소품, Component는 각 대상이 가진 위치, 모습, 소리와 행동입니다.

Project
GE1_Week02 폴더 전체입니다. Scene 파일뿐 아니라 이미지와 프로젝트 설정까지 함께 있어야 다른 컴퓨터에서도 같은 작업을 열 수 있습니다.
Scene
Week02_Playground.unity처럼 저장되는 하나의 장면 파일입니다. 이 파일은 현재 배치와 각 GameObject의 상태를 기억합니다.
GameObject
그 자체만으로는 기능이 정해지지 않은 기본 단위입니다. 이름을 가지고 Hierarchy에 놓이며, 반드시 Transform을 가집니다.
Component
GameObject에 붙어 기능을 더합니다. 같은 GameObject도 어떤 Component를 붙였는지에 따라 카메라, 그림, 소리 또는 움직이는 대상으로 달라집니다.

GameObject는 빈 상자라는 표현을 정확히 이해합니다

아무 기능도 없다는 뜻이 아니라, 기능이 Component로 조립된다는 뜻입니다. 모든 GameObject에는 위치와 계층을 담당하는 Transform이 기본으로 붙으며 제거할 수 없습니다.

선택이 Hierarchy와 Inspector를 연결합니다

초보자가 Inspector를 어렵게 느끼는 가장 큰 이유는 Inspector가 고정된 설정 창이라고 생각하기 때문입니다. Inspector는 마지막으로 선택한 대상의 설명서입니다.

교수자 화면 시연
  1. Hierarchy에서 Main Camera를 선택하고 Inspector의 Component 이름만 천천히 읽습니다.
  2. Hierarchy의 다른 GameObject를 선택해 Inspector 내용이 즉시 바뀌는 것을 보여 줍니다.
  3. Project 창에서 Scene Asset을 선택해 이번에는 GameObject가 아니라 파일 설정이 나타난다고 설명합니다.
  4. 다시 Hierarchy의 Main Camera를 선택하며 선택의 출발점이 Inspector의 내용을 결정한다고 정리합니다.
판서 핵심 Hierarchy에서 고르면 Scene의 대상, Project에서 고르면 저장된 Asset을 Inspector가 설명합니다.

Asset과 Instance를 구분하면 저장이 보입니다

Project 창의 파일과 Scene에 배치된 대상은 서로 연결될 수 있지만 같은 것은 아닙니다. 이 구분은 다음 교시의 Prefab을 이해하는 바탕입니다.

Asset

Project 창에 저장된 원본 재료

Scene, Prefab, 이미지와 Script처럼 프로젝트 폴더에 파일로 남는 대상입니다. 프로젝트를 닫았다가 열어도 존재합니다.

Instance

현재 Scene에 놓인 실제 사용본

Hierarchy에 보이는 GameObject입니다. 위치와 Component 값은 Scene의 일부로 저장됩니다.

Collectible_01, Collectible_02

저장 버튼은 무엇을 저장할까요?

Scene 저장
Ctrl/Cmd + S는 열려 있는 Scene의 GameObject 배치와 Component 값을 Scene Asset에 기록합니다. Scene 이름 옆 별표가 사라졌는지 확인합니다.
Project 파일
가져온 이미지, 만든 Prefab과 Script는 Project 창의 Assets 폴더에 별도 Asset으로 존재합니다.
Play Mode
Play 중 Inspector에서 바꾼 Scene 값은 테스트용 임시 변경입니다. Play를 멈추면 대부분 시작 전 상태로 돌아오므로 영구 편집은 Edit Mode에서 합니다.

프로젝트를 저장한다는 표현은 범위를 확인해야 합니다

Unity에는 Scene 파일, Prefab Asset, Project 설정처럼 서로 다른 저장 대상이 있습니다. 이번 주에는 먼저 Scene을 명시적으로 저장하고 Project 창에서 파일이 생겼는지 확인합니다.

교수자 시연

8분 시연으로 모든 창을 한 번 연결합니다

학생에게 같은 조작을 요구하지 않습니다. 교사는 하나의 선택이 여러 창에 어떤 변화를 만드는지 천천히 보여 주고, 학생은 결과를 예측한 뒤 관찰합니다.

  1. Scene과 Game을 나란히 봅니다

    Scene 뷰에서 카메라 프레임 밖의 오브젝트를 가리킨 뒤 Game 뷰에서는 보이지 않는 이유를 묻습니다.

    관찰점제작 공간과 최종 촬영 범위는 다릅니다.

  2. Hierarchy에서 Main Camera를 선택합니다

    선택 표시와 Inspector의 Transform, Camera Component를 연결해 읽습니다.

    관찰점GameObject의 기능은 Component 목록으로 보입니다.

  3. Project의 Scene Asset을 선택합니다

    같은 Inspector가 이번에는 파일 정보를 보여 준다는 점을 비교합니다.

    관찰점어디에서 선택했는지가 Inspector의 대상을 바꿉니다.

  4. Console을 열고 정상 상태를 확인합니다

    빨간 오류, 노란 경고, 일반 메시지의 시각적 차이를 짧게 소개합니다.

    관찰점문제가 보이지 않아도 Console은 확인 대상입니다.
중간 질문

지금 Inspector가 설명하는 것은 장면 속 GameObject인가요, Project에 저장된 Asset인가요? 선택한 위치를 근거로 답해 봅시다.

처음 생기는 오해를 바로잡습니다

용어를 많이 외우는 것보다 비슷해 보이는 개념의 경계를 정확히 세우는 것이 중요합니다.

Scene 뷰가 게임 화면이다

Scene은 제작자의 편집 화면이고 Game은 Main Camera가 보여 주는 플레이 화면입니다.

Inspector는 설정 메뉴다

Inspector는 고정된 메뉴가 아니라 현재 선택한 GameObject 또는 Asset의 상태를 보여 주는 창입니다.

GameObject가 기능을 모두 가진다

GameObject는 기능의 그릇입니다. 위치, 화면 표시와 행동은 각각의 Component가 담당합니다.

Hierarchy는 파일 목록이다

Hierarchy는 현재 Scene의 GameObject 목록입니다. 실제 Asset 파일은 Project 창에서 관리합니다.

Play 중 바꾸면 저장된다

Play Mode의 Scene 값 변경은 테스트가 끝나면 되돌아갈 수 있습니다. 영구 편집은 Play를 멈춘 뒤 저장합니다.

화면을 닫고 세 문장으로 회수합니다

먼저 소리 내어 답한 뒤 정답을 엽니다. 맞힌 개수보다 이유를 완전한 문장으로 설명하는 것이 목표입니다.

Scene 뷰에는 보이지만 Game 뷰에는 보이지 않는 이유는 무엇인가요?

Scene 뷰는 제작 공간 전체를 보여 주지만 Game 뷰는 Main Camera의 촬영 범위만 보여 줍니다. 따라서 카메라 프레임 밖의 대상은 Game 뷰에 나타나지 않습니다.

Hierarchy에서 Player를 선택하면 Inspector에는 무엇이 보이나요?

현재 Scene의 Player GameObject에 붙은 Transform, Sprite Renderer 같은 Component와 각 값이 보입니다.

Project, Scene, GameObject, Component를 큰 순서대로 말해 보세요.

Project 안에 Scene이 있고, Scene 안에 GameObject가 배치되며, GameObject는 Component로 기능을 얻습니다.

1교시 종료 문장 Unity Editor는 선택한 대상을 여러 창에서 연결해 읽고, GameObject에 붙은 Component를 수정하는 작업 환경입니다.

수업 기준이 되는 Unity 문서

메뉴 위치가 달라졌을 때는 화면 캡처보다 현재 Editor의 창 이름과 공식 문서를 기준으로 확인합니다.

  • Unity Hub 프로젝트 생성 ↗Editor 버전, 템플릿, 이름과 위치를 정해 프로젝트를 만드는 흐름
  • Unity Editor 소개 ↗Editor를 구성하는 주요 창과 작업 공간
  • Hierarchy 창 ↗현재 Scene의 GameObject와 부모, 자식 구조
  • GameObject ↗Scene을 구성하는 기본 대상과 Component의 관계
  • Component ↗GameObject에 기능을 더하는 구성 요소
  • Scene 작업 ↗Scene 생성, 열기와 저장의 기본 원칙
