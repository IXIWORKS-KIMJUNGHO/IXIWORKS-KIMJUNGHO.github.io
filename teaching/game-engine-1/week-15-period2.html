같은 질문으로 릴리스 준비를 판정합니다

교수자가 하나의 RC0를 실행하고 같은 증거 순서로 READY, READY IF, HOLD 판정을 시연합니다.

2교시의 도착점

관찰한 사실과 판정을 분리하고, 한 학생에게 적용한 질문을 다른 학생에게도 같은 순서로 적용합니다.

  • 01

    면담을 발표가 아니라 릴리스 위험 검토로 설명합니다.

  • 02

    주장과 실제 build에서 확인한 증거를 분리합니다.

  • 03

    모든 사례에 같은 관문과 질문을 적용해 판정의 공정성을 지킵니다.

  • 04

    결과를 READY, READY IF, HOLD 중 하나와 다음 행동으로 기록합니다.

CLASS MODE / PERIOD 02교수자 설명과 공개 릴리스 면담 시연

학생 제작 없음. 학생은 프로젝트를 제작하지 않습니다. 교수자가 같은 RC0, 같은 질문, 같은 순서로 공개 면담을 시연하고 학생은 각 관문의 판정을 먼저 구술한 뒤 실제 근거와 비교합니다.

60분의 설명과 시연 흐름

판정 언어를 먼저 맞춘 뒤 하나의 수업용 RC0를 끝까지 검토하고 기록으로 닫습니다.

  2. 06-14

  4. 24-38

    검토 기록 회수

    주장, 증거, 판정과 다음 행동을 네 줄로 말하며 3교시 미션을 예고합니다.

면담은 네 동사로 움직입니다

자유로운 대화처럼 보여도 교수자는 항상 실행에서 시작해 판정과 다음 행동으로 끝냅니다.

RUN

학생 설명 전에 실행

새 폴더에서 RC0를 열고 시작 화면부터 결과와 재시작까지 실제 경로를 확인합니다.

OBSERVE

보인 사실만 기록

멈춘 위치, 화면 상태, 입력, 시각과 소리, Console 또는 log의 시각을 적습니다.

ASK

가까운 증거를 질문

“왜 그랬나요?”보다 “그 상태를 바꾸는 사건과 값은 어디에 있나요?”를 묻습니다.

DECIDE

한 판정과 한 행동

첫 실패 관문을 기준으로 READY, READY IF, HOLD와 3교시 행동 하나를 확정합니다.

INTERVIEW RULE설명이 길어져도 관문을 건너뛰지 않습니다. 같은 사실에는 같은 판정 언어를 사용합니다.

다섯 입력물이 열려야 면담을 시작합니다

파일이 있다는 주장보다 지정 위치에서 실제로 열리는지가 먼저입니다.

고정 사례: 끝까지 되지만 다시 시작되지 않는 숲 게임

교수자는 수업용 RC0를 한 번만 실행하고, 학생은 왼쪽 사실에서 오른쪽 해석을 성급하게 만들지 않는 연습을 합니다.

OBSERVED FACTS

실제로 확인한 것

독립 실행은 성공했습니다. 목표 지점과 결과 화면까지 도착했습니다. 재시작 버튼 뒤 Player 위치는 초기화되지만 수집 수가 이전 값으로 남습니다. Player log에 NullReferenceException은 없습니다.

NOT YET A FACT

아직 확인하지 않은 해석

점수 Script가 잘못되었다, 저장 기능이 문제다, UI가 늦게 갱신된다는 말은 가설입니다. Inspector의 현재 값과 재시작 사건의 호출 순서를 확인하기 전에는 원인으로 기록하지 않습니다.

  1. 01

    재현 조건을 고정합니다

    RC0, 첫 시작, 수집물 3개, 목표 도착, 결과 화면, 재시작의 입력 순서를 적습니다.

    관찰 재시작 뒤 플레이어 위치는 초기화되고 수집 수만 3으로 남습니다.

  2. 02

    첫 실패 관문을 고릅니다

    실행과 핵심 경로는 통과했지만 상태와 복구 관문이 실패했습니다.

    판정 현재 결과는 READY가 아니며 수정 조건이 좁혀질 수 있습니다.

  3. 03

    한 행동과 재검사를 승인합니다

    3교시에는 새 기능 없이 재시작 사건에서 수집 상태를 초기화하고 같은 순서와 전체 핵심 경로를 다시 검사합니다.

    범위 관련 상태 소유자와 재시작 연결만 허용합니다.

판정은 세 가지뿐입니다

좋음, 아쉬움처럼 사람마다 달라지는 표현 대신 제출 가능성과 남은 조건을 말합니다.

READY

그대로 제출 후보

여덟 관문이 통과했고 제출 묶음을 다시 열었습니다. 새 기능은 추가하지 않고 최종 복사본을 보존합니다.

READY IF

한 조건 뒤 제출 후보

첫 실패가 작고 변경 범위와 재검사가 명확합니다. 조건이 통과하기 전까지는 READY라고 기록하지 않습니다.

HOLD

안전한 기준선 보존

실행, 진행, 권리 또는 제출을 막는 위험이 크거나 원인이 불명확합니다. RC0를 보존하고 진단 또는 제거 경로를 선택합니다.

DEMO VERDICT숲 게임 RC0는 READY IF입니다. 재시작 상태 초기화와 같은 핵심 경로 회귀 검사가 통과하면 RC1로 이동합니다.

에셋은 출처와 실제 사용 상태를 함께 봅니다

생성 도구 이름만 묻지 않고 최종 build에 들어간 파일과 ledger의 한 행을 연결합니다.

CLAIM

학생의 주장

현재 RC0가 통과한다고 생각하는 관문과 아직 남은 위험을 한 문장으로 씁니다.

EVIDENCE

함께 확인한 사실

build 경로, 입력 순서, 화면 결과, log 시각과 파일 위치를 적습니다.

VERDICT

교수자의 판정

READY, READY IF, HOLD 중 하나와 첫 실패 관문을 기록합니다.

NEXT ACTION

3교시 한 행동

수정, 삭제, 진단 또는 보류 범위와 같은 재검사 조건을 적습니다.

RECORD QUALITY

“버그 수정하기”는 행동이 아닙니다. “재시작 뒤 수집 수가 0이고 핵심 경로가 다시 끝나는지 T03과 T07로 검사”처럼 관찰 가능한 완료 조건을 씁니다.

공정성은 같은 시간을 주는 것보다 같은 증거를 요구하는 일입니다

작품의 장르와 표현은 달라도 제출 가능성을 막는 사실은 같은 방식으로 확인합니다.

학생 설명이 유창하면 더 높은 판정을 받아도 되나요?

학생의 말만으로 판정하지 않습니다. 같은 build, 입력, log와 파일을 열어 말과 증거가 일치하는지 확인합니다.

작품마다 플레이 시간이 다른데 표준 8분이 가능한가요?

전체 콘텐츠를 보는 시간이 아니라 첫 실패 관문을 찾는 시간입니다. 핵심 경로가 5분을 넘으면 제출 범위 자체를 다시 판정합니다.

AI를 사용하지 않은 학생은 권리 질문을 건너뛰나요?

건너뛰지 않습니다. 외부 에셋, 수업 제공 자료와 직접 제작 상태를 확인하고 AI 항목은 NONE으로 명시합니다.

수정 방법을 바로 알려 주면 더 빠르지 않나요?

면담에서는 원인과 범위를 대신 결정하지 않습니다. 가까운 증거를 찾는 질문 한 번을 제공하고 학생이 다음 행동과 검사를 말하게 합니다.
