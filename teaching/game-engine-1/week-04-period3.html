01 / MISSION CONTRACT

목표는 고정하고 방법은 선택합니다

아래 사양은 모두 충족해야 합니다. 폴더를 먼저 만들지, Player를 먼저 구성할지, Input Actions부터 확인할지는 각자 결정합니다.

MISSION / WEEK04_INPUTPHYSICS

60분 안에 하나의 Player가 두 종류의 키보드 입력으로 일정한 속도로 움직이고, 손을 놓으면 멈추며, 네 개 이상의 Wall과 충돌하는 Scene을 완성합니다. 완료는 필수 테스트 8개의 PASS로 판단합니다.

REQUIRED 01 / INPUT

하나의 Move Action

Player / Move가 Value / Vector2이며 WASD와 방향키의 2D Vector Composite를 모두 가집니다.

REQUIRED 02 / PLAYER

물리 기반 Player

Rigidbody2D, Collider2D, PlayerController를 사용합니다. Gravity Scale은 0이고 Z 회전은 고정합니다.

REQUIRED 03 / BEHAVIOR

예측 가능한 이동

입력은 Update에서 읽고, linearVelocity는 FixedUpdate에서 적용합니다. 대각선 크기는 1 이하입니다.

REQUIRED 04 / COURSE

검증 가능한 충돌장

Box Collider 2D를 가진 Wall을 네 개 이상 배치해 정면과 대각선 충돌을 반복해서 확인할 수 있게 합니다.

REQUIRED 05 / QUALITY

오류 없는 실행

Play 전후 Console Error가 0개이며, 하나의 Player를 두 Script나 Transform 코드가 동시에 움직이지 않습니다.

REQUIRED 06 / EVIDENCE

결과가 남는 검증

8개 테스트의 판정과 관찰 내용을 기록하고, 계기판과 코스가 보이는 화면 증거를 저장합니다.

완료의 정의 “움직여 보였다”가 아니라, 다른 사람이 같은 조건으로 다시 실행해도 8개 결과가 모두 PASS이면 완료입니다.

04 / MINIMUM SPEC

구현 전에 인터페이스를 확인합니다

코드 모양은 조금 달라도 괜찮지만, 아래 입력·상태·출력과 생명주기는 같아야 합니다.

INPUTMove / Vector2

WASD와 방향키가 같은 값을 만듭니다.

STATEmoveInput

가장 최근의 방향 의도를 저장합니다.

PARAMETERmoveSpeed

Inspector에서 조절하는 초당 속도입니다.

OUTPUTlinearVelocity

Rigidbody2D에 전달할 실제 물리 속도입니다.

위치필수 책임통과 기준
Awake같은 GameObject의 Rigidbody2D 참조 저장Play 중 NullReferenceException이 없음
OnEnableMove Action 확인 및 활성화입력 계기판 값이 바뀜
OnDisableMove Action 비활성화생명주기가 대칭임
UpdateVector2 읽기, 크기 최대 1로 제한대각선 Speed가 직선과 같음
FixedUpdate입력 × 속도를 linearVelocity에 적용손을 놓으면 즉시 Speed 0
참고 자료

전체 기준 코드는 2교시 Controller 해설에 있습니다. 그대로 붙여 넣기보다, 현재 자신이 해결하는 책임에 해당하는 블록만 읽고 직접 입력합니다.

06 / DEBUG LADDER

FAIL은 가까운 단계부터 좁힙니다

전체 코드를 한꺼번에 바꾸지 않습니다. 화면에서 확인 가능한 신호를 왼쪽부터 따라가며 처음 끊긴 곳을 찾습니다.

KEY / STICK→MOVE VALUE→moveInput→linearVelocity→COLLISION
1단계 힌트 · 입력값이 계속 (0, 0)

관찰: Input Actions 에셋을 열어 Move의 바인딩을 확인합니다. 비교: Action Type은 Value, Control Type은 Vector2인지 봅니다. 한 가지 수정: 에셋 저장 또는 Move Action 참조 연결 중 하나만 먼저 고칩니다.

2단계 힌트 · 값은 바뀌지만 속도가 0

관찰: PlayerController의 moveSpeed와 Rigidbody2D Body Type을 봅니다. 비교: FixedUpdate가 body.linearVelocity에 값을 쓰는지 확인합니다. 한 가지 수정: 처음 발견한 어긋남 하나만 고칩니다.

3단계 힌트 · 대각선만 더 빠름

관찰: W+D에서 Move와 Speed를 각각 기록합니다. 비교: ClampMagnitude의 결과를 다시 moveInput에 저장했는지 봅니다. 예상: moveSpeed가 5이면 직선과 대각선 모두 Speed 5입니다.

4단계 힌트 · 키를 놓아도 움직임

관찰: 키를 놓았을 때 Move가 (0, 0)으로 돌아오는지 봅니다. 값은 0인데 미끄러지면 다른 Script, Damping 또는 속도를 덮어쓰는 코드가 있는지 확인합니다.

5단계 힌트 · 벽을 통과함

관찰: Scene 뷰의 Gizmos로 두 Collider 경계를 봅니다. 비교: 양쪽 모두 2D Component인지, Wall의 Is Trigger가 꺼졌는지 확인합니다. 검색: Player Transform을 직접 바꾸는 다른 Script가 없는지 찾습니다.

6단계 힌트 · 코드가 컴파일되지 않음

Console의 가장 위에 있는 첫 빨간 오류 하나만 읽습니다. 파일명과 class명, 괄호의 짝, using UnityEngine.InputSystem;, 표시된 줄 바로 위를 순서대로 확인합니다.

ASK TEMPLATE / 설명만 요청

[Unity 6.3 LTS / Week 04] Console 원문: ___ / 오류 줄: ___ / 내가 기대한 값: ___ / 실제로 본 값: ___. 코드를 대신 작성하거나 수정하지 말고, 어느 단계의 문제인지와 먼저 확인할 한 항목만 설명해 주세요.
