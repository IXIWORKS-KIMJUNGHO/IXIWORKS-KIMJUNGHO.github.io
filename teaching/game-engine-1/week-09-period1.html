Game Engine I / Week 09 / 1교시

먼저 방향을 정하고,
그다음 생성합니다

생성형 AI는 결정을 대신하는 미술 감독이 아닙니다. 사람의 콘셉트와 시각 규칙 안에서 후보를 빠르게 보여 주는 제작 도구입니다.

Ask·Plan·Agent 구분하기 안전한 생성 원칙 보기

1교시의 도착점

도구 이름을 외우기보다 어떤 결정은 사람이 해야 하고, 어떤 작업만 AI에 맡길 수 있는지 설명할 수 있게 합니다.

  • 01

    제작 단계 AI와 runtime AI를 사용 시점과 책임으로 구분합니다.

  • 02

    Ask, Plan, Agent, Generator가 프로젝트에 미치는 변경 범위를 비교합니다.

  • 03

    게임 아트 디렉션을 취향이 아니라 반복 가능한 시각 규칙으로 설명합니다.

  • 04

    참조 이미지의 권리·개인정보·출처 기록을 생성 전에 확인합니다.

CLASS MODE / PERIOD 01교수자 이론과 설명

학생은 프로젝트를 제작하지 않습니다. 교수자의 사례와 생성 과정을 관찰하고, 어떤 규칙과 권한이 먼저 필요한지 예측합니다. 이미지 후보 제작은 2교시 시연 뒤 3교시 개인 실습에서 수행합니다.

60분의 설명 흐름

중간평가에서 완성한 작은 게임을 출발점으로 삼아, 후반부 제작에 필요한 시각 언어와 AI 사용 경계를 세웁니다.

00-60 min

그림을 만들기 전에 결정 구조 만들기

Lecture / professor-led

  1. 00-07
    중간평가 장면 다시 보기

    기능은 같지만 캐릭터, 색, 카메라가 제각각인 세 화면을 보고 왜 하나의 세계처럼 느껴지지 않는지 묻습니다.

  2. 07-17
    두 종류의 AI 구분

    제작 중 후보를 만드는 AI와 게임 실행 중 판단하는 runtime AI를 사용 시점으로 나눕니다.

  3. 17-29
    자율성 네 단계

    Ask, Plan, Agent와 Generator가 읽고 계획하고 변경하고 생성하는 범위를 비교합니다.

  4. 29-40
    아트 디렉션의 일곱 결정

    주제, 실루엣, 시점, 팔레트, 재질, 빛과 금지 요소를 하나의 규칙 묶음으로 정의합니다.

  5. 40-52
    권리·개인정보·출처

    참조 이미지를 넣기 전에 허락과 이용 조건을 확인하고, 생성 뒤에도 과정 기록을 보존합니다.

  6. 52-60
    생성 전 네 질문

    목적, 고정 규칙, 변경 변수, 검증 기준을 학생의 말로 복원합니다.

AI는 언제 작동하느냐에 따라 책임이 달라집니다

둘 다 인공지능이라고 부르지만, 제작 중 사용하는 도구와 플레이어의 기기에서 실행되는 시스템은 설계 질문이 다릅니다.

PRODUCTION-STAGE AI

게임을 만드는 동안 사용합니다

콘셉트 후보, 정적 Sprite, UI와 사운드 초안을 만들거나 설명과 계획을 얻습니다. 결과는 사람이 선택·수정·검증한 뒤 프로젝트에 들어갑니다.

RUNTIME AI

게임이 실행되는 동안 작동합니다

NPC 판단, 절차적 대화나 동적 난이도처럼 플레이 중 입력에 반응합니다. 성능, 지연, 안전, 네트워크와 예측 가능성까지 설계해야 합니다.

한 문장 콘셉트+시각 규칙→제작 단계의 정적 후보
이번 주의 경계

9주차에는 runtime AI를 게임에 넣지 않습니다. 생성한 이미지도 완성 에셋이 아니라 방향을 비교하기 위한 후보입니다. 배경 제거, 해상도 조정, 픽셀화와 Unity 연결은 10주차에서 다룹니다.

같은 문장도 모드에 따라 결과의 범위가 달라집니다

좋은 AI 활용은 가장 강한 모드를 고르는 일이 아닙니다. 지금 필요한 만큼만 읽고, 계획하고, 생성하거나 변경하게 하는 일입니다.

방식주된 역할프로젝트 변경사람이 먼저 확인할 것9주차 사용
Ask질문, 설명, 비평없음무엇을 이해하거나 비교할지허용
Plan단계와 완료 조건 정리승인 전 없음예상 순서, 범위, 검증 기준허용
Agent파일·Scene·Asset 직접 변경있음권한, 대상, 되돌리기 지점개념만 설명
Generator이미지 후보 생성새 이미지 파일 생성목적, 시각 규칙, 참조 권리, 저장 위치정적 후보만 허용
  1. 01 / ASK이해합니다

    현재 장면과 목표의 차이를 읽고 질문합니다.

  2. 02 / PLAN예측합니다

    고정할 규칙, 바꿀 변수와 판정 방법을 적습니다.

  3. 03 / GENERATE후보를 만듭니다

    정해진 범위 안에서 비교 가능한 결과를 만듭니다.

  4. 04 / REVIEW사람이 선택합니다

    기준표로 채택과 거절 이유를 남깁니다.

  5. 05 / RECORD과정을 보존합니다

    도구, 프롬프트, 참조와 직접 수정을 기록합니다.

수업 원칙 9주차 개인 실습에서는 Ask·Plan·Generator를 사용할 수 있지만 Agent는 Unity 프로젝트를 변경하지 않습니다. 최종 선택과 제출 판정은 학생이 직접 수행합니다.

스타일은 한 단어가 아니라 서로 맞물린 규칙입니다

“귀엽게”, “멋진 판타지”처럼 넓은 말만 주면 후보마다 다른 세계가 나옵니다. 반복해서 확인할 수 있는 결정으로 바꿔야 합니다.

01 / FANTASY누가 무엇을 하며 어떤 감정을 만드는가플레이어 역할과 게임의 정서
02 / SUBJECT기능이 읽히는 대상과 대표 소품배달부라면 가방, 탐험가라면 등불처럼 역할을 보여 주는 단서
03 / SHAPE실루엣과 형태 언어둥근 안전함, 뾰족한 위험처럼 반복할 형태 규칙
04 / VIEW카메라 시점과 화면 크기정면, 측면, top-down 3/4 중 하나와 64px 확인 크기
05 / COLOR다섯 색 팔레트와 대비배경, 몸통, 그림자, 강조와 검증 색의 역할
06 / MATERIAL · LIGHT표면과 빛의 규칙종이, 픽셀, 점토, 평면 음영 중 하나와 빛의 방향
07 / AVOID나오면 안 되는 요소텍스트, 복잡한 배경, 사실적 피부, 과도한 장식처럼 세 가지 이상
WEAK

“예쁜 판타지 캐릭터”

대상과 분위기만 있고 시점, 기능, 형태, 색, 크기와 금지 요소가 없습니다. 결과를 비교해도 무엇이 더 맞는지 설명하기 어렵습니다.

DIRECTED

“64px에서 가방이 읽히는 숲의 배달부”

top-down 3/4, 둥근 실루엣, 짙은 청록 몸통, 산호색 강조, 왼쪽 위의 부드러운 빛, 배경과 글자 없음까지 확인할 수 있습니다.

안전한 생성

입력할 수 있는 이미지와 사용할 수 있는 결과를 따로 확인합니다

다음 내용은 법률 자문이 아니라 수업에서 지켜야 할 최소 안전선입니다. 서비스 약관과 라이선스, 학교 규정과 실제 배포 지역의 기준은 프로젝트마다 다시 확인합니다.

참조 후보먼저 확인할 것수업 판단기록
직접 그린 그림·직접 찍은 사물사진 속 다른 사람과 개인정보 유무확인 뒤 사용 가능직접 제작, 날짜
공공저작물·CC 자료출처, 정확한 라이선스, 변경·상업 이용 조건조건을 지킬 수 있을 때 사용URL, 제작자, 라이선스

스타일을 말하는 더 안전한 방법

수업 프롬프트에는 생존 작가의 이름을 스타일 지름길로 사용하지 않습니다. “굵은 외곽선, 제한된 다섯 색, 종이 질감, 낮은 명도 배경”처럼 관찰 가능한 시각 속성으로 설명합니다.

Provenance는 이미지가 여기까지 온 경로입니다

완성 파일만 보면 어떤 참조와 판단이 들어갔는지 알 수 없습니다. 출처 기록은 결과를 설명하고, 다시 만들고, 문제가 생겼을 때 되짚는 제작 증거입니다.

  1. 01 / PURPOSE생성 목적

    캐릭터 후보, UI 아이콘 등 어디에 쓸 시안인지 적습니다.

  2. 02 / TOOL도구와 날짜

    서비스, 모델 또는 기능 이름과 생성 날짜를 남깁니다.

  3. 03 / INPUT프롬프트와 참조

    원문, 출처, 허락·라이선스와 참조 역할을 기록합니다.

  4. 04 / DECISION선택과 거절

    어떤 기준으로 하나를 남기고 둘을 버렸는지 적습니다.

  5. 05 / HUMAN EDIT사람의 수정

    재배치, 재채색, 덧그림과 후처리를 구체적으로 기록합니다.

CONTENT CREDENTIALS C2PA의 Content Credentials는 파일의 생성·수정 이력을 검증 가능한 형태로 연결하는 표준입니다. 다만 메타데이터가 있다고 판단이 자동으로 옳아지는 것은 아니므로, 수업에서는 별도의 제작 로그도 함께 보존합니다.

회수 질문

생성 버튼을 누르기 전 네 질문

먼저 자신의 말로 답한 뒤 펼쳐 확인합니다. 네 문장에 답하지 못하면 프롬프트를 길게 쓰기보다 방향을 먼저 정리합니다.

Q1. 이 이미지는 게임 제작의 어느 단계에서 무엇을 결정하기 위한 후보인가?

예: “10주차에 정적 캐릭터 Sprite로 후처리할 방향 후보이며, 이번 주에는 실루엣과 팔레트만 결정한다.”처럼 사용 시점과 결정 항목을 함께 말합니다.

Q2. 결과가 달라도 반드시 유지되어야 할 규칙은 무엇인가?

같은 대상, 기능, 시점, 형태 언어, 다섯 색 팔레트, 빛과 금지 요소를 고정 목록으로 적습니다.

Q3. 이번 한 번의 생성에서 바꿀 변수는 정확히 무엇인가?

모자 모양, 가방 재질, 강조색처럼 하나만 정합니다. 여러 요소를 동시에 바꾸면 어떤 변화가 결과를 개선했는지 설명할 수 없습니다.

Q4. 어떤 기준과 기록으로 하나를 선택할 것인가?

64px 실루엣, 게임 기능, 스타일 보드 일치, 수정 가능성, 권리·출처 기록을 기준으로 비교하고 선택·거절 이유를 남깁니다.

01

Ask는 설명과 분석을 제공하지만 프로젝트를 ______하지 않습니다.

02

생성 전에는 목적, 고정 규칙, 변경 변수와 ______ 기준을 먼저 정합니다.

03

참조 이미지에는 출처, 이용 조건과 참조의 ______을 기록합니다.
