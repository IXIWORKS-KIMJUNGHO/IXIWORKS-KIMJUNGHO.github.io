CLASS MODE / PERIOD 03학생 개인 목표지향 실습

목표는 고정하고 구현 경로는 선택합니다. 교수자는 클릭 순서를 함께 따라 하지 않고 질문, 범위 축소와 테스트 판정을 돕습니다. 테스터는 같은 절차로 다른 학생의 build를 실행하지만 공동 제작, Script 수정, 에셋 선택과 제출 판정에는 참여하지 않습니다.

세 명의 첫 시도로 문제 하나를 찾아 닫습니다

이번 목표는 기능을 늘리는 것이 아니라 피드백과 플레이 흐름을 증거로 개선하는 것입니다. 아래 네 문장이 모두 참이면 미션을 완료합니다.

FREEZE

Alpha v0

세 테스트 동안 같은 실행 build를 사용하고 중간 수정은 하지 않습니다.

OBSERVE

A · B · C

설명 없는 첫 시도 세 번을 같은 과제·시간·질문으로 기록합니다.

CHANGE

One issue

P0 또는 P1 한 문제만 선택하고 새 mechanic 없이 최소 수정합니다.

PROVE

Alpha v1

같은 질문의 재검사, 기존 루프 회귀 검사와 8 / 8 PASS를 남깁니다.

ASSESSMENT RULE

작업 속도와 생성 횟수는 평가하지 않습니다. 문제를 많이 고치거나 AI를 많이 사용해도 가산되지 않습니다. 실제 관찰 → 선택 근거 → 한 가지 수정 → 재검증의 연결과 독립 실행 build를 평가합니다.

플레이테스트 전에 제작자가 알고 있는 기능 오류를 제거합니다. 테스터가 버그를 통과하느라 UI와 사운드를 경험하지 못하면 원하는 질문에 답할 수 없습니다.

목표 / Win완료 상태, 결과 패널과 다음 행동끝맺음이 분명한 완료음 1회소리 없이 성공·재시작을 이해전체 루프에서 1회
범위 축소 질문

세 사건을 모두 새로 디자인하지 않습니다. 이미 작동하는 신호를 빠르게 확인하고, 이번 플레이테스트의 학습 질문과 가장 가까운 사건 하나에만 주의를 집중합니다.

목표는 같고 도구 경로는 선택합니다

어떤 경로를 선택해도 세 명의 실제 관찰, 사람의 수정 판단, v1 build와 같은 여덟 테스트를 제출합니다.

ROUTE A / MANUAL

Unity와 수작업만 사용

기본 UI Component, 사용 허가된 기존 효과음 또는 수업용 placeholder를 사용합니다. 기록에는 AI 미사용과 직접 수정한 항목을 씁니다.

ROUTE B / GENERATOR

Sound·UI 후보만 생성

필요한 짧은 효과음 또는 UI placeholder 후보를 만들고 trim·음량·가독성을 사람이 판단합니다. tool·prompt·출처와 최종 사용 여부를 남깁니다.

ROUTE C / ASSISTED FIX

Ask·Plan 뒤 제한 수정

익명 관찰을 Ask로 구분하고 Plan으로 작은 수정 범위를 확인합니다. Agent는 승인된 Script 한 건만 선택적으로 사용하며 diff와 회귀 검사를 남깁니다.

ROUTE D / ACCESS FALLBACK

계정 없이 같은 목표

생성 기능과 인터넷을 사용할 수 없으면 기존 에셋과 직접 편집으로 즉시 전환합니다. 유료 가입과 trial은 완료 조건이 아닙니다.

COMMON CONTRACT

세 경로 모두 같은 Alpha v0, 소개 문장, 2분 과제와 사후 질문, 실제 테스터 A·B·C, 선택 근거가 있는 문제 하나, 사람이 확인한 수정, 독립 실행 v1 build, 8 / 8 PASS를 제출합니다.

클릭 순서 대신 중간 도착점을 확인합니다

각 구간의 시간이 끝나면 완성도를 더 올리지 말고 증거를 저장한 뒤 다음 구간으로 이동합니다.

00-60 min

Alpha evidence sprint

Individual goal-directed lab

  1. 00-06
    v0 preflight

    build를 실행해 한 판을 완료하고 version, 시작 시각과 before 화면을 저장합니다. 실패하면 가장 최근 작동 copy로 즉시 돌아갑니다.

  2. 06-12
    피드백 사전 검사

    세 핵심 사건의 시각·청각 신호와 음소거 대체 신호를 확인하고 학습 질문 하나를 씁니다.

  3. 12-15
    v0 freeze와 자리 배정

    4인 검사 묶음의 A·B·C·D 역할표를 확인하고 모든 프로젝트의 수정을 멈춥니다.

  4. 15-30
    여섯 번의 2분 30초 순환

    각 학생은 작성자로서 세 번 관찰하고, 테스터로서 다른 세 build를 실행합니다. 매 회차 과제·시간·질문을 동일하게 유지합니다.

  5. 30-38
    관찰 정리와 한 문제 선택

    원문을 보존한 채 사실·해석·해결 후보를 나누고 영향·빈도·수정 위험으로 한 문제를 승인합니다.

  6. 38-50
    최소 수정

    새 mechanic 없이 UI, Audio, 수치 또는 Script 중 가장 작은 범위만 바꾸고 변경 파일을 기록합니다.

  7. 50-57
    v1 재검사와 회귀

    원 테스터 한 명이 같은 과제를 다시 수행하고, 작성자는 기존 핵심 루프를 v1 build에서 검사합니다.

  8. 57-60
    증거 저장

    CSV를 내려받고 after 화면, Alpha v1 build와 Markdown 기록을 제출 구조에 넣습니다.

INTRO / READ VERBATIM

지금은 여러분의 게임 실력을 평가하지 않고 이 게임의 안내를 검사합니다. 이름은 적지 않으며 화면과 음성을 녹화하지 않습니다. 설명 없이 게임을 시작해 목표를 찾아 한 판을 끝내고, 가능하면 다시 시작해 주세요. 생각나는 것을 말해도 좋지만 말하지 않아도 괜찮습니다.

  1. 01

    설명 없이 2분 관찰합니다

    조작법과 정답을 말하지 않습니다. 30초 이상 완전히 막히면 시간과 행동을 먼저 적고 “화면에서 지금 할 수 있는 것을 하나 찾아보세요”라는 중립 문장만 한 번 사용합니다.

    기록 도움 제공 여부와 제공 시각을 막힌 지점 열에 함께 씁니다.

  2. 02

    같은 세 질문을 묻습니다

    “목표가 무엇이라고 생각했나요?”, “어디에서 가장 확신이 없었나요?”, “어떤 화면 변화나 소리가 결과를 알려 주었나요?”를 순서대로 묻습니다.

    기록 해명하거나 반박하지 않고 핵심 응답을 짧게 옮깁니다.

  3. 03

    기록 후 즉시 reset합니다

    build를 종료하고 저장 데이터가 다음 테스터에게 영향을 주지 않도록 동일한 초기 상태로 되돌립니다.

    기록 세션 사이에 v0 파일과 설정이 바뀌지 않았음을 확인합니다.

세션이 끝난 직후 사실을 한 행에 남깁니다

테스터는 이름 대신 A·B·C로 구분하고, CSV를 내려받기 전 각 행이 실제 관찰인지 다시 확인합니다.

이름과 학번은 저장하지 않습니다. 두 값은 CSV 파일명과 내보내기에만 사용합니다. 테스트 판정·익명 관찰·결정 기록과 제출 체크만 이 브라우저에 저장됩니다.

OBSERVATION RULE

“재미없어 했다”, “UI를 이해 못했다”처럼 마음을 추정하지 않습니다. “결과 패널을 닫으려 세 번 클릭했고 재시작 버튼은 누르지 않았다”처럼 다시 볼 수 있는 행동을 씁니다.

원문을 지우지 않고 한 문제만 승인합니다

FAIL이 나오면 가장 가까운 층부터 되돌아갑니다

전체를 다시 만들지 않습니다. 증상과 가까운 사건·표현·호출·layout·build 층을 확인하고 같은 테스트만 다시 실행합니다.

관찰 문장→재현 조건→가장 가까운 원인→한 가지 수정→같은 테스트
세 테스터의 조건이 달라 비교할 수 없습니다

다른 설명을 들은 세션은 별도로 표시하고 비교 근거에서 제외합니다. v0를 복구한 뒤 같은 소개 문장·과제·시간으로 필요한 세션만 다시 진행합니다.

세 사람이 서로 다른 문제를 말했습니다

말보다 진행 영향과 실제 행동을 봅니다. 한 명에게만 나타난 crash나 진행 불가가 있으면 먼저 처리하고, 모두 완료했다면 P1·P2 중 이번 질문과 가장 가까운 하나를 선택합니다.

수정하다 새로운 기능까지 만들고 있습니다

v0 copy로 돌아가 선택 문제와 직접 연결되지 않은 변경을 제외합니다. 12분 안에 build와 재검사를 끝낼 수 없는 수정은 Week 14 backlog로 옮깁니다.

효과음이 여러 번 겹쳐 찢어집니다

AudioClip을 낮추기 전에 사건 호출 횟수를 확인합니다. Trigger 체류나 Update마다 PlayOneShot이 호출되지 않는지 보고 사건당 한 번만 실행되게 고칩니다.

4:3에서 결과 버튼이 화면 밖으로 나갑니다

Button 위치를 숫자로 밀기 전에 Anchor, Canvas Scaler, layout group과 부모 RectTransform을 확인합니다. 16:9를 고친 뒤 4:3이 다시 깨지지 않는지 왕복 검사합니다.

v1이 Editor에서는 되지만 build에서 실패합니다

Build Profile의 Scene 목록, 저장되지 않은 변경, 파일명 대소문자와 외부 절대 경로를 확인합니다. 제출 폴더가 아닌 새 위치에서 다시 실행해 독립성을 확인합니다.

AI는 보조 경로이며 실제 테스터를 대신하지 않습니다

AI 사용 여부와 관계없이 관찰 원문, 학생의 선택과 사람의 build 검증이 제출의 중심입니다.
