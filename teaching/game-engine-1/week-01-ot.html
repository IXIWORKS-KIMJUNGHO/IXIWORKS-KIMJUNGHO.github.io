게임과 게임 엔진은 다릅니다

게임은 플레이어가 경험하는 규칙과 피드백의 체계입니다. 게임 엔진은 그 체계를 만들고 실행하는 공통 도구입니다.

게임

플레이어의 행동, 목표, 규칙, 상태 변화와 피드백이 연결된 경험입니다.

예: 이동한다 → 수집한다 → 점수가 오른다
→ 목표를 달성한다

게임 엔진

화면, 입력, 물리, 사운드, UI, 코드와 빌드를 한 프로젝트 안에서 연결하는 제작 환경입니다.

Unity는 엔진과 Editor, 패키지, 빌드 도구를 함께 제공합니다.

게임은 입력·판단·피드백의 반복으로 작동합니다

파이썬이나 HTML로도 게임을 만들 수 있습니다

구독형 AI에게 파이썬이나 HTML canvas로 짧은 게임을 만들어 달라고 하면, 입력과 점수가 있는 화면이 나옵니다. 그러면 게임 엔진을 왜 배워야 하는지 의문이 들 수 있습니다. 타당한 질문입니다.

그 파일이 게임처럼 보여도 충돌, 중력, 입력, 화면, 소리는 그 코드가 처음부터 다시 만든 기능입니다. Unity에서는 같은 기능이 이미 Component로 들어 있습니다. 캐릭터 GameObject에 물리와 그림을 붙이면 벽 충돌과 화면 표시를 다시 짤 필요가 없습니다.

바이브코딩이 잘하는 일

아이디어를 실행 가능한 한 파일로 빠르게 확인합니다. 키 입력, 좌표 이동, 충돌 비교, 점수 그리기를 그 파일이 모두 담당합니다.

대화형 AI가 만든 코드는 기능을 추가하거나 수정할 때 기존 연결이 깨지기 쉽습니다.

게임 엔진이 맡는 일

Physics 2D, Sprite, Audio, UI, Build가 이미 구현되어 있습니다. GameObject에 Component를 붙이면 충돌, 움직임, 그림, 소리가 한 프로젝트 안에서 같이 돌아갑니다.

AI가 만든 후보를 적용한 뒤, 무엇이 바뀌었는지 엔진 안에서 검증합니다.

Build Profiles

엔진을 배우는 이유는 코드를 더 많이 외우기 위해서가 아닙니다. 이미 있는 물리와 Component를 연결해 게임의 반복 구조를 안정적으로 유지하기 위해서입니다. 충돌 판정과 재시작이 매번 같은 방식으로 작동합니다. 같은 빌드를 다른 기기에서도 실행할 수 있어야 합니다.

2026년에 Unity를 쓰는 이유

Unity 2026 개발 보고서에 따르면, 많은 스튜디오가 더 작은 프로젝트를 우선하고, 프로토타입도 짧은 기간 안에 제작합니다. 이 수업에서 만드는 3-5분짜리 2D 게임도 같은 방향입니다.

규모

작은 프로젝트에 집중합니다

Unity 2026 개발 보고서에서 응답자의 52%가 더 작은 프로젝트를 우선합니다. 67%가 프로토타입에 3개월 이하를 씁니다. 기능을 많이 쌓는 학기가 아닙니다.

2D

2D 도구를 한 환경에서 제공합니다

Sprite, Tilemap, Physics 2D, 애니메이션, UI를 하나의 Editor에서 함께 사용할 수 있습니다. 화면과 기능을 HTML canvas에 매번 다시 구현할 필요가 없습니다.

플랫폼

한 프로젝트에서 여러 기기로 빌드합니다

파이썬이나 HTML 파일은 그 환경에서만 실행됩니다. Unity는 같은 프로젝트에서 Build Profile을 바꿉니다. Windows, macOS, Android, iOS, Web용 빌드를 만듭니다. 게임을 플랫폼마다 다시 짜지 않습니다. 이 학기는 데스크톱 빌드까지입니다.

인디

작은 팀이 쓰는 엔진입니다

Unity 2026 개발 보고서는 소규모 팀의 짧은 게임이 성과를 낸다고 적습니다. 취미와 소규모 인디 팀은 Unity Personal을 무료로 쓸 수 있습니다. 조건은 최근 12개월 매출과 자금이 20만 달러 미만입니다. 이 학기가 만드는 짧은 2D도 그 규모입니다.

AI

AI는 엔진을 대신하지 않습니다

구독형 AI와 Unity Assistant는 코드와 에셋 후보를 제안합니다. 학생은 후보를 검토해 Unity 프로젝트에 적용하고, CLI로 프로젝트 상태와 빌드를 확인합니다. 이 수업에서는 먼저 회색 기능을 만들어 동작을 검증합니다.

Made with Unity

Unity 공식 채널이 엔진으로 만든 게임을 보여 줍니다. 학기의 3-5분 한 판과 규모는 다릅니다.

이번 학기의 핵심 질문

파이썬 파일이 한 번 실행되는지보다 입력, 규칙, 상태, 피드백이 한 Unity 프로젝트 안에서 어떻게 연결되는지를 설명할 수 있어야 합니다.

CLI가 하는 일

설치, 로그인, 지정 버전, 프로젝트 열기, 상태 확인, 빌드. 1주차부터 같은 명령을 반복합니다.

CLI가 하지 않는 일

게임을 대신 만들지 않습니다. CLI는 손이고, 구독형 AI와 Unity AI는 후보를 만듭니다. 결과는 학생이 선택하고 검증합니다.

2-7주

회색 게임을 만듭니다

Scene, GameObject, Component, C#, 입력, 2D 물리, Tilemap, 애니메이션, UI와 Audio를 직접 연결합니다. unity open으로 프로젝트를 엽니다. 구독형 AI는 설명과 초안에 쓸 수 있고, 동작은 학생이 검증합니다.

8주

기초 이해를 확인합니다

중간고사로 Unity 구조와 핵심 기능, 회색 게임이 어떻게 작동하는지 확인합니다.

9-13주

그림과 소리를 붙입니다

Sprite와 사운드 후보, Ask, Plan, Agent와 MCP를 선택, 검토, 검증의 순서로 사용합니다. CLI는 1주차부터 쓰던 명령을 이어 갑니다.

14-16주

개인 게임을 완성합니다

두 차례 면담과 플레이테스트를 거쳐 실행 build, project, 영상과 제작 기록을 제출합니다.

Final direction

Unity with AI로 제작하는 2D 게임

Unity와 AI를 함께 사용해 작고 설명 가능한 시스템을 만듭니다. 하나의 핵심 행동이 시작, 플레이, 성공 또는 실패, 재시작으로 이어져야 합니다.

  • 하나의 명확한 핵심 행동과 목표
  • 작은 맵 또는 짧은 한 스테이지
  • UI, 사운드, 애니메이션 피드백
  • 플레이테스트와 수정 전후의 증거
  • 설명할 수 있는 Scene과 Script 구조
  • AI 사용 여부와 선택 근거 기록

수업 운영

매주 3시간, 3교시로 운영합니다. 1·2교시는 이론, 3교시는 실습입니다.

1교시와 2교시는 각각 45분 이론 강의 뒤 15분 휴식입니다. 3교시는 목표지향 개인 실습입니다. 매주 새 기능을 많이 보는 것보다, 작은 기능을 직접 만들고 결과를 확인하는 리듬을 유지합니다.

1교시 · 이론 45분 강의, 15분 휴식

새 개념, 게임 디자인 원리와 이번 주의 완료 기준을 확인합니다.

2교시 · 이론 45분 강의, 15분 휴식

시연을 보고 구조를 따라 읽습니다. 이 교시에는 프로젝트를 따라 만들지 않습니다.

3교시 · 실습 목표지향 개인 실습

통과 기준을 보고 직접 만들고, Console·Inspector·Play Mode에서 검증합니다. 작업 속도는 평가하지 않습니다.

학습 평가

평가 비율은 강의계획서와 같습니다. 이 수업에서 중간시험과 기말시험은 지필 시험이 아니라 프로젝트로 진행합니다. 출결 세부 기준과 제출기한은 LMS 공지를 따릅니다.

Unity CLI는 Hub와 별도로 설치하는 독립 실행 파일입니다. Editor와 모듈을 터미널에서 관리합니다. Hub를 설치해도 unity 명령이 생기지 않습니다. 설치 방법과 명령은 Unity CLI 공식 소개 ↗와 공식 사용 안내 ↗를 따릅니다. 오늘은 설치, 로그인, 라이선스, 지정 버전 확인까지만 합니다. Editor를 제어하는 Unity Pipeline package, MCP, 프로젝트 생성은 다루지 않습니다.

버전 원칙

“Unity 6” 또는 “최신 버전”만 보고 설치하지 않습니다. 반드시 교수자가 공지한 전체 버전 번호가 6000.3.xf1 형식으로 일치해야 합니다. 학기 중 임의 업그레이드도 하지 않습니다. 명령의 정확한 플래그는 수업 당일 unity --help가 기준입니다.

설치 전 점검

하나라도 준비되지 않았다면 다운로드를 시작하기 전에 교수자에게 알립니다.

  • 지원 운영체제Windows 10 21H1 이상 또는 Windows 11, macOS 14 이상(Unity CLI 기준)
  • 메모리Unity 공식 권장 최소 8GB RAM
  • 저장 공간Editor를 설치할 로컬 디스크에 충분한 여유 공간
  • 네트워크대용량 파일을 받을 수 있는 안정적인 연결
  • 계정과 권한Unity ID 로그인과 앱 설치 권한

운영체제와 메모리 기준은 Unity 6 시스템 요구 사항 ↗, Unity Hub 설치 안내 ↗, Unity CLI 호환성 안내 ↗를 기준으로 합니다.

설치 완료 상태0 / 7 완료

체크 상태는 이 브라우저에만 저장됩니다. 계정 정보나 기기 정보는 저장하지 않습니다.

  1. Unity 다운로드 페이지 ↗에서 자신의 운영체제용 Hub 안정 버전을 설치합니다. Windows는 .exe, macOS는 .dmg 파일을 사용합니다. Hub는 라이선스와 Editor 화면의 입구입니다. CLI는 다음 단계에서 따로 설치합니다.

    • 공식 Unity 도메인에서 받은 설치 파일인지 확인합니다.
    • Beta 채널이 아닌 일반 안정 버전 Hub를 사용합니다.

  2. Unity CLI는 Hub와 다른 독립 실행 파일입니다. 터미널에서 공식 설치 스크립트를 실행합니다. 현재 스크립트는 UNITY_CLI_CHANNEL=beta 채널을 사용합니다.

    macOS · Linuxcurl -fsSL https://public-cdn.cloud.unity3d.com/hub/prod/cli/install.sh | UNITY_CLI_CHANNEL=beta bash
    Windows · PowerShell$env:UNITY_CLI_CHANNEL='beta'; irm https://public-cdn.cloud.unity3d.com/hub/prod/cli/install.ps1 | iex
    • 설치 후 터미널을 완전히 닫았다가 다시 엽니다.
    • unity --version으로 CLI 버전을 확인합니다.
    • unity --help에서 명령 목록을 확인합니다. 이 출력이 플래그의 최종 기준입니다.
    • unity doctor로 실행 환경을 확인합니다.
    패키지 관리자로 설치할 때

    공식 문서가 허용하는 다른 경로입니다. 스크립트 대신 사용할 수 있습니다.

    Windows · wingetwinget install Unity.CLI
    macOS · Homebrewbrew install --cask unity-cli

    Linux 패키지와 자세한 절차는 공식 설치 절차 ↗에서 확인합니다.

  3. Hub 로그인과 터미널의 unity auth login을 모두 완료합니다. 계정이 없다면 개인이 계속 사용할 이메일로 Unity ID를 만듭니다.

    • 공용 PC에서는 비밀번호 자동 저장을 선택하지 않습니다.
    • 다른 학생의 계정이나 인증 코드를 공유하지 않습니다.
    • unity auth status에 자신의 계정이 보이는지 확인합니다.

  4. Hub의 Licenses와 터미널의 unity license를 함께 확인합니다. Unity Personal은 로그인하면 일반적으로 자동 활성화됩니다.

    라이선스가 보이지 않을 때

    Licenses → Add license → Get a free personal license를 선택하고 약관을 확인합니다. 학교에서 별도 seat를 제공한 경우에는 교수자의 안내를 따릅니다.

  5. 터미널에서 unity install <공지된 전체 버전>을 실행합니다. 설치가 끝나면 Hub의 Official releases 및 Installs 목록과 교차 확인합니다. latest나 lts 별칭은 공지 버전과 달라질 수 있으므로 사용하지 않습니다.

    목록에 정확한 버전이 없을 때

    Unity download archive ↗에서 해당 버전의 Hub installation 링크를 사용합니다. 비슷한 버전을 대신 설치하지 않습니다.

  6. Editor 본체는 필수입니다. 플랫폼 Build Support, 언어 팩과 추가 개발 도구는 교수자가 별도로 지정하지 않았다면 오늘 설치하지 않아도 됩니다. 선택을 확인한 뒤 Install을 눌러 Editor 다운로드를 시작합니다.

    • 선택 모듈은 나중에 Installs → Manage → Add modules에서 추가할 수 있습니다.
    • CLI에서는 unity install-modules -e <버전> -m <모듈 ID>로 모듈을 추가할 수 있지만, 오늘은 교수자가 지정한 모듈만 설치합니다.
    • 강의 화면과 메뉴 이름을 맞추기 위해 Editor 기본 언어는 영어 사용을 권장합니다.
    • 모듈을 많이 선택해 설치 시간을 불필요하게 늘리지 않습니다.
Editor 다운로드 중

다운로드를 기다리며 AI 사용 원칙을 확인합니다

Hub의 Downloads에서 진행 상태를 확인한 다음, 다운로드가 이어지는 동안 아래 내용을 함께 살펴봅니다.

AI 사용량은 점수가 아닙니다. 구독형 AI와 Unity AI를 사용하되, 학생이 결과를 선택, 수정, 검증하고 설명해야 합니다.

주차 구간별 AI 사용 범위
구간허용 범위학생이 해야 할 일
1주차생성형 AI로 제작하지 않음. 종이로 구독형 AI 현황만 파악수업 정책을 확인하고 Unity CLI로 설치만 완료합니다.
2-7주구독형 AI로 설명, 오류 해석, 코드 초안. CLI로 프로젝트 열고 상태 확인핵심 구조와 기능을 이해하고 설명합니다. Play Mode에서 직접 검증합니다.
9-10주아이디어와 Sprite, UI, Sound 후보 탐색출처, prompt, 선택 이유와 직접 수정한 부분을 기록합니다.
11-13주Ask → Plan → Agent 또는 MCP변경 범위를 먼저 정하고 Console, Inspector와 Play Mode에서 검증합니다.
14-16주프로젝트 목적에 필요한 범위핵심 Script와 Scene 구조, 생성 에셋의 권리와 선택을 구술 설명합니다.

개인정보를 넣지 않습니다

이름, 연락처, 얼굴, 음성, 학생 명단과 평가 자료를 AI prompt나 reference로 업로드하지 않습니다.

권리를 먼저 확인합니다

직접 만든 자료 또는 AI 입력이 허용된 자료만 사용합니다. Asset Store 에셋을 외부 생성 AI에 업로드하지 않습니다.

비밀값을 저장하지 않습니다

API key, access token, 계정 정보는 Script, Scene, Prefab, 제작 로그와 저장소에 넣지 않습니다.

모든 결과를 검증합니다

AI가 만든 코드와 에셋은 오류 가능성이 있습니다. 작동과 권리를 확인하지 않은 결과는 제출물로 인정하지 않습니다.

접근성 원칙

Unity의 AI 기능은 베타이며 계정, Cloud 연결, 패키지와 이용 조건이 필요합니다. 특정 유료 기능은 필수가 아니며, AI를 사용하지 않아도 같은 학습 성과와 제작 증거를 제시하면 동일하게 평가합니다.

  1. Hub Downloads가 Completed인지 확인한 뒤, unity editors -i --format json과 Hub Installs 카드의 전체 버전 번호를 공지 화면과 비교합니다.

    설치 완료 기준
    1. Hub가 오류 없이 실행됩니다.
    2. 자신의 Unity ID로 로그인되어 있습니다.
    3. Licenses에 활성 라이선스가 보입니다.
    4. Installs에 지정된 6000.3.xf1이 보입니다.
    5. Downloads에 진행 중이거나 실패한 항목이 없습니다.
    6. unity --version이 설치된 CLI 버전을 출력합니다.
    7. 터미널에서 unity --help가 열립니다.
    8. unity doctor가 진단 결과를 출력합니다.
    9. unity auth status에 자신의 계정이 보입니다.
    10. unity editors -i --format json에 지정 버전이 있습니다.
여기에서 멈춥니다 Projects → New project를 누르지 않습니다

설치가 끝나면 Hub의 Installs 화면과 전체 버전 번호를 교수자에게 확인받습니다. 첫 프로젝트는 다음 수업에서 같은 절차로 함께 만듭니다.

설치가 멈췄을 때

반복해서 버튼을 누르기 전에 증상을 한 문장으로 기록하고 아래 순서대로 확인합니다.

터미널에서 unity 명령을 찾지 못합니다

CLI 설치 스크립트를 다시 실행하고 터미널을 완전히 닫았다가 다시 엽니다. 그래도 찾지 못하면 설치 디렉터리가 PATH에 포함됐는지 확인합니다. Linux 설치 스크립트의 기본 위치는 ~/.local/bin/unity입니다.

Hub 설치 파일이 열리지 않습니다

운영체제 버전과 관리자 권한을 확인합니다. Windows는 64-bit Windows 10 21H1 이상, macOS는 12 이상이 Hub의 현재 지원 기준입니다. 보안 경고가 표시되면 파일 출처가 Unity 공식 도메인인지 먼저 확인합니다.

브라우저 로그인 후 Hub로 돌아오지 않습니다

Hub를 완전히 종료한 뒤 다시 열고 로그인합니다. 브라우저의 팝업 또는 외부 앱 열기 차단 여부를 확인하고, VPN이나 학교 네트워크의 인증 페이지가 연결을 막고 있는지도 확인합니다.

Unity Personal 라이선스가 보이지 않습니다

Licenses → Refresh를 먼저 선택합니다. 계속 보이지 않으면 Add license → Get a free personal license로 진행합니다. 학교 계정 seat를 사용하는 경우 개인 라이선스를 추가하지 말고 교수자에게 문의합니다.

Unity 6.3 LTS가 목록에 없습니다

Hub를 최신 안정 버전으로 업데이트한 뒤 다시 확인합니다. 그래도 없다면 공식 download archive ↗에서 공지된 정확한 버전의 Hub installation 링크를 사용합니다.

다운로드가 오래 멈춰 있습니다

Downloads 패널을 열어 어떤 항목에서 멈췄는지 확인합니다. 저장 공간과 네트워크 연결을 점검하고, 상대 경로 형식의 네트워크 드라이브나 심볼릭 링크를 설치 위치로 사용하지 않습니다.

설치가 오늘 안에 끝나지 않습니다

실패 지점, 표시된 오류 문구, 선택한 전체 버전을 기록합니다. 임의의 다른 버전을 설치하지 말고, 교수자 확인 후 다음 수업 전까지 지정 버전 설치를 완료합니다.

문제 기록 형식

내 운영체제 / 설치하려는 전체 버전 / 멈춘 단계 / 화면의 정확한 오류 문구 / 이미 시도한 조치

“안 돼요”보다 “macOS 14, 6000.3.xf1 설치 63%에서 10분간 멈춤, Hub 재실행 후 동일”처럼 기록하면 해결이 빨라집니다.
