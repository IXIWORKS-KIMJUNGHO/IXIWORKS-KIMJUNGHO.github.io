첫 연결은 client를 확인하고 명시적으로 승인합니다

Unity MCP Server의 Bridge가 실행 중이어도 새로운 외부 client는 승인 전까지 도구를 사용할 수 없습니다. 승인 뒤에는 자동 재연결될 수 있으므로 수업 종료 때 revoke가 필요합니다.

  1. 01 / BRIDGEUnity Bridge Running

    Project Settings의 AI → Unity MCP Server에서 Bridge 상태를 확인합니다.

  2. 02 / IDENTITYclient 확인

    Pending Connection의 client 이름과 자신이 시작한 연결인지 확인합니다. 모르는 client는 승인하지 않습니다.

  3. 03 / ALLOW연결만 승인

    Allow Access는 Bridge 연결 승인입니다. Scene 쓰기와 삭제 권한을 포괄 승인한 것이 아닙니다.

  4. 04 / TOOLStool 목록 확인

    Unity_ReadConsole, Scene·GameObject 관리 tool 등 실제 연결된 목록을 읽습니다.

  5. 05 / REVOKE종료 때 해제

    시연이 끝나면 access를 revoke하고 공용 컴퓨터의 외부 client와 provider session을 종료합니다.

relay 경로

Unity의 relay 설정은 사용자 폴더 아래 ~/.unity/relay/를 사용합니다. 일부 client 설정에서는 ~가 확장되지 않을 수 있으므로 실제 absolute path를 확인합니다. 이 경로와 자격 증명 값을 학생 화면에 무분별하게 공유하지 않습니다.

3교시 전에 복원할 네 가지

답을 먼저 말하고 펼쳐 확인합니다. 순서를 잊었다면 쓰기를 실행하지 않고 baseline으로 돌아갑니다.

Q1. 첫 MCP 요청이 Console 읽기인 이유는 무엇인가?

프로젝트를 바꾸지 않으면서 연결된 tool, 대상 범위와 응답의 정확성을 수동 Console과 비교할 수 있기 때문입니다. 안전한 읽기에서 신뢰도를 먼저 확인합니다.

Q2. AutomationProbe를 0 → 1로 바꾸기 전에 무엇이 모두 일치해야 하는가?

정확히 하나인 target, Inspector와 MCP read의 X=0, Scene·Play Mode·Console baseline, 허용 property, 예상 diff와 rollback 계획이 모두 일치해야 합니다.

Q3. success: true가 수업 PASS가 아닌 이유는 무엇인가?

그 값은 CLI 명령이 성공했다고 보고할 뿐, 의도한 project를 대상으로 했는지, 실제 Unity 상태가 맞는지, 다른 변경이나 오류가 없는지까지 증명하지 않습니다.

Q4. 연결되지 않는 학생은 무엇을 똑같이 증명하는가?

제공 fixture의 상태·출력을 판독하고 수동 Unity 화면에서 baseline, read result, 한 값의 변경과 rollback을 같은 표로 증명합니다. 평가 결과는 연결 경로와 무관합니다.

학생은 같은 보고서를 서로 다른 경로로 완성합니다
