모든 GameObject는 장소와 방향과 크기를 가집니다

Transform은 GameObject가 Scene 안에서 어디에 있고, 어느 방향을 향하며, 얼마나 큰지를 저장합니다. 모든 GameObject에 반드시 존재하는 기본 Component입니다.

교수자 설명 문장

Position은 주소, Rotation은 방향, Scale은 원래 크기에 곱하는 배율입니다.

2D 장면에서 읽는 Transform의 핵심 값
항목2D에서의 의미이번 주 기준먼저 확인할 문제
Position X화면의 좌우 위치오른쪽은 양수, 왼쪽은 음수대상이 화면 좌우 어디에 있는가?
Position Y화면의 위아래 위치위쪽은 양수, 아래쪽은 음수카메라 촬영 범위 안에 있는가?
Position Z3D 공간의 깊이 위치모든 Sprite를 0에 둠Sprite 순서를 Z로 임시 해결하지 않았는가?
Rotation Z평면에서 도는 각도0에서 시작원하지 않게 기울어졌는가?
Scale X, Y가로와 세로 배율처음은 1, 1음수 또는 지나친 값이 들어갔는가?
판서 핵심 2D에서도 Transform은 X, Y, Z를 모두 가집니다. 이번 장면은 Z를 0으로 두고 보이는 앞뒤 순서는 Sprite Renderer에서 정합니다.

  1. Player의 X만 바꿉니다

    Inspector에서 Position X를 0, 2, -2로 바꾸며 좌우 이동을 확인합니다.

    예측 질문Y와 Scale은 바뀌지 않았을 때 화면에서 무엇만 달라질까요?

  2. Rotation Z만 바꿉니다

    0에서 45로 바꾸고 평면에서 회전하는 축이 Z라는 사실을 연결합니다.

    관찰점2D 화면은 X와 Y 평면이고 그 평면을 관통하는 축을 중심으로 돕니다.

  3. Scale을 원래 값으로 되돌립니다

    X와 Y를 함께 1로 맞춘 뒤 Reset의 의미가 임의의 기본값이 아니라 Component의 초기값이라는 점을 설명합니다.

    관찰점문제가 생기면 한 값씩 바꾸고 바로 되돌려 원인을 분리합니다.

크기를 0으로 만들면 삭제된 것이 아닙니다

Scale이 0이면 대상은 Hierarchy에 남아 있지만 화면에서 보이지 않습니다. 보이지 않는 Sprite를 찾을 때는 활성 상태, 카메라 범위, Sprite Renderer와 함께 Transform Scale을 확인합니다.

부모와 자식은 이동의 기준을 공유합니다

Hierarchy에서 자식으로 묶는 것은 보기 좋게 정리하는 것에 그치지 않습니다. 자식의 Transform은 부모를 기준으로 해석되고, 부모가 움직이거나 돌거나 커지면 자식도 함께 영향을 받습니다.

장면 전체를 기준으로 한 위치

Scene의 원점에서 GameObject가 실제로 어디에 있는지 나타냅니다. 부모가 움직이면 자식의 world 위치도 달라집니다.

Local position

부모를 기준으로 한 상대 위치

Inspector에 보이는 자식의 Position입니다. (0.65, 0, 0)은 부모 중심에서 오른쪽으로 0.65만큼 떨어졌다는 뜻입니다.

설명 비유

기차 안에서 내 자리는 객차를 기준으로 그대로지만, 기차가 이동하면 지도 위의 내 위치도 함께 바뀝니다. local 위치와 world 위치의 차이가 이와 같습니다.

  1. DirectionMarker를 Player의 자식으로 둡니다

    Hierarchy에서 Marker를 Player 위로 드래그해 들여쓰기된 구조를 만듭니다. Marker의 local Position을 (0.65, 0, 0)으로 둡니다.

    관찰점Hierarchy의 들여쓰기는 Transform 관계를 나타냅니다.

  2. Player만 이동합니다

    Player의 Position X를 바꾸고 Marker가 같은 간격을 유지한 채 따라오는지 확인합니다.

    예측 질문Marker의 local Position 값은 바뀔까요, 그대로일까요?

  3. Player만 회전합니다

    Player의 Rotation Z를 바꾸어 Marker가 Player 중심을 기준으로 함께 도는 것을 보여 줍니다.

    관찰점자식은 부모의 이동뿐 아니라 회전과 크기에도 영향을 받습니다.

  4. Marker의 local 위치만 바꿉니다

    Player는 그대로 두고 Marker의 값을 바꾸어 자식은 부모 안에서 독립적인 상대 위치도 가질 수 있음을 설명합니다.

    관찰점함께 움직인다는 말이 두 대상의 Transform 값이 같다는 뜻은 아닙니다.
판서 핵심 부모는 자식의 좌표 기준입니다. 자식의 Inspector Position은 부모로부터 떨어진 상대 위치입니다.

부모와 자식은 의미가 있는 움직임 단위로 묶습니다

Player와 방향 표시는 함께 움직여야 하므로 좋은 관계입니다. 단지 Hierarchy를 짧게 보이게 하려고 관련 없는 오브젝트를 부모와 자식으로 묶으면 예상하지 못한 이동과 크기 변화가 생깁니다.

2D의 앞뒤는 그리는 순서로 정합니다

Sprite Renderer는 어떤 Sprite를 그릴지뿐 아니라 언제 그릴지도 정합니다. 나중에 그려진 Sprite가 앞에 보이므로 큰 범주와 같은 범주 안의 순서를 나누어 설정합니다.

Background먼저 그리는 바탕
Actors그 위에 놓이는 Player와 Collectible
Foreground마지막에 그려 장면 앞을 가리는 요소
Sorting Layer

큰 범주의 순서

Background, Actors, Foreground처럼 역할이 다른 묶음 사이의 우선순위를 정합니다.

Order in Layer

같은 Layer 안의 세부 순서

같은 Sorting Layer라면 숫자가 큰 Sprite가 나중에 그려져 앞에 보입니다. Player가 0이면 Marker는 1로 둡니다.

  1. 모든 Sprite의 Z를 0으로 맞춥니다

    깊이 값을 섞지 않고 Sprite Renderer의 정렬 설정만으로 결과를 비교할 준비를 합니다.

    관찰점이번 수업의 변수는 정렬 설정 하나로 제한합니다.

  2. Background를 잘못된 Layer로 바꿉니다

    배경이 Player를 가리는 실패를 일부러 만들고 원인을 학생에게 묻습니다.

    예측 질문Z를 옮기지 않고 어느 Component의 어떤 값을 고쳐야 할까요?

  3. Marker의 Order를 바꿉니다

    1과 -1을 비교해 같은 Actors Layer 안의 세부 순서를 보여 줍니다.

    관찰점큰 범주는 Layer, 같은 범주의 세부 순서는 Order입니다.

Z Position으로 가림 문제를 숨기지 않습니다

2D Sprite의 역할이 배경, 캐릭터, 전경으로 분명할 때는 Sorting Layer와 Order in Layer를 사용합니다. Z를 임의로 흩어 놓으면 장면 구조를 설명하고 수정하기 어려워집니다.

Prefab은 복제본이 아니라 연결된 원본입니다

같은 구조를 여러 번 배치하고 공통 부분을 한 번에 고치려면 원본 Asset이 필요합니다. Prefab Asset은 설계도이고 Scene의 Instance는 그 설계도를 사용한 배치본입니다.

Prefab Asset
Project 창에 저장된 원본입니다. 공통 Sprite, Color, Scale와 자식 구조를 정의할 수 있습니다.
Prefab Instance
Scene에 배치된 사용본입니다. 같은 원본에 연결되면서도 Position처럼 배치마다 달라야 하는 값을 가질 수 있습니다.
Override
특정 Instance에서 원본과 다르게 바꾼 값입니다. 의도한 차이는 유지하고, 실수로 만든 차이는 Revert해 원본 값으로 되돌립니다.
Apply
Instance의 변경을 원본에 반영하는 동작입니다. 다른 Instance에도 영향을 줄 수 있으므로 영향 범위를 알고 사용할 때만 선택합니다.

  1. 일반 Collectible을 만듭니다

    기본 Sprite의 색과 Scale을 정하고 이름을 Collectible로 지정합니다.

    관찰점아직은 Hierarchy에만 있는 일반 GameObject입니다.

  2. Hierarchy에서 Project로 드래그합니다

    Assets/Prefabs 폴더에 놓아 Collectible.prefab Asset을 만듭니다.

    관찰점Project 창에 원본이 생기고 Scene의 대상은 Instance가 됩니다.

  3. Instance를 세 곳에 배치합니다

    Prefab Asset을 Scene으로 더 가져오거나 연결된 Instance를 복제하고 Position만 다르게 둡니다.

    예측 질문원본의 Color를 바꾸면 세 Instance는 어떻게 될까요?

  4. 원본과 Override를 비교합니다

    Prefab Asset의 색을 바꾸어 공통 변경을 확인한 뒤 한 Instance만 색을 바꾸고 Revert합니다.

    관찰점공통값과 개별값을 구분하는 것이 Prefab 사용의 핵심입니다.
설명 비유

일반 Duplicate는 서로 모르는 복사본이고, Prefab Instance는 같은 설계도를 계속 참조하는 제품입니다.

세 개가 똑같이 생겼다고 Prefab인 것은 아닙니다

일반 GameObject를 세 번 Duplicate하면 처음 모습은 같아도 공통 원본이 없습니다. Project 창의 Prefab Asset과 연결된 Instance인지 Hierarchy의 표시와 Inspector의 Prefab 정보를 확인합니다.

네 개념을 하나의 장면으로 연결합니다

Transform, 계층, Sprite 정렬과 Prefab은 서로 경쟁하는 기능이 아닙니다. 각각 공간, 관계, 보이는 순서와 재사용이라는 다른 문제를 해결합니다.

3교시 전에 네 가지를 회수합니다

정답을 열기 전 손을 들거나 옆 학생에게 한 문장으로 설명합니다. 용어만 말하지 않고 결과가 달라지는 이유까지 붙입니다.

Player를 옮길 때 DirectionMarker가 같은 간격으로 따라오는 이유는 무엇인가요?

DirectionMarker가 Player의 자식이고, Inspector의 Position이 Player를 기준으로 한 local 위치이기 때문입니다. 부모가 움직이면 자식의 world 위치도 함께 달라집니다.

Sorting Layer와 Order in Layer는 어떻게 다른가요?

Sorting Layer는 Background, Actors, Foreground처럼 큰 범주의 순서를 정하고, Order in Layer는 같은 Sorting Layer 안에서 숫자로 세부 순서를 정합니다.

일반 Duplicate 세 개와 Prefab Instance 세 개의 차이는 무엇인가요?

Prefab Instance는 Project 창의 하나의 Prefab Asset과 연결되어 공통 변경을 공유합니다. 일반 Duplicate는 서로 연결된 원본이 없으므로 하나를 바꿔도 나머지가 함께 바뀌지 않습니다.

이번 미션에서 모든 Sprite의 Z Position을 0으로 두는 이유는 무엇인가요?

2D의 보이는 순서를 Sprite Renderer의 Sorting Layer와 Order in Layer라는 명시적인 규칙 하나로 관리하기 위해서입니다.
