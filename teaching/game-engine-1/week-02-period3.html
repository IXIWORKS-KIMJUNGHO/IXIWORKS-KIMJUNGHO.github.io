Mission brief

Week02_Playground를 60분 안에 작동 가능한 장면으로 완성합니다

Player와 방향 표시가 하나의 움직임 단위로 묶이고, 배경부터 전경까지 의도한 순서로 보이며, 같은 원본을 사용하는 Collectible 세 개가 배치되어야 합니다. C#과 물리는 아직 사용하지 않습니다.

Output
저장된 Scene과 Prefab Asset
Success
8개 통과 기준과 오류 0개
Freedom
색, 위치, 크기와 장면 구성

완성 이미지는 답안이 아니라 방향입니다

이미지를 그대로 복사할 필요가 없습니다. 필수 구조가 화면에서 읽히고, 자신의 배치 선택을 설명할 수 있다면 색과 구도는 자유롭게 정할 수 있습니다.

  1. 움직임 단위위의 목표 이미지에서 Player와 DirectionMarker가 하나의 방향 단위로 읽히는지 확인합니다.
  2. 재사용의 증거같은 모습의 Collectible 세 개가 서로 떨어져 배치되어 하나의 원본을 반복 사용했음을 보여 줍니다.
  3. 화면 순서Background는 뒤에, Player와 Collectible은 가운데에, ForegroundBush는 앞에 보입니다.
반드시 지킬 것

기술 구조

  • 프로젝트 이름은 GE1_Week02입니다.
  • Scene은 Assets/Scenes/Week02_Playground.unity에 저장합니다.
  • DirectionMarker는 Player의 자식입니다.
  • 세 Collectible은 하나의 Collectible.prefab을 사용합니다.
  • Sprite의 Z Position은 모두 0으로 둡니다.
직접 결정할 것

시각적 선택

  • Player와 Collectible의 색
  • 세 Collectible의 위치와 간격
  • Props의 수, 크기와 배치
  • ForegroundBush가 화면을 가리는 정도
  • 전체 장면의 균형과 시선의 흐름

오늘 추가하지 않는 것

C# Script, Rigidbody2D, Collider2D, 이동 입력, 외부 Asset 다운로드는 이번 미션의 범위가 아닙니다. 먼저 정적인 Scene의 구조, 보이는 순서와 재사용을 정확하게 완성합니다.

Hierarchy가 장면의 의도를 설명해야 합니다

이름과 들여쓰기만 읽어도 무엇이 배경이고, 무엇이 묶여 움직이며, 무엇이 반복 사용되는지 알 수 있어야 합니다.

경로는 자유롭지만 중간 상태는 확인합니다

아래는 클릭 순서가 아니라 시간 관리용 이정표입니다. 각 구간의 확인 상태를 만들 수 있다면 자신에게 편한 순서로 작업해도 됩니다.

  1. 00-10

    파일과 Scene을 준비합니다

    공지된 Editor와 2D 템플릿으로 GE1_Week02를 열고, 필요한 Scenes와 Prefabs 폴더를 준비합니다.

    Checkpoint

    Project 창에 Week02_Playground Scene Asset이 보이고 Scene 이름에 미저장 별표가 없습니다.

  2. 10-24

    읽을 수 있는 Hierarchy를 만듭니다

    필수 GameObject의 이름과 부모, 자식 관계를 구성합니다. 시각적 모양보다 먼저 구조가 설명되는지 봅니다.

    Checkpoint

    Player를 이동했을 때 DirectionMarker가 같은 상대 위치를 유지하며 따라옵니다.

  3. 24-38

    보이는 순서를 설계합니다

    Background, Actors, Foreground Sorting Layer를 사용해 모든 Sprite의 역할을 나눕니다.

    Checkpoint

    배경이 Player를 가리지 않고 Marker는 Player 위에 보이며 ForegroundBush는 앞을 가립니다.

  4. 38-50

    Collectible을 재사용합니다

    하나의 Collectible.prefab과 연결된 세 Instance를 만들고 서로 다른 위치에 배치합니다.

    Checkpoint

    Prefab Asset의 Color를 바꾸었을 때 세 Instance가 모두 함께 바뀝니다.

  5. 50-60

    실행하고 증명합니다

    Play Mode에서 Game 뷰를 확인하고 Console의 빨간 오류를 없앤 뒤 Scene을 다시 저장합니다.

    Checkpoint

    통과 기준 8개를 근거와 함께 확인하고 최종 화면을 캡처할 수 있습니다.

한 번에 여러 값을 바꾸지 않습니다

결과가 예상과 다르면 마지막에 바꾼 한 가지를 되돌리고 다시 관찰합니다. Transform, 부모와 자식, Sorting, Prefab 중 어떤 원리가 문제인지 먼저 분리합니다.

8개 기준을 모두 증명하면 완료입니다

완료의 정의

통과 기준 8개가 모두 확인되고, Console의 빨간 오류가 0개이며, Scene을 저장한 상태에서 두 화면과 설명 한 문장을 준비하면 2주 차 미션 완료입니다.

필요할 때만

막혔을 때만 필요한 힌트를 엽니다

먼저 마지막으로 바꾼 값을 되돌리고, 문제의 대상을 선택해 Inspector를 읽습니다. 그래도 원인을 찾지 못할 때 관련 힌트 하나만 엽니다.

  1. 관찰Scene과 Game 중 어디에서 문제가 보이는지 구분합니다.
  2. 선택문제가 있는 GameObject를 Hierarchy에서 선택합니다.
  3. 분리Transform, 계층, Sorting, Prefab 중 하나만 확인합니다.
  4. 질문시도한 값과 예상, 실제 결과를 함께 말합니다.
Scene을 저장했는데 Project 창에서 찾을 수 없습니다

Project 창의 Assets/Scenes 폴더를 먼저 선택합니다. 현재 Scene의 이름이 Week02_Playground인지 확인하고 Ctrl/Cmd + S를 누릅니다. Scene 탭 이름의 별표가 사라져야 합니다.

Player를 움직여도 DirectionMarker가 따라오지 않습니다

Hierarchy에서 DirectionMarker가 Player 아래에 들여쓰기되어 있는지 확인합니다. 옆에 놓여 있다면 형제 관계이므로 함께 움직이지 않습니다. 자식이라면 Marker의 Inspector Position은 local 값입니다.

Player 또는 Collectible이 Background 뒤에 숨습니다

대상의 Sprite Renderer를 확인합니다. Background는 Background, Player와 Collectible은 Actors Sorting Layer여야 합니다. 모든 Sprite의 Z Position은 0으로 유지합니다.

DirectionMarker가 Player 뒤에 숨습니다

두 대상이 같은 Actors Sorting Layer인지 확인합니다. Player의 Order in Layer가 0이라면 DirectionMarker는 1로 둡니다.

Prefab 원본을 바꿔도 Collectible 하나만 바뀝니다

Project 창의 Collectible.prefab을 선택해 원본을 수정했는지 확인합니다. Hierarchy의 세 대상이 모두 Prefab Instance인지도 봅니다. 특정 Instance에 Color Override가 있다면 Overrides에서 해당 값을 Revert합니다.

Play를 멈추자 방금 바꾼 값이 사라졌습니다

Play Mode에서 바꾼 Scene 값은 테스트가 끝나면 시작 전 상태로 돌아갈 수 있습니다. Play를 멈춘 Edit Mode에서 값을 다시 설정하고 Scene을 저장합니다.

질문을 어떻게 해야 할지 모르겠습니다

대상, 바꾼 값, 예상 결과, 실제 결과를 말합니다. 예: Background의 Sorting Layer를 Background로 설정했지만 Game 뷰에서 Player가 보이지 않고 Console의 빨간 오류는 0개입니다.

선택 확장

8개 기준을 통과한 뒤에만 한 단계 확장합니다

확장은 기본 구조를 대신하지 않습니다. 먼저 완료 상태를 저장하고 캡처한 뒤 아래에서 한 가지만 선택합니다.

Option A

의도적인 Instance Override

Collectible_03의 Scale만 조금 바꾸어 Override 표시를 확인합니다. 차이를 설명한 뒤 Revert해 세 Instance를 다시 공통 원본 상태로 돌립니다.

Option B

전경 겹침 개선

기존 기본 Sprite만 사용해 ForegroundBush의 위치와 Scale을 조절하고 장면의 아래쪽 일부를 자연스럽게 가립니다. 새 Asset은 가져오지 않습니다.

확장 결과도 한 문장으로 설명합니다

무엇을 바꾸었는지보다 왜 그 값을 선택했고 화면에서 무엇이 더 분명해졌는지 말합니다.

미션 중 필요한 공식 참고 문서

힌트로 해결되지 않을 때 관련 개념 하나만 찾아봅니다. 문서를 읽은 뒤에는 자신의 Scene에서 같은 Component와 값을 직접 확인합니다.

  • Transform과 부모, 자식 ↗자식의 local 좌표와 부모 Transform의 영향
  • 2D renderer sorting ↗Sorting Layer와 Order in Layer의 렌더 순서
  • Prefab 생성 ↗GameObject에서 Prefab Asset과 Instance를 만드는 방법
  • 1교시 개념 자료Editor의 창, Project, Scene, GameObject와 Component
  • 2교시 설명 자료Transform, 계층, Sorting과 Prefab 시연
