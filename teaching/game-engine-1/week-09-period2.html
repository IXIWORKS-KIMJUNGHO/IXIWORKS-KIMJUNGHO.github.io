그림 설명보다 플레이 경험을 먼저 한 문장으로 씁니다

캐릭터의 옷부터 정하면 게임의 행동과 감정이 빠집니다. 플레이어가 누구이며, 어디서 무엇을 하고, 어떤 결과를 만드는지 먼저 적습니다.

플레이어 역할+장소+핵심 행동+목표·감정
ROUGH IDEA

“숲 배경의 귀여운 게임”

배경과 분위기는 보이지만 누가 무엇을 하는지 없습니다. 캐릭터와 소품의 기능을 결정할 기준이 생기지 않습니다.

ONE-SENTENCE CONCEPT

“작은 숲의 배달부는 빛을 잃은 길에서 씨앗 등불을 되살려 안전한 귀환을 만든다.”

배달부, 어두운 숲길, 등불을 되살리는 행동과 안전한 귀환이라는 목표가 한 문장 안에 있습니다.

문장을 검사하는 질문

이 문장을 읽은 사람이 플레이어의 대표 소품 하나와 화면의 가장 중요한 색 하나를 추측할 수 있습니까? 그렇지 않다면 형용사를 늘리기보다 역할과 행동을 더 분명하게 씁니다.

방향을 잠그기

스타일 보드는 예쁜 이미지 모음이 아니라 결정판입니다

각 이미지와 색에는 이유와 역할이 있어야 합니다. 보드만 본 다른 사람이 다음 후보를 같은 방향으로 만들 수 있어야 합니다.

CONCEPT한 문장 게임 콘셉트모든 시각 결정이 되돌아갈 기준 문장
KEYWORDS정확히 세 개의 시각 키워드예: 둥근, 조용한, 손으로 만든
SHAPE · FUNCTION실루엣과 대표 소품64px에서도 배달부의 가방과 등불이 분리되어 보이도록 설정
VIEW · SCALE하나의 시점과 확인 크기top-down 3/4, 전신 중앙, 64×64 preview
PALETTE정확히 다섯 색과 HEX배경, 몸통, 그림자, 따뜻한 강조, 빛의 역할을 고정
MATERIAL · LIGHT표면 한 가지와 빛 한 방향무광 종이 질감, 왼쪽 위의 부드러운 빛
AVOID정확히 세 가지 금지 요소복잡한 배경, 글자, 사실적인 피부와 같이 결과에서 바로 확인할 항목
BOARD TEST 보드에 넣은 모든 요소 옆에 “이것이 무엇을 통제하는가?”라고 물을 수 있어야 합니다. 역할을 답할 수 없는 이미지는 장식이므로 뺍니다.

프롬프트는 장면을 조립하는 순서로 씁니다

핵심 대상이 묻히지 않도록 사용 목적과 대상을 먼저 쓰고, 구도와 시각 규칙을 붙인 뒤 기술 제약과 제외 요소로 닫습니다.

  1. 01 / USE용도

    게임용 정적 캐릭터 Sprite 방향 후보라고 밝힙니다.

  2. 02 / SUBJECT대상과 기능

    숲의 배달부, 큰 가방과 씨앗 등불처럼 기능 단서를 씁니다.

  3. 03 / COMPOSITION시점과 구도

    전신, 중앙, top-down 3/4와 화면 여백을 고정합니다.

  4. 04 / VISUAL RULES형태·색·재질·빛

    스타일 보드에서 선택한 관찰 가능한 규칙을 적습니다.

  5. 05 / CONSTRAINTS기술 제약과 제외

    단순 배경, 글자 없음, 잘린 신체 없음처럼 검사할 조건을 씁니다.

week09_prompt_v01.txt
[용도] 게임용 정적 캐릭터 Sprite의 아트 디렉션 후보.
[대상] 작은 숲의 배달부 한 명. 큰 둥근 가방과 씨앗 등불이 역할을 보여 준다.
[구도] 전신이 모두 보이는 중앙 구도, top-down 3/4 시점, 캐릭터 주변에 충분한 여백.
[시각 규칙] 둥근 실루엣, 제한된 다섯 색, 짙은 청록 몸통과 산호색 강조, 무광 종이 질감, 왼쪽 위의 부드러운 빛.
[기술 제약] 64×64로 줄였을 때 머리·몸·가방·등불이 분리되어야 한다.
[제외] 글자, 로고, 복잡한 배경, 잘린 신체, 사실적인 피부, 과도한 장식 없음.
[이번 변경 변수] 기준 버전이므로 없음.

프롬프트는 보드와 함께 읽어야 합니다.

Negative prompt의 역할

Negative prompt는 “싫은 느낌”이 아니라 관찰 가능한 제외 조건을 적는 곳입니다. “나쁘게 만들지 말 것” 대신 “글자 없음, 배경 소품 없음, 손에 추가 물체 없음”처럼 판정 가능한 말로 씁니다.

참조 이미지는 각각 한 가지 역할만 맡깁니다

여러 이미지를 설명 없이 넣으면 무엇을 따라야 하는지 충돌합니다. 출처와 권리를 확인한 뒤, 참조마다 가져올 속성을 이름 붙입니다.

참조 방식통제하는 것수업 예시주의
Image Reference직접 수정할 출발 이미지직접 그린 배달부 스케치입력 이미지 권리를 먼저 확인
Style Reference팔레트·렌더링·전체 미감직접 만든 종이 질감 보드내용까지 복제하는 지시로 쓰지 않음
Composition Reference배치·프레이밍·자세전신 중앙과 충분한 여백대상의 정체성과 분리해 기록
Depth Reference앞뒤 거리와 깊이가방이 몸 뒤에 읽히는 층2D Sprite에 불필요하면 사용하지 않음
Line Art Reference선의 모양과 밀도굵고 단순한 직접 제작 외곽선작가 이름 대신 선의 속성을 설명
Feature Reference특정 색 패턴·형태 특징잎 모양 버클과 산호색 매듭기존 캐릭터의 고유 표지를 모방하지 않음
출처·허락+참조 역할 하나+영향 강도=설명 가능한 입력

세 결과가 모두 다르면 선택은 취향 투표가 됩니다. 공통 규칙을 잠그고 인접한 버전 사이에서 변경 변수 하나만 움직입니다.

같은 프롬프트에서 여러 장을 뽑는 것은 모델의 변동 폭을 보는 선택 batch입니다. 프롬프트 한 줄을 바꾸어 전후를 보는 것은 방향을 검증하는 iteration입니다. 3교시 기록에는 어떤 비교를 했는지 구분해 적습니다.

큰 원본보다 게임 화면 크기에서 먼저 판단합니다

1024px 이미지의 털, 주름과 장식은 게임에서 64px가 되면 사라집니다. 작게 만들었을 때 남는 외곽과 명암이 Sprite의 실제 정보입니다.

  1. 01 / 64PX실제 크기로 축소

    보간이 있더라도 먼저 64×64 preview를 따로 만듭니다.

  2. 02 / SILHOUETTE검은 외곽만 보기

    머리, 몸, 가방과 등불의 큰 덩어리가 겹치지 않는지 봅니다.

  3. 03 / GRAYSCALE색을 제거하기

    몸과 소품의 명도 차이가 남아 있는지 확인합니다.

  4. 04 / CONTEXT게임 배경 위에 놓기

    실제 배경과 비슷한 밝기에서 캐릭터가 묻히지 않는지 봅니다.

  5. 05 / DISTANCE한 걸음 물러나기

    세부를 읽지 않아도 역할과 방향이 보이는지 확인합니다.

DETAIL BUDGET 작게 보이지 않는 장식은 기능 정보가 아닙니다. 먼저 큰 덩어리와 명암을 고치고, 세부 묘사는 10주차 후처리에서 필요한 만큼만 남깁니다.

후보를 선택하기

가장 화려한 장이 아니라 다음 단계로 갈 장을 선택합니다

각 기준을 0, 1, 2점으로 판정하되 총점만 따르지 않습니다. 낮은 점수의 이유와 사람이 고칠 수 있는 범위를 함께 봅니다.

메뉴 이름보다 고정과 변경, 관찰과 선택의 관계를 설명합니다.

Q1. 스타일 보드가 mood board와 다른 점은?

mood board는 분위기 탐색에 가깝습니다. 이 수업의 style board는 각 이미지, 색과 단어가 실루엣·시점·팔레트·재질 같은 생성 규칙을 직접 통제하는 결정 문서입니다.

Q2. 세 후보에서 한 번에 하나만 바꾸는 이유는?

변화의 원인을 읽기 위해서입니다. 모양, 색, 시점과 재질을 동시에 바꾸면 무엇이 가독성을 개선하거나 방향을 흐렸는지 설명할 수 없습니다.

Q3. 큰 원본보다 64px와 회색조를 먼저 보는 이유는?

게임 화면에서 사라질 세부를 제외하고 실루엣과 명도 구조를 확인하기 위해서입니다. 색이 없어도 역할과 핵심 소품이 분리되어야 합니다.

Q4. 선택한 결과가 아직 완성 에셋이 아닌 이유는?

투명 배경, 실제 픽셀 밀도, 색과 프레임 일관성, Pivot, import 설정과 Play Mode 가독성을 아직 검증하지 않았기 때문입니다.

기능 이름과 지원 범위는 beta 버전에 따라 달라질 수 있습니다. 실제 수업 환경의 package version을 함께 확인합니다.
