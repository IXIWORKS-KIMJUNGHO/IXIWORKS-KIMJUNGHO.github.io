각 Script는 하나의 책임만 가집니다

GameManager는 시간 규칙을 소유하고, TimeBonus는 접촉 사건을 한 번 전달합니다. 같은 데이터를 두 곳에서 관리하지 않습니다.

GameManager.cs · add one public method
public bool TryAddTime(float seconds)
{
    if (CurrentState != GameState.Playing || seconds <= 0f)
    {
        return false;
    }

    timeRemaining = Mathf.Min(
        timeRemaining + seconds,
        roundDuration
    );
    UpdateHud();
    return true;
}

bool

요청이 실제로 받아들여졌는지 호출자에게 돌려줍니다.

Playing

Ready, Won과 Lost에서 시간 변경을 거부합니다.

seconds <= 0f

잘못된 0 또는 음수 입력을 시간 추가로 처리하지 않습니다.

Mathf.Min

현재 시간에 보너스를 더하되 roundDuration을 상한으로 사용합니다.

UpdateHud

데이터를 바꾼 같은 사건에서 화면도 즉시 갱신합니다.

TimeBonus.cs · event sender
using UnityEngine;

public class TimeBonus : MonoBehaviour
{
    [SerializeField] private GameManager gameManager;
    [SerializeField, Min(0.1f)] private float bonusSeconds = 5f;

    private bool collected;

    private void OnTriggerEnter2D(Collider2D other)
    {
        if (collected || !other.CompareTag("Player") || gameManager == null)
        {
            return;
        }

        if (!gameManager.TryAddTime(bonusSeconds))
        {
            return;
        }

        collected = true;
        gameObject.SetActive(false);
    }
}

순서책임실패하면
Player 접촉 확인TimeBonus다른 Collider는 무시
상태와 값 승인GameManager.TryAddTimefalse 반환, 오브젝트 유지
시간과 HUD 변경GameManager승인 전에는 아무 변화 없음
한 번 처리 기록TimeBonus승인한 사건에만 collected = true
시각 결과TimeBonus성공한 경우에만 비활성화
단일 진실TimeBonus가 timeRemaining을 직접 찾거나 복제하지 않습니다. 시간의 변경 가능 여부와 상한은 데이터 소유자인 GameManager가 결정합니다.

prompt를 처음부터 다시 쓰거나 전체 기능을 재생성하지 않습니다. 실패한 관찰과 가장 가까운 파일 또는 연결 하나만 확인합니다.

Console에 TryAddTime가 없다는 오류가 납니다

메서드가 실제 GameManager 클래스 안에 추가되었는지, 이름과 매개변수가 호출부와 같은지 확인합니다. 다른 클래스나 중괄호 밖에 들어갔다면 그 위치만 수정합니다.

접촉해도 아무 일도 일어나지 않습니다

Console, TimeBonus의 GameManager 참조, Collider2D Is Trigger, Player Tag와 Rigidbody2D 조건을 기존 Collectible과 순서대로 비교합니다.

Ready에서 보너스가 사라집니다

TryAddTime의 반환값을 확인하기 전에 collected 또는 SetActive가 실행되는지 봅니다. 승인에 실패하면 TimeBonus는 그대로 남아야 합니다.

28초에서 33초가 됩니다

Mathf.Min(timeRemaining + seconds, roundDuration)의 두 번째 인자가 상한인지 확인합니다. Mathf.Max 또는 인자 순서 오류를 고칩니다.

Restart 뒤 TimeBonus가 돌아오지 않습니다

현재 Scene 재로드가 실제로 실행되는지와 TimeBonus가 Scene에 저장된 활성 GameObject인지 확인합니다. runtime 비활성화는 Scene 재로드 뒤 원래 저장 상태로 돌아와야 합니다.

Agent가 Scene이나 package를 바꾸었습니다

검증을 중단하고 변경 목록을 저장합니다. 체크포인트와 diff로 범위 밖 변경을 되돌린 뒤 Plan과 권한을 다시 잠급니다. 그 상태를 숨기고 계속 진행하지 않습니다.

코드 구술은 네 질문이면 충분합니다

줄을 외우지 않습니다. 데이터의 주인, 사건 전달자, 거부 조건과 관찰 가능한 결과를 연결해 설명합니다.

OWNER

누가 시간을 소유합니까?

GameManager가 timeRemaining과 상태를 소유하고 상한을 결정합니다.

EVENT

누가 접촉을 전달합니까?

TimeBonus가 Player 접촉을 확인하고 TryAddTime을 한 번 요청합니다.

REJECT

언제 아무 일도 하지 않습니까?

Playing이 아니거나 값이 0 이하이거나 참조가 없거나 이미 처리한 경우입니다.

PROOF

작동을 어떻게 증명합니까?

20+5, 28+5, 한 번 처리, 상태 거부와 기존 루프 회귀를 실행합니다.

60초 구술 예시

“TimeBonus는 시간을 저장하지 않고 접촉만 감지합니다. GameManager의 TryAddTime이 Playing과 양수 조건을 확인한 뒤 roundDuration을 상한으로 timeRemaining을 바꾸고 HUD를 갱신합니다. true가 돌아온 경우에만 TimeBonus가 처리 완료를 기록하고 사라집니다. 그래서 결과 상태에서는 시간도 오브젝트도 바뀌지 않습니다.”
