자동화 실패는 연결부터 쓰기까지 역순으로 찾지 않습니다

처음 어긋난 관찰 단계로 돌아갑니다. 이미 맞는 Package·계정·Project 전체를 다시 설정하지 않습니다.

baseline→target·version→connection→read result→one diff→rollback
MCP client가 Pending Connection에 나타나지 않습니다

Bridge Running, client 설정과 relay absolute path를 한 번 확인합니다. 5분 안에 해결되지 않으면 Route B 또는 C로 전환하고 시각과 이유를 log에 남깁니다. 수업 중 package를 다시 설치하지 않습니다.

unity status가 Editor를 찾지 못합니다

Unity Editor가 실행 중인지, 현재 CLI version의 help와 Pipeline 설치 상태를 확인합니다. account login이 필요하거나 연결이 불안정하면 fixture를 읽고 수동 Unity 관찰을 계속합니다.

여러 Editor가 보여 어느 것이 대상인지 모릅니다

명령하지 않습니다. 다른 Editor를 닫고 projectPath를 다시 읽습니다. 필요할 때는 복제본의 absolute --project-path를 사용하고 report에는 식별 정보를 줄인 경로를 기록합니다.

Console report가 실제 count와 다릅니다

Console clear·collapse·filter와 읽은 시점을 확인하고 같은 baseline에서 다시 읽습니다. 자연어 요약을 맞게 고치지 말고 불일치를 FAIL로 기록한 뒤 실제 message 목록을 근거로 수정합니다.

Player가 없거나 두 개 이상입니다

쓰기를 중단합니다. active Scene과 hierarchy path를 확인하고 정확한 대상 이름을 교수자에게 보고합니다. 모호한 대상을 임의 선택하는 것은 T04 FAIL입니다.

Probe X 외에 다른 값도 바뀌었습니다

즉시 추가 실행을 멈추고 전체 diff를 기록한 뒤 Undo 또는 checkpoint로 baseline을 복원합니다. 권한 계약의 target·property 제한이 실제 tool 호출과 맞았는지 확인합니다.

Undo 뒤 X=0인데 Scene에 미저장 표시가 남습니다

Transform, Hierarchy와 file diff를 baseline과 비교합니다. 예상하지 않은 변경이 없다면 수업 지침에 따라 baseline 상태로 저장 여부를 확인하고, 잔여 diff가 있으면 checkpoint 복제본과 대조합니다.

API key 또는 계정 정보가 캡처에 보입니다

그 파일은 제출하지 않습니다. 노출이 의심되는 key는 즉시 폐기·재발급하고 담당자에게 알립니다. 새 캡처에서는 credential UI를 닫고 필요한 Unity 상태만 좁게 기록합니다.
