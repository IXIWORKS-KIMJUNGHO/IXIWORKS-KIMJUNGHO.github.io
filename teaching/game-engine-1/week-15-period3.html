15주차 / 3교시 / 목표지향 개인 실습

릴리스 후보의 위험 하나를 닫습니다

RC0의 첫 실패 관문 하나만 처리하고 같은 검사와 제출 리허설로 RC1 증거를 완성합니다.

오늘의 개인 미션

면담에서 확인한 첫 실패 관문을 닫고 재현 가능한 릴리스 기록을 남깁니다.

  • 01

    작동하는 RC0 baseline을 복사해 보존합니다.

  • 02

    면담 기록의 첫 실패 관문 하나만 선택합니다.

  • 03

    수정, 삭제, 보류 중 가장 안전한 한 경로를 실행합니다.

  • 04

    T01-T08과 제출 리허설로 RC1 또는 안전한 HOLD 증거를 완성합니다.

CLASS MODE / PERIOD 03목표지향 개인 실습 / 개인 제작

목표는 고정하고 해결 경로는 선택합니다. RC0의 첫 실패 관문 하나를 닫고 RC1 증거 묶음을 완성합니다. 작업 속도와 기능 수는 평가하지 않습니다.

원본과 작업본을 먼저 분리합니다

오늘의 변경이 실패해도 면담 때 확인한 RC0로 돌아갈 수 있어야 합니다.

01 / BASELINE

RC0_BASELINE/

면담에서 실행한 build와 기록을 그대로 복사합니다. 이 폴더에서는 어떤 파일도 수정하지 않습니다.

02 / WORKING COPY

Project_RC1_WORK/

승인된 범위의 Scene, Prefab, Script 또는 asset만 바꾸는 작업 복사본입니다.

03 / CANDIDATE

RC1_CANDIDATE/

T01-T08을 실행할 독립 build입니다. 기존 폴더 위에 덮어쓰지 않습니다.

04 / RECORD

Evidence/Week15/

면담 ticket, before, after, Player log, 테스트 CSV와 RELEASE_RECORD.md를 저장합니다.

15주차 release starter

기록 템플릿과 테스트 CSV, 권리 ledger, 제출 지도를 작업 폴더에 복사합니다. 정답 코드나 완성 project는 포함하지 않습니다.

starter ZIP 받기

첫 실패 관문에 맞는 한 경로만 고릅니다

여러 문제를 조금씩 만지지 않습니다. 한 경로의 완료 조건을 먼저 쓰고 그 범위만 변경합니다.

FIX / 제한 수정

작고 원인이 분명함

P0 또는 P1이지만 영향 파일과 재현 조건이 좁습니다. 한 변경 뒤 같은 입력과 전체 핵심 경로를 검사합니다.

REMOVE / 불안정 기능 삭제

선택 기능이 제출을 위협함

핵심 한 판에 필요하지 않고 수정 회귀가 큽니다. 참조와 UI 흔적까지 안전하게 제거한 뒤 baseline 경험을 검사합니다.

DEFER / 기록 후 보류

핵심을 막지 않거나 시간이 큼

P2 또는 P3이거나 안전한 수정 범위를 확정하지 못했습니다. 현재 RC0를 보존하고 원인, 다음 검사와 보류 위치를 기록합니다.

ROUTE LIMIT20분 안에 한 번의 변경과 같은 재검사를 끝낼 수 없으면 새 수정을 쌓지 않고 DEFER 또는 안전한 HOLD로 전환합니다.

60분 안에 한 위험을 증거로 닫습니다

빨리 끝내는 것이 목적은 아니지만, 각 단계가 길어질 때 되돌아갈 기준은 필요합니다.

00-60 min

한 선택, 한 변경, 같은 검사, 한 묶음

Goal-directed individual mission

  1. 00-06
    baseline 봉인

    RC0, 면담 ticket과 제출 파일을 복사하고 새 폴더 이름을 확인합니다.

  2. 06-12
    경로 선택

    첫 실패 관문, 재현 조건, 허용과 금지 범위, 완료 조건을 씁니다.

  3. 12-30
    제한 변경

    FIX, REMOVE, DEFER 중 선택한 경로의 한 행동만 수행합니다.

  4. 30-40
    같은 재검사

    before와 같은 target, 입력, 상태에서 기대 결과를 확인합니다.

  5. 40-49
    회귀 검사

    시작, 핵심 행동, 성공 또는 실패, 재시작과 독립 실행을 다시 확인합니다.

  6. 49-56
    RC1과 제출 리허설

    새 폴더에 build하고 권리 ledger와 제출 묶음을 실제로 다시 엽니다.

  7. 56-60
    증거 봉인

    T01-T08 CSV, RELEASE_RECORD.md와 90초 설명을 저장합니다.

변경 전에 여섯 문장을 고정합니다

코드를 먼저 열면 범위가 넓어집니다. 관찰과 검사를 먼저 쓰면 한 변경의 경계가 보입니다.

OBSERVED

실제로 본 실패

target, 입력 순서, 처음 다른 화면 또는 값과 발생 시각을 씁니다.

EXPECTED

통과했을 때의 결과

같은 조건에서 화면, 상태, log 또는 파일이 어떻게 달라져야 하는지 씁니다.

ALLOW

바꿔도 되는 범위

승인된 Scene, Prefab, Script, asset 또는 값의 실제 이름을 씁니다.

FORBID

건드리지 않을 범위

새 기능, package, 큰 구조 변경과 baseline 폴더를 명시합니다.

RETEST

같은 실패 재검사

수정 전과 같은 입력으로 기대 결과가 나타나는지 확인합니다.

REGRESSION

기존 핵심 경로 확인

정상 시작부터 결과, 재시작과 독립 실행까지 다시 검사합니다.

T01-T08이 모두 통과해야 RC1입니다

선택 문제만 고쳐도 기존 한 판이 깨지면 릴리스 후보가 아닙니다. 각 행의 결과와 확인한 증거를 기록합니다.

RELEASE TESTS0 / 8 PASS
검사행동기대 결과결과증거
T01새 폴더에서 RC1 실행Editor 없이 시작 화면 또는 게임이 정상 표시됨
T02설명 없이 3-5분 핵심 경로 완주목표, 핵심 행동과 결과가 끊기지 않음
T03성공 또는 실패 뒤 재시작플레이어와 핵심 상태가 초기값으로 돌아감
T04같은 실행 시간대의 Player log 확인critical path의 Exception과 Missing Reference가 없음
T05지정 화면 비율과 음소거에서 플레이UI가 잘리지 않고 핵심 상태를 둘 이상의 신호로 읽음
T06면담의 첫 실패를 같은 조건으로 재검사기대 결과가 나타나고 허용 범위 밖 변경이 없음
T07권리 ledger와 RC1 실제 파일 비교source, permission, AI, 수정과 최종 사용이 일치함
T08제출 폴더에서 모든 항목 다시 열기build, project, 영상, 설명서와 AI 로그가 열림

8 / 8 PASS는 자동 합격이 아니라 RC1 증거가 모두 준비되었다는 뜻입니다. 실제 파일과 build를 함께 확인합니다.

이 페이지는 이름과 학번을 묻거나 저장하지 않습니다. 이 기기에는 테스트 결과와 짧은 증거만 저장되며 CSV는 버튼을 누를 때만 내려받습니다.

검사가 실패하면 더 만들지 말고 판정을 낮춥니다

한 FAIL을 숨기지 않고 RC1, READY IF 또는 HOLD 중 현재 상태를 다시 기록합니다.

T06은 통과했지만 T02가 실패했습니다

선택 문제는 고쳤지만 회귀가 생겼습니다. RC1로 승인하지 않습니다. 작업 복사본을 보존하고 baseline과 비교해 변경을 더 작게 나누거나 되돌립니다.

Editor에서는 되지만 T01이 실패합니다

Build Profile의 Scene List, 저장되지 않은 변경, 파일명 대소문자와 project 밖 경로를 확인합니다. 독립 실행이 통과하기 전에는 다른 polish를 중단합니다.

20분 안에 원인을 찾지 못했습니다

추가 수정을 쌓지 않습니다. 재현 조건, 최초 다른 상태, 확인한 log, 안전한 RC0와 다음 검사 한 가지를 RELEASE_RECORD.md에 남기고 HOLD로 전환합니다.

권리 기록을 지금 확인할 수 없습니다

출처 불명 에셋은 최종 사용에서 제외하거나 안전한 수업 제공 에셋으로 교체합니다. 확인 전에는 T07을 PASS로 표시하지 않습니다.

REMOVE 뒤 빈 버튼이나 참조가 남았습니다

기능 코드만 삭제하지 말고 호출, Inspector 참조, UI 안내와 파일을 함께 검사합니다. Missing Reference와 핵심 경로를 다시 실행합니다.

DEFER를 선택하면 과제를 실패한 건가요?

아닙니다. 핵심 경로를 보존하고 영향, 보류 이유와 다음 검사를 정확히 남기면 유효한 릴리스 판단입니다. 다만 P0를 해결하지 못한 상태는 HOLD입니다.

파일이 함께 열릴 때 제출 묶음입니다

각 항목은 존재 여부가 아니라 다른 컴퓨터에서 다시 열리는지 확인합니다.

BUILD

RC1_CANDIDATE/

지정 target의 실행 파일과 Data 폴더 전체입니다.

PROJECT

UnityProject/

Library와 임시 build를 제외하고 열 수 있는 project입니다.

EVIDENCE

Evidence/Week15/

before, after, Player log와 테스트 CSV입니다.

RECORD

RELEASE_RECORD.md

첫 실패, 선택 경로, 변경, 판정과 남은 위험입니다.

RIGHTS

asset-ledger.csv

외부 및 생성 에셋의 출처, 허용, 수정과 최종 사용 상태입니다.

FINAL MAP

submission-map.md

build, 영상, 작품설명서와 AI 제작 로그의 실제 위치입니다.

90초 설명은 네 문장으로 끝냅니다

기능을 나열하지 않고 한 판, 위험, 결정과 증거를 연결합니다.

0-20 sec / CORE

게임의 핵심

플레이어 행동, 상태 변화와 3-5분 목표를 한 문장으로 말합니다.

20-40 sec / RISK

첫 실패 관문

어떤 target과 입력에서 무엇이 기대와 달랐는지 말합니다.

40-65 sec / CHANGE

선택한 경로

FIX, REMOVE, DEFER 중 하나와 허용, 금지 범위를 설명합니다.

65-90 sec / PROOF

판정 증거

T01-T08, RC1 또는 HOLD, 남은 위험과 제출 묶음을 제시합니다.
