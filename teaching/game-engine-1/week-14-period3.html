Week 14 / Period 03 / Individual Checkpoint

결정한 문제 하나를 증거로 닫습니다

승인된 범위만 바꾸고, 같은 조건의 재검사와 독립 build로 15주차 준비를 증명합니다.

미션 시작 필수 테스트 보기

60분 뒤 남아야 할 체크포인트

모든 학생이 교수자에게 확인받은 한 가지 목표를 각자의 project copy에서 수행합니다. 작업 속도와 기능 수는 평가하지 않습니다.

  • 결정

    면담에서 승인받은 blocking issue 하나와 완료 조건이 기록됩니다.

  • 변경

    승인 범위 안의 작고 되돌릴 수 있는 수정만 project copy에 적용합니다.

  • 증거

    같은 재현 조건과 핵심 loop 회귀 검사로 8 / 8 PASS를 남깁니다.

  • 인계

    build, 구조도, 면담 기록과 15주차 할 일을 하나의 체크포인트 묶음으로 저장합니다.

CLASS MODE목표지향 개인 실습

목표는 고정하고 해결 경로는 선택합니다. 교수자는 시작 목표와 중간 체크포인트를 확인하고 클릭 순서는 지시하지 않습니다. 학생은 자신의 project copy에서 독립적으로 개인 제작, 재검사, build와 제출 판정을 수행합니다.

미션 계약

면담 결정을 작동하는 체크포인트로 바꿉니다

아래 네 문장이 모두 참이면 완료입니다. 해결이 위험하거나 20분을 넘으면 기능을 억지로 고치지 않고 진단 경로로 전환합니다.

APPROVE

한 문제

문제, 재현 조건, 변경 범위와 완료 조건이 면담 기록에 있습니다.

BOUND

작은 변경

허용된 Scene, Prefab, Script 또는 값만 바꾸고 새 기능은 추가하지 않습니다.

RETEST

같은 조건

수정 전과 같은 입력, 상태와 실행 환경에서 기대 결과를 다시 확인합니다.

HANDOFF

15주차 준비

독립 build, 구조도, 기록과 다음 검증 목록을 한 폴더에 남깁니다.

before, after, Console, build와 면담 기록을 분리해 저장합니다.

INTERVIEW승인 문장 한 줄

문제, 범위, 기대 결과와 회귀 검사를 시작 전에 읽습니다.

Rollback수정 전 project copy와 before 증거가 있음복사와 화면 저장이 끝나기 전 변경 금지

경로 선택

문제의 영향과 위험에 따라 세 경로 중 하나를 고릅니다

가장 높은 우선순위라도 지금 안전하게 고칠 수 없는 문제는 진단해야 합니다. 낮은 우선순위는 새 기능 없이 보류합니다.

권장 경로FIX / 제한 수정

승인 범위 안에서 수정한 뒤 같은 조건과 회귀 테스트를 실행합니다.

FIX

20분 안의 제한 수정

P0 또는 P1이고 영향 범위가 작습니다. 한 변경 뒤 즉시 같은 조건을 재검사합니다.

DIAGNOSE / 원인 확정

원인과 다음 검사를 확정

구조 변경이 크거나 20분을 넘습니다. 로그, 참조와 최소 재현으로 원인을 좁히고 안전한 현재 build를 보존합니다.

DEFER / 범위 밖 보류

현재 범위 밖으로 보류

P2 또는 P3이거나 핵심 한 판을 바꾸지 않습니다. 15주차 검증표에 넣거나 삭제하고 새 기능을 시작하지 않습니다.

일곱 개 제작 구간으로 한 문제를 끝까지 닫습니다

각 구간에는 눈에 보이는 중간 도착점이 있습니다. 교수자는 18분과 48분에 목표 이탈과 증거 누락만 확인하고, 구현 순서와 해결 방법은 학생이 선택합니다.

00-60 min

Mentoring checkpoint sprint

Individual goal-directed production

  1. 00-06
    baseline과 copy

    Alpha v1을 실행하고 project copy, before 화면, Console과 증거 폴더를 준비합니다.

  2. 06-12
    승인 문장 고정

    문제, 재현 조건, 허용 변경, 기대 결과와 회귀 범위를 체크포인트에 옮깁니다.

  3. 12-18
    경로 판정

    영향, 예상 시간과 위험으로 Fix, Diagnose 또는 Defer 중 하나를 선택합니다.

  4. 18-38
    한 가지 행동

    Fix는 제한 수정, Diagnose는 최소 재현과 원인 확인, Defer는 안전한 제거와 범위 정리를 수행합니다.

  5. 38-48
    같은 재검사

    수정 전과 같은 조건에서 결과를 확인하고 정상, 경계와 거부 조건을 기록합니다.

  6. 48-55
    회귀 build

    시작, 핵심 행동, 성공 또는 실패, 재시작과 독립 실행을 다시 검사합니다.

  7. 55-60
    체크포인트 봉인

    8 / 8 PASS, CSV, Markdown, 구조도와 build를 저장하고 15주차 첫 행동을 한 줄로 씁니다.

수정 전에 여섯 칸 변경 계약을 씁니다

구현 도구와 관계없이 같은 계약을 사용합니다. AI Assistant를 사용할 때에도 먼저 읽기와 계획으로 범위를 확인하고 승인 전에는 변경하지 않습니다.

OBSERVED

현재 결과

입력, 상태와 화면에서 반복 가능한 사실을 씁니다.

EXPECTED

기대 결과

누가 보아도 PASS와 FAIL을 나눌 수 있게 씁니다.

ALLOW

허용 변경

면담에서 승인된 Scene, Prefab, Script 또는 값만 적습니다.

FORBID

변경 금지

새 패키지, 핵심 구조, 다른 기능과 Project Settings를 잠급니다.

RETEST

같은 검사

수정 전후에 같은 시작 상태, 입력과 관찰 결과를 사용합니다.

REGRESSION

기존 한 판

이번 문제와 무관해도 시작부터 재시작까지 다시 확인합니다.

AI PERMISSION

Ask는 원인과 실제 구조를 읽는 데 사용합니다. Plan은 예상 변경 파일과 테스트를 먼저 보여 주게 합니다. Agent를 사용한다면 면담에서 승인된 Script 범위만 허용하고 Scene, Prefab 연결과 build 판정은 학생이 직접 수행합니다.

완료 증거

여덟 테스트가 모두 PASS일 때 체크포인트를 제출합니다

각 테스트는 상태와 메모를 이 기기에 저장합니다. 이름이나 학번을 입력하지 않고, 완료 뒤 CSV를 내려받아 제출 폴더에 보관합니다.

필수 통과 · FIX 경로0 / 8 PASS

T05수정 전과 같은 정상 조건 재검사기대 결과가 실제 화면과 상태에 나타남
T06경계 또는 거부 조건 실행중복, 잘못된 상태와 경계값에서 규칙 유지

T0890초 설명과 체크포인트 묶음 확인구조, 결정, 증거, 다음 행동을 설명하고 파일 완비

이 표는 현재 브라우저의 localStorage에만 저장됩니다. 공용 기기에서는 CSV를 저장한 뒤 기록 초기화를 누릅니다.

FAIL은 더 큰 수정이 아니라 더 가까운 증거로 좁힙니다

한 번에 한 조건만 확인합니다. 원래 문제와 무관한 실패가 생기면 즉시 baseline copy로 돌아갑니다.

재현 조건→최초 다른 상태→실제 소유자→한 변경→같은 테스트
20분이 지나도 원인을 찾지 못했습니다

Fix에서 Diagnose로 전환합니다. 재현 순서, Console 또는 상태 값, 확인한 Script와 아직 모르는 사실을 저장합니다. 최근 작동 build를 유지하고 다음 진단 행동을 15주차 첫 항목으로 넘깁니다.

수정 뒤 다른 기능이 깨졌습니다

추가 수정을 쌓지 않습니다. project copy를 복구한 뒤 원래 변경을 더 작게 나눕니다. 같은 회귀 실패가 반복되면 이번 수정은 채택하지 않고 기록만 남깁니다.

면담 문제가 P3 polish였습니다

교수자에게 우선순위를 다시 확인합니다. 핵심 loop와 제출 준비가 통과했다면 10분 이내 수정만 허용하고, 아니면 Defer로 이동합니다.

AI가 승인 범위 밖 파일을 바꿨습니다

변경을 적용하지 않거나 project copy로 복구합니다. Plan에 허용 파일과 금지 항목을 다시 적고, 필요한 한 파일만 수동으로 비교해 반영합니다.

Editor에서는 되지만 build에서 실패합니다

Build Profile의 Scene 목록, 저장되지 않은 변경, 파일명 대소문자와 외부 절대 경로를 확인합니다. 새 폴더에서 실행해 project 밖 의존성을 찾습니다.

체크포인트에 해결하지 못한 문제가 남았습니다

숨기지 않습니다. 현재 영향, 재현 조건, 시도한 검사, 안전한 build와 15주차 첫 행동을 기록하면 유효한 진단 결과입니다.

90초 인계 설명으로 자신의 결정을 복원합니다

코드를 보지 않는 상태에서도 구조와 증거를 연결할 수 있어야 합니다. 아래 네 문장을 자신의 프로젝트 이름으로 바꿔 말합니다.

0-20 sec

CORE

플레이어의 핵심 행동, 상태 변화와 한 판의 목표를 말합니다.

20-45 sec

STRUCTURE

Scene, Prefab, 핵심 Script와 피드백이 사건을 처리하는 순서를 설명합니다.

45-70 sec

DECISION

면담에서 선택한 문제, 변경 범위와 채택하거나 보류한 이유를 말합니다.

70-90 sec

PROOF

같은 재검사, 회귀 build, 남은 위험과 15주차 첫 행동을 제시합니다.

여덟 항목을 확인하고 15주차로 이동합니다

체크 상태는 이 기기에 저장됩니다. 모든 항목이 완료되어도 실제 파일과 build가 없으면 제출 완료가 아닙니다.
