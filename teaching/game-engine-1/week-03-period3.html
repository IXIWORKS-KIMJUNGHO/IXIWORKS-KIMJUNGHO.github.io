01 / 미션

미션: Motion Test Lane

2D 화면 안에서 세 개의 Mover가 같은 행동 구조를 공유하되, Inspector 설정에 따라 분명히 다른 성격으로 움직이는 테스트 장면을 만듭니다.

Goal 공통 코드는 재사용하고, 차이는 데이터로 만든다.

MotionController.cs 한 파일과 PF_Mover 한 Prefab을 사용합니다. Scene에는 세 Prefab instance가 있으며, 각 instance의 직렬화된 field 값이 서로 다른 움직임을 만듭니다.

완성 장면에서 반드시 관찰되어야 하는 것

Behavior A

이동하고 회전하지 않음

세 instance 중 하나는 오른쪽으로 이동하지만 회전은 하지 않습니다. bool 조건의 결과가 눈에 보여야 합니다.

Behavior B

이동하며 한 방향 회전

다른 instance는 이동과 회전을 함께 수행합니다. A와 속도 차이가 분명해야 합니다.

Behavior C

다른 속도와 반대 회전

나머지 instance는 B와 다른 속도이며 회전 방향도 반대입니다. 숫자 부호의 의미가 드러나야 합니다.

Shared rule

모두 경계에서 재시작

세 instance 모두 오른쪽 경계를 넘으면 왼쪽 시작 지점으로 돌아와 움직임을 계속합니다.

숫자는 학생이 결정합니다

정해진 속도 정답은 없습니다. 다만 가장 빠른 instance와 가장 느린 instance의 차이가 한눈에 보여야 하고, resetAtX는 restartAtX보다 커야 합니다. 선택한 숫자가 역할에 맞는 이유를 설명할 수 있어야 합니다.

03 / 제약

해결 방법을 선명하게 만드는 기술 제약

제약은 창의성을 막는 규칙이 아니라 이번 주 개념을 실제로 사용했는지 확인하는 경계입니다.

Required 01

Script Asset은 하나

오브젝트마다 Script를 복사하거나 이름만 바꾼 class를 만들지 않습니다.

Required 02

값은 직렬화한 private field

속도, 회전 여부, 회전 속도, 두 경계값을 [SerializeField] private로 둡니다.

Required 03

시간 기반 변화

이동량과 회전량 모두 Time.deltaTime을 사용해 초 단위로 계산합니다.

Required 04

조건이 화면에 보임

bool과 if로 한 instance의 회전만 끌 수 있어야 합니다.

Required 05

작은 method로 책임 분리

Update()는 이동, 회전, 경계 method를 호출하는 읽기 쉬운 목차가 됩니다.

물리와 입력 사용 금지

Rigidbody2D, 힘, 키보드 입력, Input System은 4주차 범위이므로 사용하지 않습니다.

06 / 힌트

필요한 만큼만 힌트를 엽니다

바로 완성 답을 보는 대신 현재 막힌 수준에 맞는 힌트 하나만 확인합니다. 확인한 뒤에는 창을 닫고 자신의 코드로 돌아갑니다.

Hint 01 · 개념Update가 복잡해졌다면?

Update()를 전체 실행 순서를 보여 주는 목차로 생각합니다. 이동, 조건부 회전, 경계 검사를 각각 이름 있는 작은 method로 분리하고 Update에서는 세 method를 호출합니다.

Hint 02 · 이동 식프레임마다 너무 빠르게 움직인다면?

이번 프레임의 이동 벡터에는 세 재료가 필요합니다: Vector3.right, moveSpeed, Time.deltaTime. 곱셈 뒤 Space.World 기준으로 Translate합니다.

Hint 03 · 조건회전을 껐는데 이동도 멈춘다면?

if의 중괄호 또는 조기 return이 통제하는 범위를 확인합니다. 회전 여부는 회전 method 안에서만 판단해야 하며 Update 전체를 빠져나가게 두지 않습니다.

Hint 04 · 경계 의사코드오른쪽 끝에서 사라진다면?

현재 x가 오른쪽 경계보다 큰가?를 판단합니다. 참이면 현재 position을 임시 변수에 담고 x만 왼쪽 시작값으로 바꾼 뒤, 수정한 Vector3를 transform.position에 다시 대입합니다.

Hint 05 · 오류 진단Console에 여러 오류가 한꺼번에 보인다면?

가장 위의 첫 빨간 오류부터 봅니다. 파일명과 줄 번호로 이동해 세미콜론, 괄호 짝, method 위치를 확인합니다. 첫 오류를 고친 뒤 저장하고, 나머지 오류가 함께 사라지는지 다시 확인합니다.
