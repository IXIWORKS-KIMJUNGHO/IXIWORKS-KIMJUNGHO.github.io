해상도와 게임 속 크기는 같은 말이 아닙니다

이미지의 픽셀 수는 파일의 정보량이고, Pixels Per Unit은 몇 픽셀을 Unity 월드의 1 unit으로 볼지 정하는 해석 규칙입니다.

Sprite 한 변의 픽셀÷Pixels Per Unit=Unity 월드 크기

픽셀에서 월드 크기로

정사각 Sprite의 한 변을 기준으로 계산합니다. 같은 PPU에서 픽셀이 두 배면 월드 크기도 두 배가 됩니다.

WORLD SIZE 1 unit 128px ÷ 128 PPU = 1 Unity unit입니다.
128 PX / 128 PPU

1 unit

수업의 캐릭터와 상호작용 Sprite는 한 셀을 128×128로 맞추고 128 PPU로 읽어 1×1 unit 기준을 만듭니다.

512 PX / 128 PPU

4 units

512px 원본을 그대로 128 PPU로 가져오면 4 unit가 됩니다. 높은 해상도가 자동으로 같은 크기를 보장하지 않습니다.

먼저 예측하기

128×128 Sprite와 256×256 Sprite를 모두 128 PPU로 import하면 누가 더 크게 보일까요? 같은 크기로 보여야 한다면 해상도를 맞추거나 PPU를 각각 128과 256으로 정할 수 있지만, 한 프로젝트에서는 가능한 한 공통 해상도와 PPU를 사용해 규칙을 단순하게 유지합니다.

네 장이 아니라 하나의 움직임을 만듭니다

각 프레임이 개별 그림으로는 좋아 보여도 기준선과 부피가 달라지면 재생 순간에 캐릭터가 흔들리고 커졌다 작아집니다.

에셋은 다섯 관문을 모두 통과해야 합니다

한 관문에서 실패하면 전체를 다시 생성하지 않습니다. 문제가 있는 층만 고치고 같은 조건으로 다시 확인합니다.

  1. G01 / READ가독성

    실제 게임 크기에서 Player, 수집물, 위험과 목표의 역할이 구분됩니다.

  2. G02 / EDGE경계

    배경 잔여물, 흰 halo, 잘린 외곽과 불필요한 반투명 픽셀이 없습니다.

  3. G03 / SCALE크기

    셀, PPU, 피벗이 프로젝트 규칙과 맞고 프레임이 흔들리지 않습니다.

  4. G04 / SYSTEM호환

    Sprite 분할, Animator, Image 또는 RawImage에서 의도대로 작동합니다.

  5. G05 / TRACE기록

    출처, 도구, prompt, 수정, 테스트를 다시 따라갈 수 있습니다.

QUALITY RULE

생성 횟수, 사용한 유료 도구와 원본의 화려함은 평가하지 않습니다. 가장 적은 후보로도 규격을 지키고 사람이 수정해 게임 안에서 증명했다면 같은 기준으로 통과합니다.

사람의 수정은 실패가 아니라 제작입니다

생성 결과를 그대로 사용하는 것이 목표가 아닙니다. 무엇이 문제인지 관찰하고 가장 작은 수정으로 계약에 맞추는 능력이 이번 주의 핵심입니다.

LOCAL REPAIR

문제 영역만 고칩니다

손가락, 소품, 잘린 모서리처럼 국소 결함은 inpaint 또는 직접 페인팅으로 수정하고 변경 위치와 이유를 로그에 남깁니다.

SYSTEM REPAIR

공통 규칙을 다시 맞춥니다

팔레트, 캔버스, 피벗이나 발 기준선이 어긋나면 모든 프레임을 같은 표와 가이드에 놓고 함께 정렬합니다.

  • 01
    해상도가 높으면 품질도 높다고 판단함

    게임 크기, 외곽과 프레임 일관성이 먼저입니다. 필요 없는 확대는 수정할 픽셀과 파일 크기만 늘립니다.

  • 02
    문제 하나 때문에 전체를 계속 재생성함

    좋은 실루엣과 팔레트를 보존하고 배경, 손, 기준선처럼 실패한 영역만 수정합니다.

  • 03
    확대 화면에서만 검사함

    100% 확대는 경계를 찾는 도구이고, 실제 Game View는 기능과 가독성을 판정하는 장소입니다. 둘 다 필요합니다.

  • 04
    AI metadata를 권리 확인으로 오해함

    생성 표시는 제작 경로의 한 부분입니다. 입력 참조의 이용 조건과 각 제공자의 약관을 사용자가 별도로 확인하고 기록합니다.

도구를 열기 전 네 질문

먼저 자신의 말로 답한 뒤 펼쳐 확인합니다. 답이 막히면 생성보다 규격을 다시 봅니다.

Q1. 선택된 이미지와 게임 에셋의 가장 큰 차이는 무엇인가?

선택 이미지는 방향 후보입니다. 게임 에셋은 역할, 크기, 경계, 프레임, import 방식, 권리, 수정 기록과 게임 안 테스트까지 확인된 제작 자산입니다.

Q2. 256px Sprite를 128 PPU로 import하면 한 변은 몇 unit인가?

256 ÷ 128 = 2이므로 2 unit입니다. 1 unit로 보이게 하려면 128px로 정규화하거나 해당 Sprite의 PPU를 256으로 정할 수 있습니다.

Q3. 걷기 프레임이 위아래로 흔들릴 때 먼저 무엇을 비교하는가?

모든 셀의 크기와 발 기준선, 피벗을 먼저 비교합니다. 그다음 캐릭터 부피와 프레임별 투명 여백을 확인합니다.

Q4. 사람이 수정한 흔적은 왜 로그에 남기는가?

최종 결과가 어떤 판단과 수정으로 만들어졌는지 설명하고, 같은 문제가 생겼을 때 전체를 다시 만들지 않고 재현, 교체하기 위해서입니다.
