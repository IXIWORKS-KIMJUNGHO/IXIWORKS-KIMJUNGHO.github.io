강의 개요

Unity fundamentals first, AI as a controlled production tool.

본 강의는 게임 제작 경험이 없는 학생도 Unity 6.3 LTS를 이용해 작동하는 2D 게임을 설계하고 완성할 수 있도록 구성한 입문 교과목이다. 전반부에는 Scene, GameObject, Component, Prefab, C# Script, Input System, Rigidbody2D, Collider2D, Tilemap, Sprite Animation, UI와 Audio 등 게임 엔진의 핵심 구조를 직접 다룬다. 학생들은 플레이어 이동, 충돌, 수집물, 점수, 성공과 실패, 재시작을 하나씩 구현하면서 화면에 보이는 결과와 프로젝트 내부 구조의 관계를 익힌다. 매주 3시간은 이론 1시간과 실습 2시간으로 운영하며, 이론에서 게임 시스템과 시청각 표현의 원리를 이해한 뒤 같은 날 작은 기능으로 구현하고 개인적으로 변형한다.

후반부에는 Unity의 Sprite Generator, Texture2D 기반 UI 제작, Sound Generator, Assistant의 Ask·Plan·Agent, MCP, AI Gateway, Unity CLI와 Pipeline을 제작 과정에 단계적으로 도입한다. 생성형 AI는 게임 전체를 대신 만드는 도구가 아니라 아이디어를 빠르게 시각화하고, 여러 대안을 비교하고, 반복 작업을 줄이며, 오류의 원인을 설명받는 보조 도구로 사용한다. 학생은 AI가 만든 이미지와 코드를 그대로 제출하지 않고 생성 목적, 프롬프트와 참조 자료, 선택 이유, 직접 수정한 부분, Play Mode 검증 결과를 기록해야 한다. 중간고사에서는 AI Agent와 Generator 없이 Unity 기초 역량을 확인하고, 기말 프로젝트에서는 3~5분 안에 완결되는 작은 2D 게임을 제작하여 기술 이해와 인간의 선택이 생성 결과를 어떻게 작품으로 발전시켰는지 보여준다.

AI 활용 방법론

기초 제작 → Ask → Plan → 제한 실행 → 검증 → 기록

  1. 01

    기초 제작

    학생이 먼저 최소 기능과 placeholder를 직접 만들어 비교 가능한 baseline을 확보한다.

  2. 02

    Ask

    필요한 Component, 코드 흐름과 오류 가능성을 읽기 전용 질문으로 이해한다.

  3. 03

    Plan

    수정할 Script·GameObject·에셋과 완료 조건을 실행 전에 확인한다.

  4. 04

    제한 실행

    Agent와 MCP는 하나의 작은 작업, 최소 권한, 예상한 파일 범위에서만 사용한다.

  5. 05

    검증

    Console, Inspector, Play Mode에서 정상·실패·경계 조건을 직접 테스트한다.

  6. 06

    기록

    프롬프트, 출처, 선택 근거, 사람의 수정, 테스트 결과를 AI 제작 로그에 남긴다.

수업 원칙 2~7주차에는 Agent를 사용하지 않는다. 9주차 이후에도 Ask와 Plan 없이 실행한 Agent 결과는 제작 증거로 인정하지 않으며, AI를 사용하지 않은 학생도 같은 기능과 반복 수정 과정을 제시하면 동일하게 평가한다.

Unity에서 이미지 만들기

Generate, select, edit, integrate, and verify.

Prompt & reference

Sprite Generator로 방향 탐색

Project 창에서 Create → 2D → Generate Sprite를 열고 텍스트 프롬프트와 참조 이미지를 함께 사용한다. 캐릭터, 수집물, 장애물, 아이콘을 동일한 팔레트와 시점으로 설계하고 negative prompt로 원하지 않는 요소를 제한한다.

Variation & control

후보를 만들고 사람이 선택

해상도, 생성 개수와 custom seed를 조절해 여러 후보를 비교한다. 생성 횟수나 화려함이 아니라 작은 게임 화면에서의 가독성, 충돌 영역과 실루엣의 일치, 다른 에셋과의 스타일 통일을 기준으로 선택한다.

Post-process

이미지를 게임 에셋으로 정리

Remove Background, Upscale, Pixelate, Recolor, Inpaint를 이용해 배경, 해상도, 팔레트와 일부 형태를 정리한다. 결과는 프로젝트의 GeneratedAssets/에서 확인하고 사람이 수정한 버전을 분리해 보관한다.

Animate & integrate

스프라이트시트에서 Play Mode까지

animation-ready 스프라이트시트를 생성해 Sprite Editor에서 slicing하고 idle·move·hit Animation Clip과 Animator Controller로 연결한다. 프레임 일관성을 직접 고친 뒤 Prefab, Collider2D, Sorting Layer와 함께 실제 장면에서 검증한다.

Placeholder first. 생성 이미지는 아트 디렉션과 기능 검증을 위한 임시 에셋으로 시작한다. 최종 사용 여부는 권리, 캐릭터 일관성, 학생의 수정 정도와 프로젝트 목적을 확인한 뒤 결정한다.

UI와 사운드도 같은 방식. UI는 기본 Text·Button으로 기능을 먼저 완성한 뒤 Sprite·Texture2D 결과로 교체하고, Sound Generator는 짧은 효과음과 환경음에 한정해 trim, fade, 음량과 반복 이음새를 검사한다.

프로젝트 운영 원칙

Small scope, visible evidence, explainable decisions.

Scope

작고 완결된 게임

기말은 하나의 핵심 행동, 작은 맵, 시작·플레이·성공 또는 실패·재시작이 있는 3~5분짜리 2D vertical slice로 제한한다.

Evidence

결과보다 과정

중간 build, 플레이테스트, 수정 전후 화면, 코드 diff와 AI 제작 로그를 통해 학생이 내린 판단과 반복 개선을 평가한다.

Authorship

설명할 수 있는 제작

학생은 핵심 Script의 입력→조건→결과, Scene과 Component 관계, 생성 에셋의 선택 이유와 직접 수정한 부분을 설명할 수 있어야 한다.

Access

AI는 선택 사항

유료 credit이나 특정 외부 모델을 필수로 요구하지 않는다. AI 접근이 어려운 경우 비AI 에셋과 수동 제작으로 같은 과제를 수행한다.

AI 안전·권리 규칙

  • 이름, 연락처, 얼굴, 음성 등 본인이나 타인의 개인정보를 AI 도구에 업로드하지 않는다.
  • Unity Asset Store 에셋과 사용 권한을 확인하지 않은 자료를 외부 생성 AI의 참조 이미지로 업로드하지 않는다.
  • API key, access token, 계정 정보는 Unity project, 제작 로그, 화면 캡처와 저장소에 기록하지 않는다.
  • AI 제작 로그에는 사용 도구·모델, 프롬프트·참조 출처, 생성 결과, 선택 이유, 직접 수정, 테스트와 최종 사용 여부를 기록한다.

학기 전 확인 Unity AI 기능은 beta이며 접근 조건, credit, 패키지 버전과 CLI 명령이 바뀔 수 있다. 개강 전 실습실 계정과 공식 문서를 다시 확인한다.
