Week 01 / Orientation

콘텐츠 프로그래밍과 데이터 아트

데이터와 알고리즘을 창작 재료로 쓰는 16주의 출발점을 함께 확인합니다.

오늘의 도착점

코드를 외우기보다 입력과 규칙이 어떻게 콘텐츠가 되는지 설명하고 직접 실행합니다.

  • 이 과목에서 말하는 콘텐츠 프로그래밍을 자신의 말로 설명할 수 있습니다.
  • 생성예술과 데이터 아트 사례에서 입력, 규칙, 출력을 찾아낼 수 있습니다.
  • 자신의 전공과 일상에서 프로젝트로 발전시킬 데이터 후보를 세 가지 이상 찾을 수 있습니다.
  • Google Colab에 접속해 새 노트북을 만들고 첫 코드를 실행할 수 있습니다.

오늘의 흐름

  1. 사전 진단

    프로그래밍 경험과 수강 목표, 관심 매체를 개별 기록합니다.

  2. 강의 개요 및 운영 안내

    강의 목표와 프로젝트를 확인하고 콘텐츠 프로그래밍의 구조를 이해합니다.

  3. 사례 분석

    규칙이 그림을 만드는 장면과 데이터가 감각이 되는 장면을 본 뒤, 같은 구조가 궤적·흐름·방의 빛으로 매체를 바꾸는 방식을 봅니다.

  4. 개인 관심 분야 조사

    일상과 전공에서 프로젝트로 발전시킬 개인 주제 후보를 정리합니다.

  5. 환경 점검

    Google Colab에서 새 노트북을 만들고 첫 코드를 실행합니다.

  6. 수업 정리

    오늘 이해한 개념과 다음 수업 전에 해결할 질문을 기록합니다.

사전 진단 및 수강 목표 확인

출발점 확인

첫 수업의 목적은 학생을 평가하는 것이 아니라 출발점을 확인하는 데 있습니다. 아래 응답은 이후 예시의 난이도와 실습 속도를 조절하고, 학생이 자신의 학습 변화를 확인하는 기준으로 사용합니다.

개별 활동

수강 전 진단

  1. 프로그래밍 경험을 0-3단계로 표시합니다: 0 처음 접함 / 1 예제를 실행해 봄 / 2 예제를 수정해 봄 / 3 작은 결과물을 혼자 만든 경험이 있음.
  2. 사용해 본 제작 도구를 적습니다. 예: Photoshop, Illustrator, After Effects, Blender, Unity, Excel, Processing, p5.js.
  3. 이번 학기에 코드로 다뤄보고 싶은 매체를 두 개 고릅니다: 이미지 / 데이터 / 텍스트 / 소리 / 움직임 / 웹.
  4. “수업이 끝났을 때 나는 ______을 만들 수 있으면 좋겠다”를 한 문장으로 완성합니다.
  5. 프로그래밍 수업에서 가장 걱정되는 점을 한 가지 적습니다.

교수자 진행

응답을 회수하거나 온라인 설문 결과를 확인한 뒤, 경험의 차이는 성취도의 차이가 아니라 출발점의 차이라는 점을 안내합니다. 반복 실행과 수정 과정을 수업의 공통 학습 방식으로 제시합니다.

강의 개요 및 핵심 개념

도입: 일상 속 데이터

수업에 참여하기 전까지의 하루를 떠올려봅니다. 알람을 끈 횟수, 이동 거리, 들은 음악, 보낸 메시지, 감정의 변화처럼 일상에는 다양한 데이터가 존재합니다. 이러한 기록은 콘텐츠 제작의 기초 자료가 될 수 있습니다.

개별 기록

오늘 아침부터 현재까지 생성되거나 관찰된 데이터 세 가지를 기록합니다. 이 단계에서는 정확한 수치보다 기록할 수 있는 대상의 발견에 집중합니다.

콘텐츠 프로그래밍의 정의

콘텐츠 프로그래밍은 코드를 사용해 이미지, 텍스트, 수치, 소리 같은 재료를 변환하고 새로운 표현이나 경험으로 만드는 일입니다. 이 수업에서 코드는 정답을 맞히는 시험 과목이 아니라, 아이디어를 반복해서 시험하고 수정할 수 있게 하는 창작 도구입니다.

Input 재료

숫자, 문장, 사진, 색, 소리, 개인의 기록

→
Rule 변환 규칙

반복, 조건, 정렬, 무작위성, 함수, 매핑

→
Output 콘텐츠

생성 이미지, 포스터, 시각화, 텍스트와 소리 작품

예를 들어 “최근 일주일의 기분”을 입력으로 정하고, 기분이 좋을수록 원을 크게 그리고 피곤할수록 색을 어둡게 만드는 규칙을 세우면, 일주일의 상태를 보여주는 이미지가 출력됩니다. 같은 데이터라도 규칙이 달라지면 전혀 다른 콘텐츠가 됩니다.

같은 데이터, 서로 다른 콘텐츠

데이터가 결과의 형태를 자동으로 결정하지는 않습니다. 제작자는 무엇을 전달할지 먼저 정하고, 그 목적에 맞게 데이터와 시각 요소의 관계를 설계합니다. 같은 일주일의 음악 청취 시간도 아래처럼 서로 다른 결과가 될 수 있습니다.

이 수업에서 중요한 것

처음부터 코드를 외우거나 완벽하게 작성하는 것이 목표가 아닙니다. 실행하기 → 결과 관찰하기 → 한 가지 바꾸기 → 다시 실행하기를 반복하며 코드와 결과의 관계를 이해하는 것이 핵심입니다. 3교시 실습의 속도는 평가하지 않습니다.

공식 사례로 보는 생성예술과 데이터 아트

사례 분석 기준: 입력, 규칙, 출력

코드 기반 작품은 표면적인 인상뿐 아니라 작품을 구성하는 입력, 변환 규칙, 출력의 관계를 함께 살펴보아야 합니다. 아래 세 질문은 이후의 작품 사례 분석에서도 공통 기준으로 사용합니다.

  1. 입력: 작가는 무엇을 재료로 사용했는가?
  2. 규칙: 재료를 어떤 기준으로 선택하고 변환했는가?
  3. 출력: 그 규칙이 어떤 형태와 의미를 만들었는가?

생성예술, 데이터 시각화, 데이터 아트의 차이

세 이름은 작품을 한 상자에 넣으려고 있는 것이 아닙니다. 한 작품이 두 영역에 걸쳐 있을 수 있고, 목적과 강조점이 겹칩니다. 장르를 먼저 붙이지 말고, 무엇이 중심에 있는지를 봅니다. 규칙은 어디서 오는가. 이미 있는 숫자를 쓰는가. 그 숫자를 읽게 하려는가, 경험하게 하려는가.

앞에서 본 일주일의 음악 시간도 이 세 갈래로 갈립니다. 규칙을 발명해 패턴을 만들면 생성예술에 가깝고, 요일별 막대로 비교하면 시각화이며, 듣는 시간의 리듬을 빛이나 소리로 옮기면 데이터 아트입니다. 데이터는 같습니다. 중심이 다릅니다.

생성예술

작가가 완성된 그림을 하나씩 그리지 않습니다. 규칙과 시스템을 설계하고, 컴퓨터가 그 규칙을 반복해서 실행합니다. 선의 각도, 구멍의 위치처럼 사건의 재료를 규칙이 만들어 냅니다. 비행 기록이나 날씨처럼 밖에서 가져온 표가 없어도 이미지가 나옵니다. 물을 질문은 이것입니다. 값을 하나 바꾸면 형태가 어떻게 달라지는가. 4-8주에서 반복, 난수, 조건, 함수로 이 일을 합니다. 바로 아래 사례 1이 이 자리입니다.

데이터 시각화

이미 있는 값을 전제로 합니다. 목적은 감각을 압도하는 것이 아니라 값과 관계를 정확하게 읽게 하는 것입니다. 축, 단위, 범례, 그래프 종류를 고르는 일이 핵심입니다. 화면이 예뻐도 축이 잘리거나 단위가 빠지면 관계는 왜곡됩니다. 물을 질문은 이것입니다. 이 화면에서 크고 작음을 믿을 수 있는가. 바로 아래 사례 2가 이 자리입니다. 9-11주에 데이터 정리와 그래프로 다시 만납니다. 앞에서 본 일주일의 음악 시간 차트가 이쪽입니다.

데이터 아트

시각화처럼 이미 있는 데이터를 재료로 씁니다. 다만 목적은 정확한 비교가 아닙니다. 그 데이터가 어떤 관점과 감각을 만들게 할지를 설계합니다. 숫자를 벽면과 소리로 키우거나, 궤적·바람·심박처럼 다른 매체로 옮깁니다. 차트 한 장으로 줄이면 숫자는 남고 경험이 사라집니다. 물을 질문은 이것입니다. 표로는 보이지 않던 무엇을 이 데이터가 느끼게 하는가. 사례 3이 이 자리입니다.

구분의 방법은 짧습니다. 재료가 규칙에서 태어나면 생성예술 쪽에 가깝습니다. 재료가 이미 있는 숫자이고 읽기가 목적이면 시각화입니다. 같은 숫자라도 경험과 해석이 목적이면 데이터 아트입니다. 아래 사례 1·2·3이 그 순서입니다. 원작은 각 공식 페이지에서 봅니다.

사례 1: 생성예술

컴퓨터가 없어도, 컴퓨터가 있어도, 중심은 같습니다. 규칙을 적고 실행합니다.

François Morellet, 6 répartitions aléatoires… d’après… π

컴퓨터가 없습니다. 제목이 곧 규칙입니다. 패널을 네 칸으로 나누고, π의 짝수·홀수에 따라 검거나 희게 칠합니다. 작가가 칸을 고르지 않습니다. 숫자가 배치를 결정합니다. 생성예술입니다. 4주차 LeWitt 판화와는 다른 작가, 다른 토큰입니다.

Vera Molnár, Interruptions

1968년, 작가는 선을 그리지 않았습니다. 같은 길이의 막대를 격자에 놓고, 각도를 흔들고, 일부를 지우는 규칙만 컴퓨터에 맡겼습니다. 아래는 그 규칙을 지금 이 페이지에서 한 번 실행한 결과입니다. 버튼을 누를 때마다 같은 레시피에서 다른 장이 나옵니다.

규칙 세 줄

  1. 같은 길이의 직선을 격자의 각 칸에 놓는다.
  2. 각 선의 각도를 무작위로 돌린다.
  3. 일부 칸을 지워 구멍을 만든다.

비행 기록이나 날씨처럼 밖에서 가져온 숫자는 없습니다. 사건의 재료를 규칙이 만듭니다. 그래서 이 작품은 데이터 아트가 아니라 생성예술입니다. 이후 주차에서 여러분이 할 일도 같습니다. 선을 예쁘게 배치하는 것이 아니라, 값이 바뀌면 무엇이 변하는지를 적고 실행하는 일입니다.

사례 2: 데이터 시각화

이미 있는 값을 읽게 합니다. 범례가 규칙입니다.

Charles-Joseph Minard, 1812년 러시아 원정

이미 있는 병력·경로·기온을 종이 위에 올립니다. 규칙이 범례에 적혀 있습니다. 1밀리미터가 1만 명입니다. 연한 띠는 진격, 검은 띠는 후퇴. 얼굴도 깃발도 없습니다. 값을 정확하게 읽게 하려는 데이터 시각화입니다. 9-11주에 그래프를 다시 만납니다.

사례 3: 데이터 아트

재료는 시각화와 같이 이미 있는 데이터입니다. 도착지는 표가 아니라 관점과 감각입니다.

Mark Hansen & Ben Rubin, Listening Post

공개 게시판의 문장을 모아, 작은 화면 격자와 합성 목소리로 읽습니다. 표가 아니라 말과 빛입니다. 데이터 아트입니다. 아래는 수업용으로 만든 짧은 문장입니다. 원작의 채팅을 가져오지 않습니다.

Ryoji Ikeda, datamatics

사례 1이 규칙을 발명해 형태를 만든 것과 달리, Ikeda는 이미 있는 데이터를 재료로 삼습니다. 수학, 저장 오류, 나중에는 과학 관측값. 각 픽셀과 소리의 입자가 계산되어 벽면만 한 화면에 쏟아집니다. 표로는 읽을 수 없는 양을, 압도감으로 보여 주는 데이터 아트입니다.

작가는 값을 발명하지 않습니다. 어떤 데이터를 얼마나 빠르고 크게 보여줄지를 설계합니다. 차트 한 장으로 줄이면 숫자는 남고, 몸의 스케일은 사라집니다.

데이터가 매체를 바꾸는 방식

사례 1·2·3이 규칙, 읽기, 경험의 차이를 보여 줬다면, 지금은 장르를 늘리지 않습니다. 같은 입력-규칙-출력이 도착하는 매체만 바꿉니다. 표에 두면 정보입니다. 궤적이 되면 하늘의 시스템이 보이고, 선이 흐르면 공기가 보이며, 전구가 깜빡이면 이 방의 사람이 데이터가 됩니다.

Aaron Koblin, Flight Patterns

땅에서 올려다보면 비행기는 몇 대뿐입니다. 운항 기록을 시간과 좌표에 올리면, 보이지 않던 항공망이 한 장의 흐름이 됩니다. 숫자는 그대로인데 매체가 궤적으로 바뀐 겁니다.

Fernanda Viégas & Martin Wattenberg, Wind Map

바람은 원래 안 보입니다. 격자마다 방향과 속도를 선의 움직임에 옮기면, 예보 표가 초상이 됩니다. 정보를 읽게 하는 지도이면서, 매시간 다시 그려지는 풍경이기도 합니다.

Rafael Lozano-Hemmer, Pulse Room

앞의 두 작품은 파일에 있는 숫자를 씁니다. 이 작품은 관람자의 몸을 입력으로 둡니다. 심박이 전구로 옮겨지고, 다음 사람이 잡히면 이전 리듬은 한 칸 밀립니다. 공간이 사람들을 기억합니다.

세 장면 모두 입력-규칙-출력입니다. 달라진 것은 데이터가 아니라, 그 데이터가 도착한 매체입니다. 이후 주차에서 고를 것도 이것입니다.

수업 후 개별 복습: 개념 확인

이 항목은 수업 중 사례 분석에 포함하지 않습니다. 질문에 먼저 답한 뒤 항목을 열어 핵심 내용을 확인합니다.

1. 생성예술에서 작가는 완성된 이미지 대신 무엇을 만드는가?

생성 조건과 규칙을 설계하고, 가능한 결과 가운데 무엇을 보여줄지 선택합니다. 작가의 역할이 사라지는 것이 아니라 픽셀의 직접 배치에서 시스템의 설계로 이동합니다.

2. datamatics는 왜 데이터 아트인가?

이미 존재하는 숫자와 신호를 재료로 삼아 픽셀과 소리에 대응시키기 때문입니다. 작가는 값을 발명하지 않고, 어떤 데이터를 얼마나 크게 보여줄지를 설계합니다.

3. 같은 데이터에 다른 규칙을 적용하면 의미도 달라질 수 있는가?

그렇습니다. 무엇을 크게 보이고 어떤 값을 묶거나 제외하는지에 따라 독자가 주목하는 관계가 달라집니다. 시각화의 규칙은 정보를 옮기기만 하는 것이 아니라 의미의 읽는 순서를 만듭니다.

4. Interruptions는 왜 데이터 아트가 아닌가?

외부에서 수집한 기록을 그리지 않기 때문입니다. 선의 각도와 구멍은 작가가 만든 규칙이 칸마다 만들어 냅니다. 데이터 아트는 사례 3처럼, 이미 존재하는 숫자를 먼저 재료로 둔 뒤 시각 규칙에 옮깁니다.

  2. 선택한 데이터를 원, 선, 색, 크기, 위치 중 두 가지 시각 요소에 연결합니다.

예: 들은 노래 한 곡을 원 하나로 그린다. 곡이 길수록 원이 커지고, 에너지가 높을수록 채도가 높아진다.

데이터 선택과 표현의 책임

데이터는 현실 전체가 아니라, 누군가가 목적에 따라 선택하고 기록한 현실의 일부입니다. 무엇을 세고 무엇을 제외했는지, 숫자가 어떤 맥락에서 만들어졌는지를 함께 보아야 합니다.

  • 출처: 누가, 언제, 어떤 목적으로 수집했는가?
  • 동의: 다른 사람의 정보가 포함된다면 사용할 권한이 있는가?
  • 표현: 크기와 축, 색의 선택이 사실을 과장하거나 축소하지 않는가?
  • 저작권: 이미지, 텍스트, 음악의 사용 조건과 출처를 확인했는가?
