0-6분 · 5주차 코드는 한 장을 만들지만 아직 다시 쓰기 어렵다

5주차에는 반복문 안에서 크기, 위치, 색상을 선택하고 조건에 따라 세 가지 도형을 그렸습니다. 시드와 설정값을 바꾸면 새로운 결과를 만들 수 있었지만, 이미지를 만드는 전체 과정에는 아직 하나의 이름이 없었습니다.

from PIL import Image, ImageDraw
from IPython.display import display
import random

canvas_width = 600
canvas_height = 600
seed_number = 73
shape_count = 56
min_size = 20
max_size = 80
margin = 40
medium_threshold = 42
large_threshold = 64
background_color = (235, 241, 250)
primary_color = (48, 112, 166)
secondary_color = (92, 150, 118)
accent_color = (230, 83, 72)
outline_color = (35, 42, 55)
palette = [primary_color, secondary_color, accent_color]

image = Image.new(
    "RGB",
    (canvas_width, canvas_height),
    background_color,
)
draw = ImageDraw.Draw(image)
random.seed(seed_number)

for shape_number in range(shape_count):
    size = random.randint(min_size, max_size)
    x = random.randint(margin, canvas_width - margin - size)
    y = random.randint(margin, canvas_height - margin - size)
    base_color = random.choice(palette)

    if size >= large_threshold:
        draw.rectangle(
            (x, y, x + size, y + size),
            fill=accent_color,
            outline=outline_color,
            width=3,
        )
    elif size >= medium_threshold:
        draw.ellipse(
            (x, y, x + size, y + size),
            fill=base_color,
        )
    else:
        draw.ellipse(
            (x, y, x + size, y + size),
            fill=background_color,
            outline=base_color,
            width=4,
        )

display(image)

이 코드는 잘못된 코드가 아닙니다. 다만 새로운 포스터를 세 장 만들려면 설정값을 바꾸고 같은 셀을 여러 번 실행해야 하며, 다른 노트북에서 사용하려면 관련 코드를 다시 찾아 옮겨야 합니다. 6주차의 함수는 이미 작동하는 코드를 버리는 문법이 아니라, 작동하는 코드의 시작과 끝을 정하고 그 작업에 이름을 붙이는 구조입니다.

15-27분 · def는 새로운 작업의 정의를 시작한다

Python에서 자신만의 함수를 만들 때에는 def로 정의를 시작합니다. 다음 함수는 생성 규칙 한 문장을 출력하는 작은 작업입니다.

def announce_rule():
    message = "크기는 무작위로 선택하고 큰 값은 사각형으로 표현한다."
    print(message)

announce_rule()
1def새로운 함수를 정의한다는 Python 키워드입니다.
2announce_rule작업의 목적을 나타내는 함수 이름입니다.
3()함수가 받을 입력의 자리를 표시합니다. 이번 함수에는 입력이 없습니다.
4:다음 줄부터 함수 본문이 시작됨을 알리는 콜론입니다.
5 message = "크기 규칙"네 칸 들여쓴 첫 번째 본문 문장입니다. 문자열을 변수에 저장합니다.
6 print(message)같은 깊이로 들여쓴 두 번째 본문 문장입니다. 저장한 문장을 표시합니다.
7announce_rule()들여쓰기를 끝내고 함수 이름과 괄호로 작업을 호출합니다.

함수의 본문에는 한 줄만 들어갈 수도 있고 여러 줄이 들어갈 수도 있습니다. 중요한 것은 줄 수가 아니라 한 이름으로 부를 만한 하나의 책임을 갖는지입니다. 배경 만들기, 도형 하나 그리기, 포스터 한 장 만들기처럼 결과를 행동으로 설명할 수 있으면 함수 이름도 자연스럽게 정할 수 있습니다.

들여쓰기는 함수에 포함되는 코드의 경계다

def show_start_message():
    print("이미지 생성을 시작합니다.")
    print("설정값을 확인했습니다.")

print("함수 정의가 끝났습니다.")
show_start_message()

앞의 두 print()는 네 칸 들여썼으므로 함수 본문입니다. 세 번째 print()는 왼쪽 끝으로 돌아왔으므로 함수 밖의 코드입니다. 빈 줄은 읽기 쉽게 나눈 것이며 함수의 경계를 결정하지 않습니다. 경계는 들여쓰기 깊이로 결정됩니다.

호출문도 네 칸 들여쓰면 어떻게 되는가?

호출문이 함수 본문 안에 포함됩니다. 함수가 실행되는 동안 자기 자신을 다시 호출하는 재귀 구조가 되어 의도하지 않은 반복과 오류가 생길 수 있습니다. 이번 수업에서는 함수 정의가 끝난 뒤 왼쪽 끝으로 돌아와 호출합니다. 재귀는 이번 학습 범위가 아닙니다.

27-37분 · 정의는 준비이고 호출은 실행이다

def 문장을 실행하면 Python은 함수 이름과 본문을 기억합니다. 그러나 본문 안의 출력이나 도형 그리기를 바로 실행하지는 않습니다. 프로그램이 함수 호출을 만날 때에만 본문으로 이동합니다.

print("1. 프로그램 시작")

def show_generation_step():
    print("3. 함수 본문 실행")

print("2. 함수 정의 완료")
show_generation_step()
print("4. 프로그램 종료")
OUTPUT ORDER

1. 프로그램 시작
2. 함수 정의 완료
3. 함수 본문 실행
4. 프로그램 종료

코드에서 함수 본문이 “2. 함수 정의 완료”보다 위에 적혀 있어도 출력 순서는 3번입니다. Python은 정의 줄에서 본문을 기억한 뒤 건너뛰고, 아래의 호출을 만났을 때 본문으로 돌아갑니다. 본문이 끝나면 호출 다음 줄로 복귀합니다.

위에서 아래로 순서 복원
함수를 수정했는데 이전 결과가 계속 나올 때

정의 셀의 글자만 수정하고 실행하지 않으면 런타임에는 이전 함수가 남아 있습니다. 수정한 정의 셀을 다시 실행한 뒤 호출 셀을 실행합니다. 최종 확인에서는 세션을 다시 시작하고 모두 실행하여 화면의 코드와 런타임 상태를 일치시킵니다.

37-45분 · 고정된 도형 묶음을 함수로 만들기

이제 Pillow 도형 세 개를 하나의 고정 모티프로 묶습니다. 다음 코드는 그대로 실행할 수 있는 완전한 예제입니다.

from PIL import Image, ImageDraw
from IPython.display import display

image = Image.new("RGB", (600, 400), (245, 240, 228))
draw = ImageDraw.Draw(image)

def draw_fixed_motif():
    draw.rectangle(
        (80, 90, 260, 270),
        fill=(230, 83, 72),
        outline=(35, 42, 55),
        width=4,
    )
    draw.ellipse(
        (210, 120, 390, 300),
        fill=(48, 112, 166),
    )
    draw.line(
        (70, 330, 530, 330),
        fill=(35, 42, 55),
        width=8,
    )

draw_fixed_motif()
display(image)

함수의 이름만 보아도 “고정된 모티프를 그리는 작업”임을 알 수 있습니다. 호출문에서는 사각형, 타원, 선의 좌표와 색을 다시 적지 않습니다. 함수 내부의 구체적인 절차를 하나의 이름 뒤에 숨겼기 때문입니다.

함수로 묶기 전과 묶은 뒤의 읽기 차이
구분함수로 묶기 전함수로 묶은 뒤
실행 의도여러 도형 명령을 끝까지 읽어야 파악draw_fixed_motif() 이름으로 먼저 파악
재사용도형 명령 전체를 다시 작성하거나 복사호출문 한 줄을 추가
수정 위치복사한 코드마다 값을 찾아 수정함수 본문 한 곳에서 공통 절차 수정
현재 한계모든 숫자가 고정됨호출해도 같은 위치와 색을 사용함

draw_fixed_motif()를 두 번 호출해도 두 번째 모티프는 첫 번째와 정확히 같은 위치에 그려집니다. 두 모티프가 포개지므로 화면에서는 하나처럼 보입니다. 함수는 재사용을 가능하게 했지만, 아직 호출할 때 위치·크기·색을 바꾸는 방법은 없습니다. 이 한계가 2교시에서 매개변수가 필요한 이유입니다.

호출 결과 확인

draw_fixed_motif() 호출 한 줄을 찾아 표시하고, 호출을 두 번 해도 결과가 하나처럼 보이는 이유를 “함수 안의 좌표가 고정되어 있기 때문”이라고 설명할 수 있으면 완료입니다.

함수를 쓰면 항상 코드가 짧아지는가?

항상 그렇지는 않습니다. 짧은 코드를 함수로 묶으면 전체 줄 수가 잠시 늘어날 수도 있습니다. 함수의 핵심 가치는 줄 수를 줄이는 데만 있지 않습니다. 작업에 이름을 붙이고, 수정 위치를 모으고, 같은 절차를 일관되게 다시 실행할 수 있게 하는 데 있습니다.

함수 정의와 호출에서 자주 발생하는 오류
증상확인할 부분수정 기준
SyntaxErrordef draw_motif() 뒤의 콜론def draw_motif():로 작성

아무 출력도 없음함수 이름만 적고 괄호를 빠뜨렸는지draw_motif()처럼 괄호를 붙여 호출

오류가 보이면 함수 전체를 지우지 않는다

오류 메시지의 마지막 줄에서 오류 종류를 먼저 확인합니다. SyntaxError이면 콜론과 괄호, IndentationError이면 본문의 공백, NameError이면 정의 셀의 실행 여부를 확인합니다. 한 번에 한 원인만 고친 뒤 정의 셀과 호출 셀을 다시 실행합니다.

개별 종료 확인 · 3분

함수의 정의와 호출을 세 문장으로 설명하기

  1. def가 하는 일을 한 문장으로 적습니다.
  2. 정의만 실행했을 때 함수 본문이 실행되지 않는 이유를 적습니다.
  3. 같은 함수를 세 번 호출하면 본문이 몇 번 실행되는지 적습니다.
종료 확인 기준 답안
  1. def는 함수 이름과 들여쓴 본문을 하나의 작업으로 정의합니다.
  2. 정의는 실행 준비이며 본문은 호출을 만났을 때 실행되기 때문입니다.
  3. 호출이 세 번이면 함수 본문도 세 번 실행됩니다.
