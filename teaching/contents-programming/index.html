강의 개요 Course overview

본 강의는 Python과 Google Colab을 활용하여 데이터와 알고리즘을 기반으로 다양한 디지털 콘텐츠를 기획하고 제작하는 이론·실습 중심의 교과목이다. 프로그래밍 경험이 없는 인문학, 음악, 미술, 디자인 및 기타 전공 학생들도 참여할 수 있도록 Python의 기초 개념부터 단계적으로 학습한다. 변수, 자료형, 조건문, 반복문, 리스트, 함수 등의 프로그래밍 문법을 단순히 암기하는 방식에서 벗어나 도형, 색상, 이미지, 텍스트, 수치, 소리 등의 재료를 활용한 창작 활동을 통해 자연스럽게 이해하도록 구성한다. 학생들은 좌표와 색상의 원리를 바탕으로 디지털 이미지를 제작하고, 반복과 무작위성, 조건과 매개변수를 활용하여 실행할 때마다 서로 다른 결과가 만들어지는 생성예술의 원리를 학습한다. 또한 기존 이미지를 불러와 자르기, 크기 변경, 픽셀 변형 및 합성 등의 작업을 수행하며 디지털 이미지가 데이터로 구성되는 방식을 이해한다.

수업의 후반부에는 개인의 일상, 전공, 사회적 관심사와 관련된 데이터를 직접 수집하거나 공개된 자료를 활용하여 데이터를 정리하고 분석하며, 이를 시각적 콘텐츠로 변환하는 방법을 학습한다. 수치 데이터뿐만 아니라 시, 소설, 가사, 대사 등의 텍스트 자료와 음악, 목소리 등의 소리 자료도 데이터로 해석하여 새로운 이미지와 시각적 표현으로 발전시킨다. 매주 1·2교시에는 생성예술, 데이터 아트, 정보 시각화의 주요 개념과 사례를 살펴보고 코드의 구조와 표현 원리를 이해한다. 3교시에는 해당 개념을 Python 코드와 개인 창작 결과물로 구현한다. 이 과정에서 데이터의 선택과 해석, 개인정보, 저작권, 시각화의 왜곡 등 디지털 콘텐츠 제작자가 고려해야 할 윤리적 문제도 함께 다룬다. 중간 프로젝트에서는 규칙 기반의 생성 이미지 또는 포스터 시리즈를 제작하고, 기말 프로젝트에서는 자신의 전공이나 관심 분야를 데이터와 알고리즘으로 재해석한 독창적인 디지털 콘텐츠를 기획, 제작하고 발표한다.

강의 목표 Course goals

본 강의는 학생들이 Python 프로그래밍의 기본 개념과 구조를 이해하고 이를 자신의 아이디어를 구현하기 위한 창작 도구로 활용할 수 있도록 하는 것을 목표로 한다. 학생들은 컴퓨터에 명령을 전달하는 방식과 프로그램이 정보를 처리하는 과정을 이해하고, 복잡한 아이디어를 작은 규칙과 단계로 나누어 설계하는 컴퓨테이셔널 사고 능력을 기른다. 변수, 자료형, 조건문, 반복문, 리스트 및 함수 등의 기초 문법을 이미지 생성과 데이터 시각화 실습에 적용함으로써 프로그래밍 개념과 실제 결과물 사이의 관계를 이해한다. 좌표, 색상, 형태, 반복, 우연성, 매개변수 등의 요소를 이용하여 하나의 결과물을 직접 만드는 것에서 나아가 다양한 결과를 지속적으로 생성할 수 있는 규칙과 시스템을 설계한다.

이미지, 텍스트, 수치, 소리 등 서로 다른 형식의 자료를 수집하고 정리하며, 자료가 가진 특징을 시각적 요소로 변환하는 과정을 경험한다. 또한 생성예술과 데이터 아트, 정보 시각화의 주요 작품을 분석하여 작품에 적용된 알고리즘과 데이터의 역할을 파악하고, 기술적 구조와 예술적 표현이 결합되는 방식을 탐구한다. 학생들이 자신의 전공 지식, 개인적 경험 및 사회적 관심사를 프로그래밍 프로젝트의 주제로 발전시켜 각자의 전공적 특성이 반영된 결과물을 제작하도록 한다. 제작 과정에서 발생하는 오류와 예상하지 못한 결과를 새로운 가능성을 발견하고 문제를 해결하는 과정으로 받아들이며, 데이터의 수집과 선택, 표현 방식에 따라 의미가 달라질 수 있음을 이해한다. 최종적으로 작품의 기획 의도와 데이터의 의미, 알고리즘의 작동 원리 및 제작 과정을 스스로 설명하고 교수자의 피드백을 반영하여 프로젝트를 수정하고 완성하는 능력을 기르는 것을 목표로 한다.

학습 성과 Learning outcomes

본 강의를 이수한 학생은 Google Colab의 기본 환경을 이해하고 Python 코드를 작성, 실행, 수정하며 자신의 노트북 파일을 저장하고 공유할 수 있다. 변수와 자료형, 조건문, 반복문, 리스트 및 함수 등의 기초 프로그래밍 문법을 이해하고 이를 활용한 간단한 프로그램을 독립적으로 작성할 수 있다. 디지털 이미지의 좌표, 픽셀 및 RGB 색상 구조를 이해하고 도형, 색상, 크기와 배치를 조절하여 시각적 결과물을 생성할 수 있으며, 반복과 난수, 조건 및 매개변수를 활용하여 실행할 때마다 일정한 규칙 안에서 서로 다른 결과가 생성되는 이미지 시스템을 설계할 수 있다. 외부 이미지를 프로그램으로 불러와 자르기, 크기 변경, 색상 조절, 픽셀 변형 및 이미지 합성 등의 작업을 수행하고 결과물을 적절한 파일 형식으로 저장할 수 있다.

CSV 등의 데이터 파일을 Colab으로 불러오고 필요한 정보를 정렬, 필터링, 분류 및 요약하여 시각화에 적합한 형태로 가공할 수 있다. 데이터의 특성과 표현 목적에 따라 색상, 형태, 위치, 크기 및 배치 등의 시각 요소를 선택하여 데이터 포스터 또는 시각화 작품으로 제작할 수 있으며, 시·소설·가사·대사 등의 텍스트 자료와 음악·목소리 등의 소리 자료를 데이터로 해석해 이미지 또는 그래프로 변환할 수 있다. 생성예술과 데이터 시각화 작품에 사용된 규칙과 표현 방식을 분석하고 데이터의 출처와 신뢰성, 개인정보, 저작권 및 시각화의 윤리적 문제를 비판적으로 검토할 수 있다. 또한 자신이 작성한 코드의 핵심 구조와 작동 원리를 설명하고 오류를 찾아 수정하며, 피드백을 반영하여 결과물을 개선할 수 있다. 최종적으로 자신의 전공 또는 관심 분야와 관련된 자료를 선정하고 이를 데이터와 알고리즘을 활용한 디지털 콘텐츠로 기획, 제작, 발표할 수 있다.

이미지를 변형·합성해 중간 프로젝트 프로토타입 만들기

6주차 연결 create_poster()로 생성한 세 이미지를 완성품이 아니라 다시 사용할 수 있는 시각 재료로 불러온다. 자신의 6주차 결과물이 없으면 수업에서 제공하는 대체 이미지를 사용해 같은 학습 목표를 수행한다.

1교시 · 원본을 보존하며 이미지 변형하기 ↗ Image.open()으로 파일을 불러오고 copy(), crop(), resize(), rotate()가 각각 새 이미지 객체를 만드는 흐름을 읽는다. 원본·작업본·결과물을 다른 변수와 파일명으로 구분하고, 자르기 좌표·가로세로 비율·회전 후 경계가 결과에 미치는 영향을 비교한다.

2교시 · RGBA 레이어 합성과 책임 있는 이미지 이용 ↗ RGB와 RGBA의 차이, 알파 값의 투명도, 캔버스와 레이어의 크기·위치·쌓이는 순서를 이해하고 alpha_composite()로 여러 이미지를 합성한다. 외부 이미지는 변형과 재이용이 허용된 자료인지 먼저 확인하고, 제목·창작자·원본 주소·라이선스·변형 내용을 노트북에 기록한다.

3교시 · 목표 달성형 개인 실습 ↗ 6주차 결과물 또는 대체 이미지에서 작업본을 만들고, 자르기·크기 변경·회전을 적용한 변형 레이어 세 개 이상을 1000 × 1000 RGBA 캔버스에 합성한다. 프로토타입 PNG를 저장하고 새 세션 전체 실행에서 자동 검사 PASS를 받은 뒤 Colab 노트북과 PNG 두 파일 제출을 완료하면 즉시 귀가한다.

Week 09Data as material

중간 프로젝트에서 데이터 아트로: 관찰을 표로 바꾸기

8주차 연결 중간고사에서 제작한 생성 포스터 시리즈를 결과 이미지로만 보지 않고, 각 포스터에 사용한 매개변수인 시드·도형 수·크기 기준·팔레트와 관찰된 결과를 하나의 기록으로 다시 읽는다. 포스터 한 장을 한 행, 비교할 항목을 열로 놓아 이미지 생성 경험을 표 데이터의 구조와 연결한다.

1교시 · 데이터는 발견되는가, 만들어지는가 강의 자료 ↗ · 데이터가 주어진 사실의 묶음이 아니라 질문에 따라 대상을 관찰하고 기준을 정해 기록한 결과임을 이해한다. 관찰 단위, 변수, 값, 메타데이터를 일상의 기록 예시로 구분한다. Dear Data와 The Library of Missing Datasets를 비교하여 무엇을 기록했는지뿐 아니라 누가 무엇을 선택했고 무엇을 누락했는지 살피며, 데이터가 완전히 중립적인 재료가 아님을 개별 관찰 질문으로 확인한다.

2교시 · CSV와 DataFrame의 구조 읽기 강의 자료 ↗ · 쉼표로 값을 구분하는 CSV 파일과 pandas의 DataFrame을 처음 접하고 행, 열, 헤더, 인덱스, 셀의 역할을 실제 표와 연결한다. 수치, 범주, 문자열, 날짜 자료형과 결측값을 구분하고 pd.read_csv(), head(), shape, columns, dtypes, isna().sum()의 출력으로 파일의 앞부분·크기·열 이름·자료형·빈 값을 차례대로 점검한다. 이번 주에는 시각화와 통계 계산보다 데이터가 무엇을 담고 있는지 정확히 설명하는 데 집중한다.

이번 주 완료 기준 · 30% 프로토타입 30%는 화면을 30%만 꾸몄다는 뜻이 아니다. 승인된 입력 자료 하나 → 원본 보존 → 처리 규칙 하나 → 핵심 시각화 규칙 하나 → 열리는 결과 파일 하나가 처음부터 끝까지 이어지는 최소 작동 경로를 뜻한다. 노트북에는 프로젝트 질문, 예상 독자, 자료 출처와 이용 조건, 입력 한 건 또는 한 행의 의미, 결과에서 확인한 관찰 한 문장, 아직 단정할 수 없는 한계 한 문장, 15주차에 수행할 두 가지 수정 항목을 기록한다. 새 런타임에서 전체 셀을 순서대로 실행했을 때 같은 미리보기가 다시 생성되어야 한다.

1교시 · 아이디어를 제작 가능한 프로젝트 문장으로 바꾸기 0–6분에는 13주차 기획 문서와 기말 완성작 사이에 남은 일을 입력·처리·표현·설명·저장의 다섯 항목으로 나누어 본다. 6–14분에는 “어떤 기술을 쓰겠다”는 도구 목록과 “누구에게 어떤 자료의 무엇을 보여 주겠다”는 프로젝트 문장을 비교하고, 질문·예상 독자·입력 자료·최종 결과물의 네 요소를 한 문장으로 묶는다. 14–24분에는 세 가지 축소 사례를 분석한다. 공공문화시설 전체를 설명하려던 계획은 한 범주의 프로그램 수 비교로, 긴 소설 전체를 해석하려던 계획은 저작권을 확인한 짧은 텍스트의 반복 단어와 문장 흐름으로, 실시간 공연 시스템 전체를 만들려던 계획은 사용 권한이 있는 짧은 소리의 파형과 에너지 변화로 줄인다. 각 사례에서 무엇을 포기했기 때문에 핵심 질문이 더 선명해졌는지 확인한다. 24–34분에는 입력 한 건이 무엇을 뜻하는지, 어떤 열·토큰·소리 구간을 사용할지, 그 값을 위치·길이·색상·크기·시간 순서 가운데 무엇으로 번역할지 정한다. 시각화가 직접 보여 주는 사실과 자료만으로 단정할 수 없는 해석을 분리한다. 34–43분에는 기능을 이번 주에 반드시 작동할 핵심, 15주차에 개선할 보완, 시간이 남을 때만 시도할 확장으로 나눈다. 자료가 열리지 않거나 구현이 막힐 때 사용할 수업 제공 대체 자료와 더 단순한 표현 방식도 함께 정한다. 43–50분에는 13주차 기획 문서를 바탕으로 프로젝트 질문, 독자, 입력과 출처, 처리 규칙, 시각화 규칙, 결과 형식, 가장 큰 위험 한 가지를 프로젝트 카드에 기록하고 2교시 면담용 초안을 완성한다.

2교시 · 코드 구조와 검증 기준을 세우고 1차 면담 시작하기 0–7분에는 서로 다른 프로젝트도 불러오기 → 원본 보존 → 정리·분석 → 시각 요소로 변환 → 저장이라는 공통 구조를 가진다는 점을 9–13주차 결과물로 확인한다. 7–17분에는 노트북 셀을 준비, 입력 확인, 처리, 시각화, 저장, 최종 점검의 여섯 구역으로 나누고 각 구역이 하나의 질문에만 답하도록 설계한다. 새로운 라이브러리를 늘리기보다 이미 수업에서 실행해 본 코드 가운데 필요한 부분을 복사한 뒤 변수 이름과 입력만 자신의 프로젝트에 맞게 바꾼다. 17–27분에는 정상 작동을 눈대중으로 판단하지 않도록 입력 수, 필수 열 또는 샘플 수, 결측값, 변환 전후 개수, 그래프 요소 수, 출력 크기와 파일 존재 여부를 확인하는 검증 문장을 정한다. 소리나 인터랙티브 결과처럼 한 장의 수치로 충분하지 않은 경우에는 재생·조작 방법과 육안 확인 항목을 함께 기록한다. 27–35분에는 출처·작성자 또는 제공자·이용 조건·수집 시점·개인정보 제거 여부를 입력 자료 옆에 기록하고, 결과 화면에도 독자가 확인할 수 있는 출처와 해석의 한계를 배치한다. 자료 이용이 불확실하면 기술 구현을 계속하기 전에 수업 제공 대체 자료로 전환한다. 35–50분에는 교수자가 프로젝트 카드를 학생별로 확인하여 승인, 범위 축소 후 승인, 대체 자료로 전환 가운데 하나를 기록한다. 질문과 입력의 대응, 한 주 안에 구현 가능한 범위, 자료 이용 권한, 결과 형식을 60–90초 단위로 점검하며, 대기 학생은 자신의 여섯 구역 셀 제목과 검사 기준을 먼저 작성한다. 면담이 끝나지 않은 학생은 3교시 제작 중 같은 순서로 확인받는다.

3교시 · 목표 달성형 개인 실습: 30% 프로토타입 완성 0–5분에는 개인 노트북 사본을 만들고 week14_학번_이름_prototype.ipynb로 저장한다. 프로젝트 카드와 승인·축소·대체 자료 중 자신의 면담 결정은 노트북 첫 부분에 기록하며 별도의 기획 파일은 제출하지 않는다. 5–12분에는 승인된 입력을 불러오고 원본을 별도 변수에 보존하며 제목, 출처, 이용 조건, 관찰 단위를 기록한다. 입력 파일을 별도로 사용한다면 week14_학번_이름_source.확장자로 저장하고 노트북과 함께 다시 열 수 있는 승인된 파일인지 확인한다. 12–22분에는 집계·필터링·토큰 빈도·소리 에너지 계산·생성 매개변수 적용 가운데 프로젝트 질문에 필요한 처리 규칙 하나를 구현하고 처리 전후의 개수를 출력한다. 22–32분에는 값 하나 이상을 위치·길이·색상·크기·시간 순서에 연결하여 핵심 시각화 한 화면을 완성한다. 장식 기능을 추가하기 전에 축·범례·단위·재생 또는 조작 안내가 실제 입력과 일치하는지 확인한다. 32–38분에는 결과를 week14_학번_이름_preview.png 또는 week14_학번_이름_preview.html로 저장하고, 노트북 밖에서 직접 열어 글자 잘림·빈 화면·누락된 요소가 없는지 점검한다. 38–44분에는 새 런타임에서 전체 셀을 실행하여 입력, 처리 결과, 그래프 요소, 출력 파일의 공통 자동 검사 PASS를 확인한다. 자동 검사는 파일 존재와 수치 일관성을 확인하며 질문의 의미와 시각적 완성도는 대신 판단하지 않는다는 점을 명시한다. 44–48분에는 미리보기에서 확인한 관찰 한 문장, 현재 자료의 한계 한 문장, 15주차에 실행할 수정 두 가지를 구체적인 동사로 작성하고 교수의 범위 확인을 받는다. 48–50분에는 실행 결과가 남은 노트북과 열리는 PNG 또는 HTML을 제출한다. 외부 입력이 노트북에 포함되지 않았다면 재실행에 필요한 입력 파일도 함께 제출한다. 공통 자동 검사 PASS, 결과 파일 열림, 출처 확인, 교수 범위 확인, 필수 파일 제출을 모두 마친 학생은 즉시 귀가한다.

선택 확장 · 두 번째 표현을 더하기 전에 비교 질문 세우기 필수 프로토타입을 별도 파일로 보존한 뒤 같은 입력을 다른 그래프나 상호작용으로 표현하고, 새 표현이 기존 결과에서 보이지 않던 무엇을 보여 주는지 두 문장으로 비교한다. 단순한 장식 추가나 라이브러리 교체는 확장으로 인정하지 않으며, 선택 확장은 필수 귀가 조건과 추가 점수에 포함하지 않는다.

15주차 연결 1차 면담에서 승인된 질문과 최소 작동 경로는 유지하고, 이번 주에 기록한 두 가지 수정 항목을 15주차 제작의 시작점으로 삼는다. 15주차에는 입력 전체가 안정적으로 처리되는지 확인하고, 빠진 설명과 오류 처리를 보완하며, 색상·위계·레이아웃을 정리해 70% 프로토타입으로 발전시킨다. 주제를 처음부터 바꾸기보다 자료 이용 문제나 구현 불가능성이 확인된 경우에만 변경 이유와 새 범위를 교수와 다시 합의한다.
