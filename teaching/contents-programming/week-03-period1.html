오늘의 학습 목표

  • 래스터 이미지를 색상 값을 가진 픽셀의 격자로 설명할 수 있습니다.
  • 이미지의 가로와 세로 크기, 전체 픽셀 수를 구분하고 계산할 수 있습니다.
  • 왼쪽 위 원점과 x는 오른쪽, y는 아래쪽으로 증가하는 좌표 규칙을 사용할 수 있습니다.
  • 이미지의 크기와 실제로 사용할 수 있는 마지막 픽셀 좌표를 구분할 수 있습니다.
  • 2주차의 변수와 정수 자료형이 이미지의 크기와 위치를 표현하는 방식과 연결됨을 설명할 수 있습니다.
  • =, (), ,, .처럼 이미지 코드에 반복해서 나오는 기호를 말로 풀어 읽을 수 있습니다.
  • 0-5 min이전 학습과 기호

    =, 괄호, 쉼표를 다시 읽고 이미지 데이터로 범위를 넓힙니다.

  • 5-18 min이미지의 구조

    래스터 이미지, 픽셀, 해상도의 관계를 정리합니다.

  • 18-29 min이미지 좌표

    원점과 축 방향을 확인하고 좌표를 읽습니다.

  • 29-39 min크기와 계산 기호

    width, height, 마지막 주소와 *, -, //를 구분합니다.

  • 39-47 min첫 이미지 코드

    변수, print(), 점, Image.new()를 한 조각씩 읽습니다.

  • 47-50 min개념 확인

    좌표 예측 문제와 한 문장 정리로 2교시를 준비합니다.

두 가지 운영 시간

50분 교시에서는 픽셀 격자, 왼쪽 위 원점, 유효 좌표 범위, 첫 이미지 코드까지 진행합니다. 60분 교시에서는 본문 마지막의 50-60분 확장 활동까지 이어서 좌표로 실제 화면 구성을 설계합니다. 본문은 강사가 별도의 설명을 덧붙이지 않아도 핵심 논리가 이어지도록 작성되어 있습니다.

코드를 처음 보는 학생을 위한 진행 원칙

  1. 처음부터 외우지 않습니다. 먼저 제공된 코드를 보고, 한 줄이 하는 일을 우리말로 설명합니다.
  2. 한 줄 전체를 한꺼번에 보지 않습니다. 변수 이름, 기호, 값처럼 작은 조각으로 나누어 읽습니다.
  3. =이 있으면 오른쪽부터 봅니다. 오른쪽 값을 준비한 뒤 왼쪽 이름에 기억한다고 읽습니다.
  4. 괄호 안은 필요한 재료입니다. 쉼표는 여러 재료의 경계를 구분합니다.
  5. 오류는 실패 판정이 아닙니다. Python이 이해하지 못한 위치나 아직 준비되지 않은 이름을 알려주는 안내문입니다.

0-5분 · 한 개의 값에서 이미지 데이터로

2주차에는 이름, 시간, 평점처럼 하나의 값을 변수에 저장했습니다. 이번 주에는 같은 생각을 이미지로 확장합니다. 디지털 이미지는 컴퓨터가 한 번에 이해하는 그림 덩어리가 아니라, 위치와 색상 값을 가진 수많은 작은 데이터의 모음입니다.

사람은 이미지를 보는 순간 인물, 풍경, 분위기와 같은 전체적인 의미를 먼저 파악합니다. 컴퓨터가 이미지를 처리할 때에는 출발점이 다릅니다. 컴퓨터는 “따뜻한 저녁 풍경”이라는 인상을 직접 저장하는 대신, 이미지의 크기, 각 픽셀의 위치, 그 위치의 색상 값을 다룹니다. 우리가 감상하는 하나의 장면을 계산 가능한 작은 단위로 나누는 것이 이번 시간의 핵심입니다.

이 관점은 창작의 자유를 줄이는 것이 아니라 오히려 새로운 조절 가능성을 만듭니다. 위치가 숫자라면 형태를 정확히 이동할 수 있고, 크기가 숫자라면 같은 비율로 확대할 수 있으며, 색상이 숫자라면 여러 색의 차이를 체계적으로 설계할 수 있습니다. 코드는 그림을 대신 그리는 자동화 장치가 아니라, 시각적 결정을 명시적인 규칙으로 기록하는 매체가 됩니다.

Week 02 / one value 
favorite_color = "blue"

좋아하는 색을 하나의 문자열 값으로 저장합니다.

Week 03 / many values 
position = (2, 1)
color = (40, 110, 230)

한 픽셀은 위치와 색상이라는 여러 숫자로 설명할 수 있습니다.

가장 짧은 코드부터 조각내어 읽기

favorite_color = "blue"를 처음 보았을 때 영어 문장처럼 처음부터 끝까지 읽으려고 하면 어렵게 느껴질 수 있습니다. Python의 대입문은 오른쪽 값을 먼저 확인하고, 그 값을 왼쪽 이름으로 기억하는 순서로 읽습니다.

favorite_color = "blue"의 네 조각
코드 조각이름초심자의 읽는 방법
favorite_color변수 이름나중에 값을 다시 찾기 위해 우리가 붙인 이름
_밑줄변수 이름에 공백을 쓸 수 없어서 두 단어를 연결하는 기호
=대입 기호오른쪽 값을 왼쪽 이름으로 기억하라는 표시
"blue"문자열 값따옴표 안의 글자 blue를 데이터로 사용

이 줄을 실행하면 화면에 blue가 바로 나타나는 것이 아닙니다. Python의 실행 공간에 favorite_color → "blue"라는 연결이 생깁니다. 값을 화면에서 확인하려면 다음 줄에 print(favorite_color)처럼 출력 명령을 사용합니다.

favorite_color = "blue"
print(favorite_color)
blue

괄호와 쉼표가 보일 때의 첫 번째 해석

position = (2, 1)의 괄호는 위치에 필요한 두 값을 한 묶음으로 만듭니다. 쉼표 앞의 2는 x, 뒤의 1은 y입니다. color = (40, 110, 230)도 같은 방식으로 세 색상 값을 순서대로 묶습니다. 지금은 ‘튜플’이라는 용어를 외우기보다 괄호 안에 순서가 있는 여러 값이 들어 있다고 읽으면 충분합니다.

개별 생각 · 2분

파란 점 하나를 컴퓨터에 알려주려면?

빈 화면에 파란 점 하나를 정확히 표시하려고 합니다. 컴퓨터에 알려줘야 할 정보를 두 종류로 나누어 적습니다.

  • 어디에: 화면 안의 위치
  • 어떤 모습으로: 점의 색상
왜 “왼쪽 위쯤 파란색”만으로는 부족할까?

컴퓨터에는 “쯤”을 처리할 공통 기준이 없습니다. 사람마다 떠올리는 범위도 다릅니다. 위치를 나타내는 좌표와 색상을 나타내는 수치처럼 실행 가능한 데이터로 바꾸어야 같은 명령이 같은 결과를 만듭니다. 정확한 수치는 표현을 제한하는 규칙이 아니라, 의도한 결과를 반복하고 수정하고 비교하기 위한 공통 언어입니다.

5-18분 · 디지털 이미지는 픽셀의 격자다

픽셀, 래스터 이미지, 해상도

디지털 이미지의 기본 용어
용어뜻이번 수업의 예
픽셀래스터 이미지 안에서 하나의 위치와 색상 값을 가지는 가장 작은 주소 단위(2, 1) 위치의 파란색 칸
래스터 이미지픽셀이 가로와 세로의 격자로 배열된 이미지사진, PNG, JPEG처럼 픽셀로 저장되는 이미지
해상도이미지를 구성하는 가로 픽셀 수 × 세로 픽셀 수800 × 600 픽셀
색상 값각 픽셀이 어떤 색으로 보일지 나타내는 데이터2교시에서 배울 (R, G, B)

픽셀을 단순히 “아주 작은 네모”라고만 이해하면 중요한 특징을 놓칠 수 있습니다. 핵심은 모양보다 주소를 가진 데이터 단위라는 점입니다. 각 픽셀은 격자 안에서 자신의 위치를 가지며, 그 위치에는 색상 정보가 저장됩니다. 이미지를 확대했을 때 네모난 칸이 보이는 이유는 연속된 장면을 유한한 수의 격자로 나누어 기록했기 때문입니다.

이미지의 한 부분을 수정한다는 말은 결국 특정 좌표에 저장된 색상 값을 바꾼다는 뜻입니다. 붓으로 선을 긋는 명령도 내부적으로는 선이 지나가는 여러 픽셀의 값을 갱신합니다. 원을 그리는 명령 역시 완성된 원 모양을 이미지에 붙이는 것이 아니라, 원의 내부와 경계에 해당하는 픽셀을 계산해 새로운 색으로 기록합니다.

800 × 600 이미지는 가로 800칸, 세로 600칸으로 이루어진 격자입니다. 전체 픽셀 수는 800 * 600, 즉 480,000개입니다. 픽셀 수가 많을수록 항상 좋은 작품이 되는 것은 아니지만, 같은 크기로 확대했을 때 더 세밀한 정보를 담을 수 있습니다.

래스터와 벡터는 이미지를 기록하는 출발점이 다르다

오늘 다루는 Pillow는 래스터 이미지를 처리합니다. 래스터는 각 위치의 픽셀 값을 기록합니다. 반면 벡터 그래픽은 선, 곡선, 도형의 수학적 관계를 기록합니다. 두 방식 가운데 하나가 항상 우수한 것은 아닙니다. 사진처럼 미세한 색 변화가 많은 장면은 래스터가 자연스럽고, 로고처럼 크기를 자주 바꾸는 단순한 형태는 벡터가 유리합니다.

래스터 이미지와 벡터 그래픽의 구조 비교
구분래스터 이미지벡터 그래픽
기록 단위좌표마다 저장된 픽셀의 색상 값점, 선, 곡선, 도형을 만드는 수학적 명령
확대할 때원래 픽셀 수보다 크게 표시하면 경계가 거칠어질 수 있음도형을 다시 계산하므로 다양한 크기에서 선명하게 표현 가능
적합한 예사진, 회화 스캔, 픽셀 아트, Pillow 결과 이미지로고, 아이콘, 다이어그램, 글자 윤곽선
대표 형식PNG, JPEGSVG
이번 주의 초점좌표와 RGB 값으로 픽셀을 생성개념 비교만 하고 직접 제작하지 않음

같은 원인데 왜 확대 결과가 다를까?

래스터 파일의 원은 이미 정해진 격자 안의 픽셀 값으로 저장되어 있습니다. 크게 확대하면 기존 픽셀도 함께 커집니다. 벡터 파일의 원은 중심과 반지름 같은 관계로 저장되어 있어 새로운 크기에 맞추어 경계를 다시 계산할 수 있습니다. 이번 주에는 Pillow가 계산한 도형을 최종적으로 래스터 픽셀에 기록합니다.

해상도, 표시 크기, 파일 용량은 서로 다른 값이다

초심자가 자주 혼동하는 세 가지 값이 있습니다. 해상도는 이미지가 실제로 가진 픽셀의 개수이고, 표시 크기는 그 이미지를 현재 화면이나 문서에서 얼마나 크게 보여주는지이며, 파일 용량은 저장 장치에서 차지하는 바이트의 양입니다.

이미지의 크기를 말할 때 구분해야 하는 세 기준
기준질문예달라지는 요인
픽셀 해상도몇 개의 픽셀로 이루어졌는가?800 × 600픽셀가로·세로 픽셀 수
표시 크기지금 화면에서 얼마나 크게 보이는가?웹페이지에서 가로 400픽셀로 표시브라우저, CSS, 화면 배율
파일 용량저장할 때 몇 바이트를 차지하는가?82KB 또는 1.2MB파일 형식, 압축 방식, 이미지 내용

예를 들어 800 × 600 이미지를 웹페이지에서 가로 400픽셀로 표시해도 원본이 가진 픽셀 수는 그대로입니다. 반대로 작은 원본을 크게 표시하면 화면에서 차지하는 공간은 커지지만 새로운 세부 정보가 저절로 생기지는 않습니다. 따라서 “크게 보인다”와 “많은 픽셀을 가진다”를 같은 뜻으로 사용해서는 안 됩니다.

한 장의 이미지는 얼마나 많은 숫자를 가지는가

800 × 600 이미지에는 480,000개의 픽셀이 있습니다. 2교시에서 배울 RGB 이미지는 픽셀마다 빨강, 초록, 파랑의 세 값을 가지므로, 단순하게 세어도 480000 * 3, 즉 1,440,000개의 채널 값을 다룹니다. 우리가 화면에서 즉시 보는 한 장의 이미지 뒤에는 이처럼 많은 수치 데이터가 놓여 있습니다.

계산된 데이터 양과 실제 파일 용량은 같지 않다

RGB 채널 값의 개수는 이미지 구조를 이해하기 위한 계산입니다. PNG와 JPEG 같은 파일은 픽셀 정보를 각기 다른 방식으로 압축하므로 실제 파일 용량은 이미지 내용과 저장 방식에 따라 달라집니다. 가로 × 세로 × 3의 결과를 그대로 PNG 파일 용량이라고 해석하지 않습니다.

픽셀은 화면에서 항상 같은 크기로 보이지 않는다

이미지를 확대하면 한 픽셀이 큰 네모처럼 보이고 축소하면 여러 픽셀이 한데 모여 보입니다. 이미지의 픽셀 수와 웹페이지나 화면에서 보이는 표시 크기는 서로 다른 개념입니다.

18-29분 · 이미지 안의 위치는 좌표로 찾는다

왼쪽 위가 원점이고 y는 아래로 증가한다

Pillow를 포함한 일반적인 이미지 처리 환경에서는 왼쪽 위 픽셀을 원점 (0, 0)으로 사용합니다. 첫 번째 숫자 x는 오른쪽으로 갈수록 커지고, 두 번째 숫자 y는 아래로 갈수록 커집니다.

print("point_x")는 저장된 120을 찾지 않고 point_x라는 글자를 그대로 출력합니다. 변수의 현재 값을 확인할 때에는 print(point_x)처럼 변수 이름을 따옴표 밖에 작성합니다.

여기서 변수명은 단순한 약어가 아니라 시각적 의도를 설명합니다. x1, a, number만으로도 코드는 실행될 수 있지만, 시간이 지난 뒤 그 값이 캔버스의 너비인지 점의 위치인지 다시 해석해야 합니다. canvas_width와 point_x처럼 역할이 드러나는 이름을 사용하면 코드가 곧 작업 기록이 됩니다.

from PIL import Image

생성한 이미지의 구조를 코드로 확인하기

이미지가 만들어졌다면 눈으로만 확인하지 않고, 코드가 기억한 속성을 직접 출력할 수 있습니다. size는 가로와 세로 크기, mode는 픽셀의 데이터 구조, getbands()는 이미지가 가진 채널의 이름을 보여줍니다.

여기서 점 .은 소수점이 아닙니다. image.size는 “image가 가진 size 정보를 찾는다”, image.getbands()는 “image가 제공하는 getbands 기능을 실행한다”라고 읽습니다. 괄호가 없는 정보와 괄호가 있는 기능을 다음처럼 구분합니다.

print("크기:", image.size)
print("모드:", image.mode)
print("채널:", image.getbands())
크기: (400, 300)
모드: RGB
채널: ('R', 'G', 'B')
이미지 객체에서 확인할 세 가지 정보
확인 코드괄호출력해석
image.size없음(400, 300)이미지가 이미 가진 크기 정보를 읽음
image.mode없음RGB이미지가 이미 가진 모드 정보를 읽음
image.getbands()있음('R', 'G', 'B')채널 이름을 돌려주는 기능을 실행

점을 기준으로 앞뒤 순서를 바꾸지 않는다

image.size에서 점 앞의 image는 확인할 대상이고, 점 뒤의 size는 그 대상에서 찾을 정보입니다. size.image처럼 순서를 뒤집으면 같은 의미가 되지 않습니다. 영어 문장으로 외우기보다 “대상.정보” 또는 “대상.기능()” 구조로 읽습니다.

이 확인 과정은 오류를 찾을 때도 유용합니다. 예상한 크기와 실제 image.size가 다르면 이미지 생성 셀의 값을 확인해야 합니다. 색상 튜플을 세 값으로 작성했는데 이미지 모드가 RGB가 아니라면, 어떤 모드로 이미지를 만들었는지 다시 살펴볼 수 있습니다. 추측보다 현재 상태를 출력해 확인하는 습관이 안정적인 작업 흐름을 만듭니다.

괄호로 묶인 값은 오늘 외우지 않는다

(400, 300)과 (245, 240, 230)처럼 여러 값을 괄호로 묶은 형태를 Python에서는 튜플이라고 합니다. 이번 주에는 “크기 두 값”과 “색상 세 값”을 정해진 순서로 묶는 표기라고 읽으면 충분합니다.

개별 출구 확인 · 3분

6 × 4 이미지 설계 카드

  2. 왼쪽 위와 오른쪽 아래 픽셀 좌표를 적습니다.

설계 카드 정답 확인

50-60분 · 확장: 좌표로 화면 구성 설계하기

60분 교시에서는 코드를 작성하기 전에 한 장의 화면을 좌표로 설계합니다. 이 활동의 목적은 그림을 정교하게 완성하는 것이 아니라, “왼쪽”, “가운데”, “여백이 넓다”와 같은 시각적 표현을 계산 가능한 값으로 바꾸는 데 있습니다.

설계 조건

  • 캔버스 크기는 600 × 400픽셀입니다.
  • 사방에 최소 40픽셀의 여백을 남깁니다.
  • 큰 형태의 기준점 A는 왼쪽 영역에 둡니다.
  • 보조 형태의 기준점 B는 오른쪽 위 영역에 둡니다.
  • 강조점 C는 화면의 중심보다 조금 아래에 둡니다.

먼저 사용할 수 있는 안전 영역을 계산합니다. 왼쪽과 위쪽은 40에서 시작하고, 오른쪽은 600 - 40 = 560, 아래쪽은 400 - 40 = 360입니다. 세 기준점은 모두 x가 40~560, y가 40~360 사이에 있어야 합니다.

언어로 표현한 구성 의도를 좌표 후보로 바꾸기
요소시각적 의도좌표 후보판단 근거
기준점 A왼쪽의 주된 형태(150, 200)x가 중심 300보다 작고, y는 세로 중심에 가까움
기준점 B오른쪽 위의 보조 형태(450, 110)x가 중심보다 크고, y는 중심 200보다 작음
강조점 C중심보다 조금 아래(320, 275)x는 중심에 가깝고, y가 세로 중심보다 75 큼

이 좌표들은 유일한 정답이 아닙니다. 중요한 것은 각 값이 언어로 표현한 의도와 모순되지 않는지 설명하는 일입니다. 예를 들어 B의 y값이 330이라면 안전 영역 안에는 있지만 “오른쪽 위”라는 조건에는 맞지 않습니다. 범위 안에 있다는 기술적 조건과 구성 의도에 맞는다는 표현적 조건을 함께 확인해야 합니다.

개별 설계 · 5분

나만의 세 기준점 정하기

  1. A, B, C의 좌표를 각각 하나씩 정합니다.
  2. 세 좌표가 안전 영역 안에 있는지 x와 y를 따로 확인합니다.
  3. 각 좌표가 시각적 의도에 맞는 이유를 한 문장으로 씁니다.
  4. 세 점 가운데 하나를 30픽셀 이동하고, 어느 값을 어떻게 바꾸었는지 기록합니다.
예시 해설: 강조점 C를 오른쪽 위로 이동하려면?

예시 C가 (320, 275)라면 오른쪽으로 이동할 때 x를 키우고, 위로 이동할 때 y를 줄입니다. 각각 30픽셀 이동하면 새 좌표는 (350, 245)입니다. 두 값을 모두 더하는 것이 아니라 축의 방향에 따라 하나는 더하고 하나는 뺍니다.

1교시 핵심 문장

디지털 이미지는 정해진 크기의 픽셀 격자이며, 각 픽셀은 왼쪽 위 원점을 기준으로 한 좌표와 색상 값을 가집니다. 좌표를 사용한다는 것은 단순히 숫자를 입력하는 일이 아니라, 화면 구성의 의도를 반복 가능한 관계로 기록하는 일입니다.
