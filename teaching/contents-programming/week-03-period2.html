0-5분 · 좌표를 알면 위치를 말할 수 있다

1교시에는 이미지를 픽셀 격자로 읽고, 왼쪽 위를 (0, 0)으로 하는 좌표를 배웠습니다. 색을 배우기 전에 위치 규칙을 세 문제로 다시 확인합니다.

한 픽셀의 위치를 정확히 찾았다고 해서 화면에 보일 모습이 모두 결정된 것은 아닙니다. 같은 (120, 80)이라도 검은 픽셀, 붉은 픽셀, 흰 픽셀은 서로 다른 이미지를 만듭니다. 1교시의 좌표가 픽셀의 주소를 정했다면, 이번 시간의 RGB 값은 그 주소에 기록할 내용을 정합니다.

1. 이미지 좌표에서 (0, 0)은 어디인가?

이미지의 왼쪽 위입니다. x는 오른쪽, y는 아래쪽으로 증가합니다.

2. 500 × 300 이미지의 오른쪽 아래 픽셀 좌표는?

(499, 299)입니다. 각 크기에서 1을 뺀 값이 마지막 픽셀 주소입니다.

3. (80, 120)에서 오른쪽으로 30, 위로 20 이동하면?

(110, 100)입니다. 오른쪽 이동은 x에 더하고, 위쪽 이동은 y에서 뺍니다.

오늘 추가할 한 가지 질문

좌표가 어디에 그릴지를 정한다면, RGB는 그 위치를 어떤 색으로 채울지를 정합니다. 이미지 생성 코드는 위치 데이터와 색상 데이터를 하나의 명령 안에서 만납니다.

5-15분 · RGB는 세 빛의 밝기를 섞는 방식이다

Red, Green, Blue 세 채널

RGB는 Red, Green, Blue 세 빛의 밝기를 조합해 색을 표현하는 방식입니다. Pillow의 일반적인 RGB 이미지에서는 각 채널을 0부터 255까지의 정수로 나타냅니다.

세 채널은 서로 독립적인 세 개의 조절 장치와 같습니다. R 값만 바꾸면 빨강 성분이 달라지고, G 값만 바꾸면 초록 성분이 달라집니다. 하나의 RGB 색을 읽을 때에는 색 이름을 바로 맞히려고 하기보다, 어느 채널이 강하고 어느 채널이 약한지부터 비교하는 편이 정확합니다.

  • 0: 해당 색의 빛을 켜지 않은 상태
  • 255: 해당 색의 빛을 가장 강하게 켠 상태
  • (R, G, B): 항상 빨강, 초록, 파랑 순서로 세 값을 작성

왜 최대값이 255인가?

Pillow의 일반적인 RGB 모드는 채널 하나를 8비트로 기록합니다. 8개의 이진 자리로 표현할 수 있는 경우는 2 ** 8 = 256가지이며, 0부터 시작하므로 값의 범위는 0~255가 됩니다. 세 채널이 각각 256가지 값을 가지므로 가능한 조합은 256 ** 3 = 16,777,216가지입니다.

RGB와 물감 혼합을 같은 규칙으로 생각하지 않는다

빨간 빛과 초록 빛을 강하게 더하면 노란 빛에 가까워집니다. 물감을 섞을 때의 경험과 결과가 다를 수 있으므로, 이번 수업에서는 빛의 세 채널 밝기로 판단합니다.

RGB 값을 읽는 세 단계

  1. 순서를 확인합니다. 첫째는 R, 둘째는 G, 셋째는 B입니다.
  2. 가장 큰 값과 가장 작은 값을 찾습니다. 강한 채널이 색의 주된 방향을 만듭니다.
  3. 세 값이 서로 얼마나 가까운지 봅니다. 세 값이 같으면 회색 계열이고, 차이가 클수록 특정 색의 성격이 뚜렷해집니다.

RGB 숫자는 색을 설명하는 정확한 데이터이지만, 숫자의 차이가 사람이 느끼는 밝기 차이와 언제나 같은 비율로 대응하는 것은 아닙니다. 또한 같은 값도 화면의 밝기와 색상 설정에 따라 조금 다르게 보일 수 있습니다. 이번 수업에서는 먼저 채널의 상대적 크기로 색의 방향을 예측하고 실제 결과를 확인하는 습관을 기릅니다.

15-23분 · 색상은 순서가 있는 세 정수 데이터다

RGB 튜플 읽기

(235, 86, 75)처럼 세 값을 괄호로 묶은 형태를 색상 튜플로 사용합니다. 첫 값은 R, 둘째는 G, 셋째는 B입니다. 같은 숫자 세 개라도 순서를 바꾸면 다른 색이 됩니다.

튜플은 여러 값을 정해진 순서로 묶는 Python 자료형입니다. RGB에서는 세 값의 순서와 개수가 의미를 결정합니다. (235, 86, 75)와 (75, 86, 235)는 같은 숫자를 사용하지만 첫 번째는 R이, 두 번째는 B가 강하므로 전혀 다른 색이 됩니다.

coral = (235, 86, 75)

print(type(coral))
print("R:", coral[0])
print("G:", coral[1])
print("B:", coral[2])
<class 'tuple'>
R: 235
G: 86
B: 75

색상 숫자에는 따옴표를 붙이지 않는다

(235, 86, 75)의 세 값은 계산 가능한 정수입니다. ("235", "86", "75")처럼 따옴표를 붙이면 세 값이 숫자가 아니라 문자열이 되므로 Pillow의 RGB 색상 값으로 올바르게 사용할 수 없습니다. 설명 글자에는 따옴표를 쓰고, 채널 숫자에는 쓰지 않습니다.

대괄호 읽기는 확인용으로만 사용

coral[0]은 튜플의 첫 값, coral[1]은 둘째 값, coral[2]는 셋째 값을 확인합니다. 0부터 세는 방식이 픽셀 좌표뿐 아니라 여러 값을 저장한 자료에도 다시 나타납니다. 튜플의 일반적인 사용법은 지금 확장하지 않고 RGB 순서를 확인하는 용도로만 사용합니다.

빨강 계열: R 값이 가장 큽니다.

파랑 계열: 같은 세 숫자의 순서만 바뀌었습니다.

2주차의 변수는 색상에도 그대로 사용할 수 있습니다. 자주 사용하는 색에 의미 있는 이름을 붙이면 숫자를 매번 다시 읽지 않아도 되고, 팔레트를 한 곳에서 바꿀 수 있습니다. 같은 색을 여러 도형에 사용할 때 숫자 세 개를 반복하는 대신 변수 하나를 사용하면 수정 위치도 줄어듭니다.

paper = (244, 239, 229)
coral = (235, 86, 75)
blue = (48, 95, 180)

색의 이름보다 화면에서 맡은 역할을 설계한다

팔레트는 단순히 마음에 드는 색을 모아둔 목록이 아닙니다. 한 화면 안에서 각 색이 어떤 역할을 맡을지 정한 체계입니다. 배경색은 다른 형태가 놓일 바탕을 만들고, 주조색은 화면에서 가장 큰 시각적 면적을 차지하며, 강조색은 작은 영역에서 시선을 모읍니다. 윤곽색은 형태의 경계를 분명하게 합니다.

색 차이만으로 형태를 구분하지 않는다

서로 다른 RGB 값을 사용해도 두 색의 밝기가 비슷하면 경계가 약하게 보일 수 있습니다. 특히 작은 글자나 얇은 선은 배경과 충분한 명암 차이가 필요합니다. 이번 기하학 이미지에서는 색뿐 아니라 크기, 위치, 윤곽선도 함께 사용해 형태를 구분합니다.

(240, 40, 40)은 R이 가장 강해 빨강 계열입니다. (40, 40, 240)은 B가 가장 강해 파랑에 가깝습니다. (210, 210, 210)이 더 밝은 회색입니다. 마지막 색에서 B를 높이면 빨강과 초록만 강한 주황·노랑 계열에 파랑 성분이 더해집니다. B가 R과 G에 가까워질수록 세 채널의 차이가 줄어 색은 더 중성적으로 보입니다. 정확한 인상은 실제 결과를 함께 확인합니다.

같은 파일명으로 다시 저장하면 이전 결과와 구분하기 어렵다

수정 전후를 비교할 때에는 result_a.png, result_b.png처럼 서로 다른 이름을 사용합니다. 같은 위치에서 같은 파일명으로 다시 저장하면 기존 파일이 새 결과로 바뀔 수 있습니다. 또한 Colab 런타임의 파일은 영구 보관을 보장하지 않으므로 완성한 PNG는 수업이 끝나기 전에 자신의 컴퓨터로 다운로드합니다.
